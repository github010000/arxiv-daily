## 한 줄 요약
Flash-dLLM은 diffusion LLM의 추론에서 KV cache 갱신을 I/O 측면에서 fused kernel로 융합하고, 별도 model 없이 자기 자신이 draft와 verify를 수행하는 병렬 decoding을 더해, 학습 없이 기존 최고 방법 대비 GSM8K에서 5.1배, HumanEval에서 11.0배 빠르면서 accuracy를 유지하는 프레임워크다.

## 핵심 개념 풀이
Diffusion LLM(dLLM)은 텍스트 생성을 autoregressive 방식과 다르게 본다. 기존 LLM은 prompt 뒤에 token을 왼쪽에서 오른쪽으로 하나씩 생성하지만, dLLM은 생성할 길이만큼 [MASK] token을 깔아 두고 여러 step에 걸쳐 "이 [MASK] 자리에 어떤 단어가 들어갈지"에 대한 확률을 전체 위치에서 동시에 계산한 뒤 확실한 것부터 채워 나간다. diffusion이라는 이름은 이미지 생성에서 noise를 조금씩 제거하듯 mask를 조금씩 해소하는 과정에서 왔다. 이렇게 하면 한 step에 여러 token을 병렬로 결정할 수 있어 비자기회귀(non-autoregressive) 생성이 된다. 대신 매 step마다 전체 sequence가 model을 통과하므로 attention 계산과 key/value 상태 관리가 새로운 병목이 된다.

KV cache는 Transformer attention에서 나오는 key와 value 벡터를 저장해 두는 구조다. key와 value는 "이전에 처리한 token이 이후 token에게 줄 정보"를 담는다. autoregressive LLM은 새 token을 만들 때마다 과거 token의 key/value를 GPU memory에 저장해 두고 재사용한다. dLLM에서는 token이 mask에서 실제 단어로 바뀌면 그 위치의 key/value도 변하고, 양방향 attention 때문에 인접한 다른 위치의 표현까지 영향을 받아 cache를 단순히 append만 할 수 없다. 그래서 dLLM에서는 cache의 어느 부분을 정확히 갱신할지, 그리고 갱신된 cache를 어떻게 효율적으로 읽을지가 속도를 좌우한다.

Memory-bound와 IO-aware fused kernel은 GPU의 memory 계층 구조와 관련된 개념이다. GPU는 main memory인 HBM(high-bandwidth memory)과 chip 안의 작은 SRAM을 가진다. HBM에서 SRAM으로 데이터를 옮기는 것이 계산보다 느리면 그 연산은 memory-bound가 된다. 기존 cache 구현은 QKV projection, rotary positional embedding(RoPE), cache write, attention을 각각 별도의 kernel로 실행했다. 각 kernel이 결과를 HBM에 쓰고 다음 kernel이 다시 읽으므로, 실제 곱셈 덧셈보다 데이터 왕복이 더 큰 비용이 된다. "fused"는 이 여러 작은 kernel을 하나로 합쳐 SRAM에서 연속으로 처리하고 중간 결과는 HBM에 쓰지 않는 것을 뜻한다. Flash-dLLM은 QKV projection, RoPE, cache write를 한 fused kernel로 만들어 I/O 병목을 줄인다.

Confidence-aware decoding은 dLLM이 한 step에서 [MASK] 위치에 대해 내놓는 확률 분포를 이용하는 방법이다. 한 위치의 confidence는 그 분포에서 가장 높은 확률 값, 즉 c^i = max_x p_θ(x^i | x_t)이다. confidence가 높으면 그 위치의 예측이 거의 확실하다는 뜻이고, 낮으면 여러 후보가 경합한다는 뜻이다. Fast-dLLM 등은 confidence가 임계값 ε을 넘는 token만 unmask하는 방식으로 병렬 decoding의 accuracy를 보호한다. 그러나 임계값 아래여도 실제로는 맞는 예측이 많아, 이들을 전부 버리면 한 step당 decode되는 token 수가 적어져 throughput이 떨어진다. Flash-dLLM은 이렇게 버려지는 후보를 다시 검증해 살린다.

Draft-and-verify(speculative decoding)는 빠른 model이 여러 후보를 먼저 draft하고, 큰 model이 그것들을 한 번에 확인하는 전략이다. dLLM의 병렬 decoding에서도 draft 후보를 만든 뒤 verify하는 아이디어를 쓴다. Flash-dLLM의 특이점은 별도의 빠른 model이 아니라 dLLM 자신이 drafter와 verifier를 겸한다는 것이다. 같은 search token 위치에 "draft가 예측한 값"을 넣은 view와 "[MASK]"를 넣은 view를 동시에 model에 넣고, causal attention mask로 두 view가 서로를 보지 못하게 한다. 두 view가 독립적으로 내놓은 예측이 일치하고 mask view의 confidence가 높을 때만 token을 수용한다. 이렇게 하면 추가 model이나 학습 없이 병렬 decoding의 accuracy를 높일 수 있다.

## 문제의식
dLLM은 비자기회귀 생성이라는 매력에도 불구하고 실제 추론 속도가 성숙한 autoregressive LLM보다 느리다. autoregressive LLM은 KV cache를 append하는 방식으로 과거 token의 attention 상태를 재계산하지 않지만, dLLM은 sequence 전체를 반복적으로 다시 본다. 매 denoising step에서 일부 위치가 mask에서 실제 token으로 바뀌고, 그 위치들의 key/value가 바뀌면서 cache를 자주 읽고 쓰게 된다. 기존 방식들은 이 cache update를 PyTorch의 kernel 여러 개로 나누어 수행했기 때문에, 작은 window만 갱신하는 경우에도 중간 tensor가 HBM을 여러 번 오가며 memory-bound에 빠진다. Fig. 1(a)는 positional embedding과 cache write가 attention 자체보다 큰 비중을 차지하는 것을 보여 준다.

또한 모든 decoded token이 다음 step에 똑같이 중요하지 않다. Fig. 1(b)는 상위 32개 token이 중간 layer attention의 약 50%를 차지함을 보여 주는데, 그렇다면 전체 cache를 매번 정확히 갱신하는 것은 낭비다. 병렬 decoding 쪽에서도 문제가 있다. 기존 confidence-aware decoding은 confidence가 낮은 token을 전부 다음 step으로 미루므로 정답을 이미 예측했음에도 불구하고 threshold를 넘지 못해 버려지는 경우가 많다. 수학 문제처럼 생성이 어려운 task에서는 model 확신이 낮아 throughput이 특히 낮아진다. 마지막으로 batch 추론에서는 sample마다 현재 mask 수와 cache 갱신 범위가 달라, 일괄적으로 같은 연산을 강제하면 padding과 동기화로 효율이 떨어진다.

## 핵심 아이디어
Flash-dLLM의 핵심은 dLLM 추론의 두 병목, 즉 KV cache 갱신의 I/O 비용과 보수적 confidence threshold로 인한 낮은 병렬 decode율을 하나의 framework로 묶는 것이다. 먼저 I/O-aware fused kernel을 통해 QKV projection, RoPE, cache write를 SRAM에서 한 번에 수행한다. 이렇게 하면 중간 key/value tensor를 HBM에 여러 번 쓰고 읽는 일이 사라져, 실제 필요한 연산 시간이 그대로 wall-clock 속도 향상으로 이어진다. 둘째, attention logit을 기준으로 영향이 큰 일부 decoded token만 tracking set으로 유지한다. 모든 token을 정확히 cache하는 대신 중요한 소수만 정확히 갱신해도 attention의 대부분을 복원할 수 있다는 관찰에 기댄 것이다. 셋째, Flash-Verify는 confidence threshold 아래로 밀려난 token을 버리지 않고, 같은 model에게 두 가지 view로 다시 물어본다. draft 예측을 넣은 view와 [MASK]를 넣은 view가 독립적으로 같은 답을 내고 mask view의 신뢰도가 높으면 수용한다. 이는 "낮은 confidence는 그 자체로 틀렸다는 뜻이 아니다"라는 점을 이용해 step 수를 줄인다. 이 세 요소는 모두 training-free이므로 기존 dLLM 가중치를 그대로 쓸 수 있다.

또한 block table 기반의 scheduled flash attention은 batch 안의 sample들이 서로 다른 길이와 진도를 가져도 각 query block을 알맞은 key/value block에 연결해 padding 없이 실행한다. 이는 병렬 decoding과 adaptive cache가 만드는 길이 편차 문제를 해결한다.

## 방법
Flash-dLLM은 Algorithm 2의 흐름을 따른다. prompt 뒤에 생성 길이 N만큼 [MASK]를 붙인 x^0에서 시작한다. while loop에서 현재 masked token의 앞쪽 β_m개(M^t_{β_m})와 tracking set T^t를 query Q^t로 삼아 model forward를 수행한다. 이때 Flash-Cache의 fused kernel과 selective cache update가 사용된다. forward 결과로 각 masked 위치의 확률 분포와 attention logit S를 얻는다.

기존에는 layer마다 QKV projection, RoPE, cache write, attention을 각각 다른 CUDA kernel로 실행했다. Flash-Cache는 첫 세 단계를 하나의 fused kernel로 수행한다. Algorithm 1에서 입력 X를 block size β 단위로 자르고, 각 block을 head별로 나눈 다음 projection과 RoPE를 SRAM에서 계산한다. 계산된 key와 value는 곧바로 KV cache의 해당 위치에 기록된다. 중간에 별도 key/value tensor를 만들지 않기 때문에 HBM traffic이 줄고, cache에 쓰는 위치도 position index P로 정확히 배치된다. 이 fused kernel만으로 RTX 3090에서 1.37배 속도 향상이 관찰되었다.

cache를 쓰는 부분 이후에는 attention이 이어진다. batch 안의 sample들은 cache를 update하는 stage에 있을 수도, 작은 window만 보는 stage에 있을 수도 있어 길이가 크게 다르다. Flash-dLLM은 Flash Attention의 tiling을 확장해 각 batch를 여러 sequence block으로 나누고 block table B로 query block과 key/value block을 대응시킨다. 이는 각 block이 자기에게 필요한 cache 구간만 읽게 하여, 서로 다른 길이를 padding 없이 parallel 처리할 수 있게 한다. block을 추가하거나 제거하기 쉬워 adaptive cache 전략과도 잘 맞는다.

모든 decoded token을 cache에 똑같이 반영하지 않고, 현재 masked token들에게 많이 참조되는 token만 추적한다. 식 (2)에서 decoded token i의 attention score a_i^t는 모든 layer l, 모든 head h, 모든 masked query j에 대해 unnormalized attention logit S^{t,l,h}_{j,i}를 평균한 값이다. 이 값이 크면 현재 masked token들이 i의 정보를 많이 쓰고 있다는 뜻이다. 다음 step의 tracking set T^{t+1}는 이 점수의 top-k를 뽑는다. query Q^{t+1}는 sliding window M_{β_m}^{t+1}와 이 tracking set의 합집합이다. 이렇게 하면 fixed-size query만 계산하고, cache에 기록하는 위치도 중요한 subset으로 제한하여 I/O와 memory를 아낀다.

forward pass 후 각 masked token i에 대해 confidence c^i와 예측 x̂^i를 얻는다. c^i ≥ ε인 token은 D^t에 넣어 즉시 decode한다. 나머지 S^t는 verification 후보이다. verify pass에서는 query를 세 부분으로 구성한다: 원래 tracking set과 D^t를 포함한 context, S^t의 각 위치에 draft 예측 x̂^i를 넣은 draft view, 같은 S^t 위치에 [MASK]를 넣은 mask view. 여기에 causal attention mask를 씌워 context는 draft view를 볼 수 없고, 같은 위치의 draft view와 mask view는 서로를 볼 수 없다. 두 view는 shared positional embedding을 가지지만 causal mask에 의해 독립적인 출력을 낸다. search token i는 x̂^i = x̃^i이고 mask view의 confidence c̃^i ≥ γ일 때 수용되며, speculative decoding처럼 decoding 순서대로 보다가 첫 mismatch 이후의 후보는 모두 reject한다. verify pass의 query 길이는 search set 크기의 두 배 정도(총 2β_m에 비례)이므로 전체 sequence를 다시 계산하는 것보다 훨씬 싸다. 논문의 기본 setting은 ε=0.9, γ=0.8, β=16, β_t=80, β_m=64, generation length 512이다.

## 왜 성립하는가
Flash-dLLM은 수학적 증명을 하지 않는 대신, 각 설계가 실제로 병목을 제거한다는 관찰을 제시한다. 첫 번째 근거는 Fig. 1(a)의 kernel별 latency breakdown이다. 기존 pipeline에서 positional embedding과 cache write가 attention이나 QKV projection보다 큰 시간을 차지하는데, fused kernel이 이 중간 materialization을 없애 RTX 3090에서 1.37배 속도 향상을 낸다. 이는 memory-bound 가설을 직접 뒷받침한다.

두 번째 근거는 attention sparsity이다. Fig. 1(b)에서 상위 32개 decoded token이 중간 layer attention의 약 50%를 차지한다. 따라서 top-k tracking set만 정확히 cache해도 전체 attention 출력을 크게 왜곡하지 않는다. 실제로 Table 1에서 Flash-Cache greedy는 No Cache greedy보다 accuracy가 떨어지지 않으면서 21.1배 빠르다.

세 번째 근거는 Flash-Verify의 수용 조건이다. draft view와 mask view가 causal mask로 분리되어 있기 때문에, 서로 독립적으로 같은 예측을 했다는 것은 그 예측이 model 내부에서 안정적이라는 신호이다. mask view의 confidence γ 조건은 draft가 주어졌을 때 model이 그 자리에서 여전히 높은 확신을 가지는지를 추가로 확인한다. Fig. 5(b)와 Fig. 6은 Flash-Verify가 confidence-aware decoding보다 같은 accuracy에서 더 많은 token을 iteration당 decode하며 throughput이 1.33배까지 높아짐을 보여 준다. 즉 verification이 실제로 step 수를 줄인다.

마지막으로 batch scaling에서 block table이 sample 간 길이 차이를 흡수하여 Fig. 4처럼 batch 32까지 nearly linear scaling이 가능하고, memory는 preallocation 때문에 Fast-dLLM 대비 약 48% 줄어든다. 이는 일관된 실험적 근거이다.

## 구체적 예시
Table 1의 GSM8K 5-shot, length 512 행을 보자. 우선 No Cache greedy decoding은 accuracy 81.35%, throughput 2.6 tokens/s이다. 이 방식은 매 denoising step마다 전체 512 sequence에 대해 projection과 attention을 처음부터 다시 계산하므로, token을 하나도 빨리 unmask하지 않는 greedy step 고정 전략과 맞물려 매우 느리다.

Flash-Cache greedy는 같은 greedy schedule을 쓰지만 KV cache를 재사용한다. fused kernel로 cache update의 I/O를 줄이고 selective tracking으로 일부만 갱신하여 throughput이 54.8 tokens/s로 올라간다. 이는 기준 2.6 대비 21.1배다. accuracy는 82.94%로 오히려 1.59%p 상승하는데, cache가 approximate이긴 하지만 tracking set이 중요한 token을 계속 잡아 주는 효과로 보인다.

Confidence-aware decoding을 No Cache에 적용하면 17.2 tokens/s, 6.6배가 된다. No Cache greedy보다는 빠르지만 Flash-Cache greedy보다 느린 이유는 confidence가 threshold를 넘는 token만 unmask하므로 step 수는 줄지만, 여전히 전체 sequence를 매번 재계산하기 때문이다.

Flash-Cache에 confidence-aware decoding을 결합하면 149.4 tokens/s, 57.5배가 된다. 이 지점이 cache와 parallel decoding의 시너지를 보여 준다. Elastic-Cache는 41.7 tokens/s, 16.0배로 기존 방법 중에서는 좋지만, Flash-Cache confidence-aware의 27.9% 수준이다.

Flash-Verify를 Flash-Cache 위에 올리면 210.6 tokens/s, 81.0배가 되고 accuracy는 83.02%로 이 행에서 최고다. Elastic-Cache의 41.7과 비교하면 210.6 / 41.7 ≈ 5.05, 즉 초록에서 말한 5.1배 speedup이 여기서 나온다. 왜 이렇게 빠를까? confidence-aware decoding은 threshold를 넘지 못한 search token을 버리지만 Flash-Verify는 그 후보를 두 view로 검증한다. 정답을 미리 예측해 둔 token을 되살리면 step당 decode token 수가 늘고, verify pass는 2β_m 정도의 작은 query만 추가로 계산한다. 그래서 accuracy를 잃지 않으면서 step 수가 크게 줄어든다.

HumanEval 512 행에서는 Flash-Cache+Flash-Verify가 185.6 tokens/s, Elastic-Cache가 16.8 tokens/s로 비율이 약 11.0배다. code 생성에서는 수학보다 confidence가 낮거나 긴 code block이 많아 기존 confidence-aware decoding이 더 보수적이 되기 때문에 Flash-Verify의 이득이 크게 나타난다.

## 실험과 결과
실험은 LLaDA-1.5 model을 NVIDIA A100 80GB 한 개에서 돌렸고, kernel은 Triton 2.0으로 구현했다. 평가 dataset은 GSM8K, MATH, HumanEval, MBPP이고 generation length는 256과 512를 쓴다. 주요 지표는 accuracy와 throughput(tokens/s), speedup이다.

Table 1을 보면 Flash-Cache greedy는 모든 benchmark에서 No Cache greedy 대비 8.0배에서 58.5배의 speedup을 낸다. confidence-aware Flash-Cache는 17.0배에서 102.2배, Flash-Cache+Flash-Verify는 22.3배에서 148.2배까지 높아진다. 절대 throughput도 Flash-Verify+Flash-Cache가 모든 8개 setting 중 최고로, 148.0 tokens/s에서 210.6 tokens/s 사이이다. 예를 들어 GSM8K-512에서 210.6 tokens/s인데, 이는 GPU가 한 번에 많은 token을 처리한다는 뜻이다.

accuracy는 setting마다 다르다. GSM8K-512에서는 Flash-Verify+Flash-Cache가 accuracy 83.02%로 가장 높으면서 가장 빠르다. MATH-512에서는 Flash-Verify No Cache가 37.76%로 가장 높지만 Flash-Cache+Flash-Verify는 35.98%이다. HumanEval-512에서는 confidence-aware Flash-Cache가 42.07%로 가장 높고 Flash-Verify+Flash-Cache는 40.24%이다. MBPP-512에서도 confidence-aware Flash-Cache가 40.20%, Flash-Verify+Flash-Cache가 39.00%이다. 즉 수학에서는 fastest가 accuracy도 좋지만, code 생성 256 token에서는 HumanEval 3.66%p, MBPP 3.60%p 격차가 난다.

Table 2의 추가 baseline 비교에서는 dKV-Cache, FlashDLM, dLLM-Cache, Dyna-dLLM, Fast-dLLM, FreeDave, Elastic-Cache의 accuracy가 79.32%에서 82.79%이고 throughput은 14.9에서 42.8 tokens/s이다. Flash-Cache+Flash-Verify는 83.02%와 210.6 tokens/s로 accuracy와 throughput을 동시에 끌어올린다. Elastic-Cache는 baseline 중 accuracy가 가장 높은 82.79%이지만 throughput은 41.7 tokens/s에 그친다.

Scalability 분석(Fig. 4)에서는 batch size 32까지 Flash-dLLM이 nearly linear로 증가하고 Fast-dLLM은 batch 24에서 out-of-memory가 난다. batch 16에서 memory는 Flash-dLLM 약 26GB, Fast-dLLM 약 50GB로 약 48% 절감된다. 이는 preallocated flat cache layout 덕분이다.

Ablation에서 Fig. 5(a)는 track budget β_t와 verify threshold γ에 따른 accuracy-throughput Pareto frontier를 보여 준다. accuracy를 80.2%에서 83.2%로 올리면 throughput은 278에서 186 tokens/s로 떨어진다. 큰 β_t는 accuracy를 높이지만 compute가 늘고, γ를 낮추면 parallelism이 커진다. Fig. 5(b)는 Flash-Verify가 82.6~82.9% accuracy 구간에서 190~210 tokens/s로 confidence-aware decoding의 140~160 tokens/s보다 높은 throughput을 낸다. confidence-aware decoding은 최고 accuracy 83.4%에 도달하지만 throughput은 131 tokens/s로 낮아진다. Fig. 6은 Flash-Verify가 iteration당 7.2 tokens을 decode할 때 confidence-aware의 5.6 tokens과 비슷한 throughput을 내면서 accuracy는 3.5% 높다고 보고한다. Fig. 7은 masked-window size β_m이 커질수록 accuracy는 중간까지 오르고 throughput은 감소하며, Flash-Verify의 speedup 이점이 1.4배에서 1.5배로 커진다.

## 한계
저자들이 명시한 한계는 아니지만, 결과에서 accuracy와 throughput 사이의 trade-off가 분명하게 드러난다. 특히 256-token code generation에서 Flash-Cache+Flash-Verify가 가장 높은 throughput을 내지만, accuracy는 confidence-aware Flash-Cache보다 HumanEval에서 3.66%p, MBPP에서 3.60%p 낮다. 실무에서는 task에 따라 ε, γ, β_t, β_m을 다시 tuning해야 할 수 있다. Figure 5의 Pareto frontier처럼 큰 β_t와 낮은 γ가 유리한 지점이 있지만, 이 hyperparameter들은 dataset별로 최적 값이 달라질 것이다.

또한 Flash-Verify는 verify pass를 추가로 돌리기 때문에, search set이 거의 없거나 confidence-aware decoding이 이미 대부분의 token을 수용하는 경우에는 추가 cost가 overhead가 될 수 있다. 논문에서도 Fig. 6에서 iteration당 7.2 tokens과 5.6 tokens의 throughput이 비슷해지는 구간이 언급된다. 즉 절대 throughput 우위는 항상 유지되지만, 상대적 이득은 상황에 따라 줄어든다.

평가가 LLaDA-1.5 하나의 model과 A100 단일 GPU 환경에 집중되어 있다. 다른 dLLM architecture나 multi-GPU, 다른 GPU architecture에서 fused kernel과 block scheduling이 얼마나 잘 동작할지는 논문에 명시되어 있지 않다. Triton kernel의 성능은 GPU별 SRAM 크기와 HBM bandwidth에 민감할 수 있다.

## 왜 중요한가
Flash-dLLM은 dLLM이 autoregressive LLM의 추론 최적화 수준에 다가가기 위한 실용적인 다리를 놓는다. autoregressive LLM이 FlashAttention과 speculative decoding으로 큰 속도 향상을 얻었듯, dLLM도 KV cache와 parallel decoding을 함께 최적화해야 실제 배포가 가능하다. 이 논문은 두 문제를 분리하지 않고 동시에 해결해야 한다는 점을 보여 준다.

training-free라는 점이 특히 실무에서 중요하다. 별도의 draft model이나 추가 학습 없이 기존 dLLM checkpoint에 그대로 적용할 수 있어 도입 비용이 낮다. fused kernel과 preallocated cache는 GPU memory 사용을 줄여 batch inference를 가능하게 한다. 예를 들어 Fast-dLLM이 batch 24에서 실패할 때 Flash-dLLM은 batch 32까지 linear scaling을 보인다. 이는 dLLM을 server에서 여러 요청을 묶어 처리하는 scenario에 가깝게 만든다.

후속 연구로는 Flash-Verify의 verification 규칙을 더 정교하게 하거나, draft view를 여러 개 사용하는 방법, 다른 dLLM 계열로의 확장이 있을 수 있다. 또한 I/O-aware kernel과 block scheduling은 dLLM뿐 아니라 mask 기반 비자기회귀 sequence model 전반에 재사용 가능하다. 결국 이 논문은 dLLM의 병렬성을 실제 GPU 시간으로 바꾸는 데 필요한 시스템적 지식을 제공한다.

## 원문 초록

> Diffusion Large Language Models (dLLMs) have recently emerged as a promising alternative to autoregressive LLMs by enabling non-autoregressive text generation. However, their practical deployment remains limited by inefficient inference, largely due to the absence of effective Key-Value (KV) caching and scalable parallel decoding mechanisms. Existing acceleration methods typically study KV caching and parallel decoding in isolation, overlooking the I/O bottlenecks that arise when cache reuse and parallel token verification are jointly applied. In this work, we introduce $\textbf{Flash-dLLM}$, a training-free inference acceleration framework for fast and memory-efficient dLLMs. Flash-dLLM first identifies GPU memory I/O as a dominant bottleneck in KV-cache-enabled dLLM inference and addresses it with an I/O-aware fused KV-cache kernel that reduces redundant memory movement. Building on this optimized cache mechanism, Flash-dLLM further proposes an efficient KV-cache-driven draft-and-verify decoding strategy, where the dLLM itself serves as both drafter and verifier without requiring an auxiliary model. This unified design enables faster decoding while preserving generation quality and improving scalability to longer sequences and larger batch size. Extensive experiments on mathematical reasoning and code-generation benchmarks demonstrate that Flash-dLLM consistently outperforms existing state-of-the-art dLLM acceleration methods in both inference speed and memory efficiency. In particular, it achieves $5.1\times$ and $11.0\times$ speedups over prior strongest baseline Elastic-Cache on GSM8K and HumanEval, respectively.
