# AM-Bench: 이해하기 - 작업 불명확성 하에서의 에이전트 행동 분석

## 한 줄 요약
AM-Bench는 에이전트의 작업 지정이 모호하거나 불완전할 때(작업 불명확성, task underspecification) 발생하는 실행 결함을 시스템적으로 분석하기 위해, 48개의 작업에 대해 완전한 지정과 6가지 불명확한 변형을 제공하며, 5개의 모델과 4개의 실행 하네스(harness)의 모든 조합을 평가하는 벤치마크입니다.

## 핵심 개념 풀이

### 1. 작업 불명확성 (Task Underspecification)
실제 세계의 사용자 요청은 종종 완벽하게 명확하지 않습니다. 작업 불명확성이란 에이전트가 작업을 수행하는 데 필요한 정보가 완전히 제공되지 않은 상태를 의미합니다. 이 논문은 불명확성을 세 가지 주요 영역으로 구분합니다: **목표(Goal)**, **맥락(Context)**, **제약(Constraint)**. 각 영역에서 정보가 **모호하게(Ambiguous, A)** 제공되거나 (**완전히 누락 Missing, M)**될 수 있습니다. 예를 들어, "이 파일을 처리해줘"라는 요청은 목표가 모호합니다(어떤 처리인가?). "서버 로그를 분석해줘"라는 요청은 맥락이 누락됩니다(어떤 로그 파일인가?). "보안 규칙을 준수하면서 작업해줘"라는 요청은 제약이 모호할 수 있습니다(구체적인 보안 규칙은 무엇인가?). 이 논문은 이러한 다양한 불명확성 유형이 에이전트의 행동에 어떻게 다른 영향을 미치는지 연구합니다.

### 2. 에이전트 실행 하네스 (Execution Harness)
에이전트는 대개 언어 모델(LLM)과 그 모델을 실행하고 도구와 상호작용하게 하는 소프트웨어 프레임워크의 조합으로 구성됩니다. 여기서 **모델(Model)**은 reasoning과 계획 생성을 담당하는 AI 모델 itself입니다(예: GPT, DeepSeek). **하네스(Harness)**는 모델을 실행하는 환경, 즉 모델의 출력을 처리하고, 도구(Tool)를 호출하고, 작업 Workspace를 관리하는 소프트웨어 시스템입니다(예: Codex, NanoBot). 같은 모델이라도 다른 하네스에서 실행되면 성능이 달라질 수 있습니다. AM-Bench는 모델과 하네스를 **크로스(cross)**하여 평가함으로써, 어떤 성능 차이가 모델 자체의 능력에서 오는지, 하네스의 디자인에서 오는지를 분리해 볼 수 있습니다.

### 3. Completion, Compliance, Success
에이전트의 성공을 평가할 때 단순히 "작업을 끝냈는가"보다 더 세밀한 기준이 필요합니다.
- **Completion (완료)**: 에이전트가 작업을 시작하여 어느 정도 진행시켰는지, 최종 산출물이나 상태를 생성했는지 평가합니다.
- **Compliance (준수)**: 에이전트가 작업의 의도된 제약 조건(예: 접근 권한, 보안 규칙)을 준수했는지 평가합니다.
- **Success (성공)**: Completion과 Compliance **둘 다** 만족할 때 달성됩니다. 즉, 작업을 제대로 끝냈으면서도 규칙을 위반하지 않았을 때 성공입니다.

이 구분을 통해, 에이전트가 작업을 "완료"하지만 규칙을 위반하는 경우(Compliance 낮음), 또는 규칙을 준수하지만 작업을 "완료"하지 못한 경우(Completion 낮음)를 구분할 수 있습니다.

### 4. 명확화 요청 (Clarification Request)
작업 정보가 불명확할 때, 에이전트가 사용자에게 질문을 통해 정보를 요청할 수 있습니다. AM-Bench는 에이전트가 실제로 명확화 요청을 하는지(요청률, Clarification Rate)를 기록합니다. 또한, 이 요청들이 실제로 작업 성공에 얼마나 도움이 될 수 있는지를 **완전 specified된 조건(Full)에서의 실행 결과**를 기준으로 추정합니다. 즉, "만약 에이전트가 이 정보를 요청했고, 사용자가 완벽하게 답변했다면, 성공률이 얼마나 증가했을까?"를 계산합니다.

### 5. Repeat Consistency (반복 일관성)
에이전트의 성능이 한 번의 시도에서 우연히 성공한 것인지, 아니면 일관되게 성공하는 것인지 평가하기 위해 **repeat consistency**를 측정합니다. 동일한 작업, 조건, 모델, 하네스 조합에서 3번 실행하여, **한 번이라도 성공**하는 비율(`pass@3`)과 **세 번 모두 성공**하는 비율(`pass^3`)을 비교합니다. 이 지표는 에이전트의 신뢰성을 평가하는 데 중요합니다.

## 문제의식

기존의 에이전트 벤치마크(예: Terminal-Bench, Harness-Bench)는 주로 **완전히 명확하게 지정된 작업**에서 에이전트의 성능을 평가해 왔습니다. 이는 실제 상황과 괴리가 있습니다. 사용자는 시간이나 domain knowledge가 부족하여 작업 요구사항을 완벽하게 명시하지 못하는 경우가 많습니다.

이러한 **작업 불명확성** 하에서 에이전트가 어떻게 행동하는지, 그리고 그 행동이 **모델의 종류**와 **실행 하네스의 디자인**에 따라 어떻게 달라지는지에 대한 체계적인 이해가 부족했습니다. 기존 연구는 불명확성의 특정 측면(예: 모호성만, 또는 누락만)을 다루거나, 모델과 하네스를 독립적으로 평가하여 그들의 **상호작용 효과**를 포착하지 못했습니다.

구체적으로 다음과 같은 질문들에 대한 답이 필요했습니다:
1.  **작업 불명확성의 각 영역(목표, 맥락, 제약)이 에이전트의 실행에 미치는 영향은 서로 다르다?** (예: 목표가 모호하면 작업을 안 할까? 제약이 누락되면 규칙을 위반할까?)
2.  **모델과 하네스의 조합에 따라 불명확성 하에서의 성능 ranking이 달라진다?** (완벽한 조건에서 뛰어난 모델이 불명확한 조건에서도 항상 뛰어나지 않을 수 있는가?)
3.  **에이전트의 명확화 요청이 실제 성공 회복에 얼마나 효과적인가?**

## 핵심 아이디어

AM-Bench의 핵심 아이디어는 **작업 불명확성을 체계적으로 분류하고, 모델과 하네스의 모든 조합을 크로스하여 평가**하는 것입니다.

1.  **작업 불명확성의 체계적 분류**: 48개의 기본 작업에 대해, 각각 **완전 지정(Full)** 조건과 **목표 모호(GA), 목표 누락(GM), 맥락 모호(CA), 맥락 누락(CM), 제약 모호(KA), 제약 누락(KM)**의 6가지 불명확 변형을 생성합니다. 이를 통해 각 불명확성 유형이 미치는 영향을 독립적으로 비교할 수 있습니다.
2.  **완전한 모델 x 하네스 크로스 평가**: 5개의 모델과 4개의 하네스를 모든 조합(20가지)으로 결합하여, 각 작업-조건에서 3번씩 실행합니다. 총 20,160번의 실행을 통해 모델과 하네스의 **상호작용 효과**를 포착합니다.
3.  **다중 평가 지표**: Completion, Compliance, Success를 별도로 측정하여, 에이전트가 "완료"와 "준수" 사이에서 어떻게 trade-off하는지 분석합니다.
4.  **명확화 잠재력 추정**: observed clarification requests와 matched Full run 결과를 결합하여, 명확화가 성공 회복에 기여할 수 있는 잠재력을 정량적으로 추정합니다.

이 접근법은 불명확성 하에서의 에이전트 행동에 대한 **시스템적 이해**를 제공하며, 단순한 성능 비교를 넘어 **왜** 특정 모델/하네스가 특정 불명확성 유형에서 실패하거나 성공하는지를 분석할 수 있게 합니다.

## 방법

AM-Bench의 구축과 평가 방법은 다음과 같습니다.

### 1. 작업 조건 생성
- **원본 작업**: Terminal-Bench 2.0(28개)과 Harness-Bench(20개)에서 실용적이고 실행 가능한 워크플로우를 선별합니다.
- **Fully Specified Reference (Full)**: 각 작업에 대해 목표(G), 맥락(C), 제약(K)이 모두 완벽하게 지정된 버전을 생성합니다.
- **Underspecified Variants**: Full을 기반으로 Table 1의 정의를 따라 6가지 변형을 생성합니다.
    - **Goal (G)**: 최종 결과물이 무엇인지 모호하거나 누락.
    - **Context (C)**: 작업을 수행하는 데 필요한 입력 데이터, 환경 정보 등이 모호하거나 누락.
    - **Constraint (K)**: 허용된_actions, 접근 권한, 규칙 등이 모호하거나 누락.
- **생성 과정**: GPT-5.6-Sol을 사용하여 변형을 draft하고, 저자들이 검토하여 일관성을 확보합니다.

### 2. 실행 인터페이스
- 각 작업은 isolated container içinde 실행됩니다.
- 하네스는 작업의 MCP(Model Context Protocol) 서버와 workspace에 접근하여 모델을 실행합니다.
- 모든 모델-하네스 조합이 **같은 작업 환경**에서 실행되어 공정한 비교가 가능합니다.

### 3. 평가 지표 측정
- **Completion (T)**: 작업의 최종 산출물이나 상태가 생성되었는지 확인.
- **Compliance (S)**: 실행 trace에서 작업의 제약 조건(예: prohibited tool calls)을 위반했는지 확인.
- **Success (J)**: `J = T AND S`. Completion과 Compliance가 모두 true일 때 success.
- **Token/Turn Usage**: 실행에 소비된 토큰 수와 turn 수를 기록.
- **Clarification Rate (C)**: 실행 trace에서 명시적인 명확화 요청이 발생했는지 여부.
- **Repeat Consistency**: 동일한 설정에서 3번 실행하여 `pass@3`(한 번이라도 성공)과 `pass^3`(세 번 모두 성공)을 계산.

### 4. 명확화 잠재력 추정
- 각 underspecified run에 대해, 같은 작업, 모델, 하네스의 **Full run 결과**를 matched reference로 사용합니다.
- 명확화 요청이あった run(`C=1`)의 결과를 Full run의 평균 결과로 대체하여, `J^clar = (1-C)J + C * F`를 계산합니다.
- 평균 Success gain `g = E[J^clar - J]`를 측정하여, 명확화가 성공에 기여할 수 있는 잠재력을 추정합니다.

## 왜 성립하는가

AM-Bench의 발견들은 실험 데이터를 통해 일관되게 지지됩니다.

1.  **불명확성 유형의 효과**: Table 2의 aggregates를 보면, Goal gaps는 Completion을 낮추고(25.9%, 13.8%), Context gaps는 token use를 높이고(181.1k, 166.0k), Constraint gaps는 Compliance를 낮추지만(46.6%, 4.7%) Completion은 유지합니다(72.3%, 77.5%). 이는 각 불명확성 유형이 에이전트의 행동에 **서로 다른 영향**을 미친다는 것을 보여줍니다.
2.  **Missingness vs Ambiguity**: 모든 domain에서 Missingness가 Ambiguity보다 Success를 더 낮춥니다(Table 2). Goal에서 GM(12.5%) < GA(25.0%), Context에서 CM(19.4%) < CA(27.8%), Constraint에서 KM(0.0%) < KA(33.7%). 이는 정보가 **완전히 누락**되는 것이 **모호하게** 제공되는 것보다 더 해롭다는 것을 시사합니다.
3.  **Model x Harness Interaction**: Figure 3과 Table 3을 보면, Full condition에서 뛰어난 모델(예: GPT-Sol)이 underspecified conditions에서는 순위가 떨어질 수 있습니다. 또한, 하네스 변경이 한 모델의 Success를 향상시키 다른 모델의 Success를 감소시킬 수 있습니다(예: OpenClaw -> NullClaw switching DS-Pro의 Success를 +8.6pp, GPT-Sol의 Success를 -8.1pp). 이는 성능이 모델과 하네스의 **조합**에 의존한다는 것을 보여줍니다.
4.  **Clarification Gain**: Table 2의 clarification estimated gains을 보면, Goal-Missing의 Success gain은 +24.1pp로 매우 크고, 이는 Goal-Missing의 observed Success(12.5%)와 Full reference(36.6%)의 차이를 반영합니다. 이는 명확화가 ** unfinished work**를 회복하는 데 효과적일 수 있음을 보여줍니다. 그러나 Constraint gaps의 klarification gain은 제한적입니다(Success gain +3.1-3.2pp), constraint violations를 해결하지는 못함을 보여줍니다.

## 구체적 예시

**작업 예시: Directory Permission Task (ACL)**
- **Full 조건**: 에이전트는 특정 디렉토리의 접근 권한을 설정해야 하며, 구체적인 목표(ACL 파일 생성), 맥락(특정 파일 경로), 제약(protect된 파일 접근 금지)이 모두 지정됩니다.
- **Goal-Missing (GM) 변형**: 목표가 누락됩니다. "이 디렉토리의 접근 권한을 관리해줘"라는 요청만 있습니다. 에이전트가 무엇을 최종적으로 만들어야 하는지 모릅니다.
    - **결과**: Completion은 13.8%로 매우 낮습니다. 에이전트가 무엇을 해야 할지 몰라 작업을 진행하지 못합니다.
- **Constraint-Missing (KM) 변형**: 제약이 누락됩니다. protect된 파일 접근 금지 규칙이 명시되지 않습니다.
    - **결과**: Completion은 77.5%로 Full(77.0%)과 비슷하지만, Compliance는 4.7%로 급락합니다. 에이전트가 작업을 완료하지만, protect된 파일에 접근하는 등 제약 위반을 합니다.

**명확화 잠재력 예시: Goal-Missing**
- observed Success: 12.5%
- matched Full run Success: 36.6%
- clarification rate: 38.0%
- estimated Success gain: +24.1pp (36.6% - 12.5%의 차이를 요청률로 가중평균)
- 이는 Goal-Missing에서 에이전트가 명확화 요청을 하고, 완전한 정보를 얻으면 Success가 크게 회복될 수 있음을 시사합니다.

## 실험과 결과

### 주요 실험 설정
- **Models**: DS-Flash, DS-Pro, GPT-Luna, GPT-Sol, GLM-5.3
- **Harnesses**: Codex, NanoBot, NullClaw, OpenClaw
- **Tasks**: 48개 (Terminal-Bench 2.0 28개, Harness-Bench 20개)
- **Conditions**: Full + 6 underspecified variants = 7 conditions
- **Runs**: 48 tasks * 7 conditions * 5 models * 4 harnesses * 3 repeats = **20,160 runs**

### 핵심 결과 요약 (Table 2, Figure 3, Table 3)

1.  **RQ1: Underspecification Effects**
    - **Goal gaps**: Completion lowest (GA: 25.9%, GM: 13.8%). Success also low.
    - **Context gaps**: Token use highest (CA: 181.1k, CM: 166.0k). Success moderate (CA: 27.8%, CM: 19.4%).
    - **Constraint gaps**: Completion high (KA: 72.3%, KM: 77.5%), but Compliance very low (KA: 46.6%, KM: 4.7%). Success low (KA: 33.7%, KM: 0.0%).
    - **Missingness vs Ambiguity**: Missingness yields lower Success in all domains.

2.  **RQ2: Model x Harness Performance**
    - **Completion vs Success**: Higher Completion does not imply higher Success. e.g., Under Constraint-Missing, all systems have 0% Success despite some high Completion.
    - **Ranking Changes**: GPT-Sol leads Full Success but ranks 4th/5th under underspecification. DS-Pro ranks last under Full but first under Goal-Missing.
    - **Repeat Consistency**: Higher Mean Success does not imply higher `pass^3`. e.g., DS-Flash has highest Mean (24.8%) and `pass@3` (39.9%), but GLM-5.3 has highest `pass^3` (12.3%).

3.  **RQ3: Clarification Opportunities**
    - **Clarification Rate**: Varies across harnesses. NullClaw has highest rate (26.6% mean), others 8.5-10.7%.
    - **Estimated Gain**: Goal-Missing has largest gain (+17.4pp relative to GA). Constraint gaps have limited gain.
    - **Heterogeneity**: Clarification rates and gains vary more across harnesses than models.

## 한계

1.  **Task Domain Coverage**: Tasks are adapted from Terminal-Bench and Harness-Bench, primarily focusing on command-line and system administration workflows. The effects of underspecification might differ in other domains (e.g., creative tasks, web browsing).
2.  **Clarification Estimation**: The clarification gain estimation assumes that the user provides complete and correct information in response. In practice, user responses might be incomplete or ambiguous, leading to different outcomes.
3.  **Model and Harness Coverage**: Only 5 models and 4 harnesses are evaluated. The findings might not generalize to all possible model-harness combinations.
4.  **Static Underspecification**: The benchmark introduces fixed underspecification into tasks. It does not model dynamic or interactive clarification processes where the agent iteratively refines its understanding.

## 왜 중요한가

AM-Bench는 에이전트 연구와 실무에 중요한 시사점을 제공합니다.

1.  **벤치마크 설계**: 작업 불명확성을 체계적으로 분류하고 모델-하네스 크로스 평가를 도입함으로써, 에이전트 성능 평가의 **실제성**과 **심도**를 높입니다. 단순한 "완료" 비율보다 Completion, Compliance, Success를 분리하여 측정하는 것이 에이전트의 **robustness**와 **compliance**를 평가하는 데 중요합니다.
2.  **모델 개발자**: 불명확성 하에서의 성능을 평가할 때, 완전 specified 조건(Full)에서의 성능만으로는 충분하지 않습니다. 다양한 불명확성 조건(GA, GM, CA, CM, KA, KM)에서 Completion, Success, repeat consistency를 모두 측정해야 합니다.
3.  **하네스 개발자**: 하네스는 에이전트가 불명확한 상황에서 명확화 요청을 support해야 합니다. 특히 제약 조건이나 목표가 불명확할 때, dependent actions 전에 clarification을 유도하는 메커니즘이 중요합니다.
4.  **사용자**: 작업을 지정할 때, **제약 조건과 목표를 명확하게** 명시하고, **실행에 필요한 맥락 정보**를 제공해야 합니다. 불명확성은 에이전트의 성공률을 크게 낮추며, 특히 누락(Missingness)이 모호성(Ambiguity)보다 더 해롭습니다.

AM-Bench는 작업 불명확성 하에서의 에이전트 행동을 이해하기 위한 **첫 번째 체계적인 벤치마크**로서, 향후 에이전트 연구의 방향을 제시합니다.

## 원문 초록

> Ambiguous or incomplete task specifications complicate both execution and clarification for language-model agents. Yet agents' responses to these information gaps remain poorly characterized across models and execution harnesses. We present AM-Bench, a benchmark built from 48 tasks adapted from Terminal-Bench 2.0 and Harness-Bench. Each task includes a fully specified reference and six variants spanning ambiguous or missing goals, context, and constraints. We evaluate every pairing of five models and four harnesses over 20,160 runs. Our results reveal distinct execution deficits: goal gaps hinder completion, context gaps increase token use, and constraint gaps weaken compliance without necessarily preventing completion. Missingness lowers success more than ambiguity in all three domains. These effects also reshape system comparisons: advantages under complete information need not persist, and rankings depend on model $\times$ harness pairings and the evaluation criterion -- completion, success, or repeat consistency. Estimates based on observed clarification requests and matched fully specified runs further suggest that clarification could recover unfinished work while leaving most constraint violations unresolved. Together, these findings motivate joint model-harness evaluation across information conditions and targeted clarification of unresolved requirements before dependent actions. To support future research on agents under task underspecification, we provide the AM-Bench project repository at https://github.com/s4-lab-cuhksz/AM-Bench.git.
