## 한 줄 요약

CritICL은 같은 모델 계열의 작은 언어 모델들이 반복적으로 보이는 실수 유형(failure mode)을 오프라인에서 미리 분석해 두고, 추론 시점에 강한 모델의 프롬프트에 그 실수를 피하도록 돕는 critique 예시를 넣어, 생성을 거의 반복하지 않으면서 추론 성능을 높이는 방법이다.

## 핵심 개념 풀이

**failure mode**

failure mode는 모델이 틀린 답을 낼 때 그 오답을 만든 사고 방식의 패턴이다. 단순히 "이 문제에서 틀렸다"가 아니라 "이런 유형의 실수를 해서 틀렸다"를 가리킨다. 예를 들어 분수를 비교할 때 통분하지 않고 분자만 보고 크기를 잘못 판단했다면, 그건 arithmetic error가 아니라 comparison failure mode의 일종이다. 논문에서는 algebraic sign error, logical step skipping, incorrect formula application 같은 라벨로 실수를 분류한다. 이렇게 이름을 붙이면 서로 다른 문제에서도 같은 종류의 실수를 모아서 다룰 수 있다.

**in-context learning(ICL)**

in-context learning은 모델의 가중치를 바꾸지 않고 프롬프트에 몇 개의 예시를 넣어 답을 유도하는 방법이다. 예를 들어 수학 문제 몇 개와 정답을 보여준 뒤 새 문제를 주면, 모델은 예시의 형식을 따라 풀이와 답을 만든다. 보통 few-shot learning이라고도 부르며, 예시가 1개면 1-shot, 3개면 3-shot이다. 표준 ICL은 정답 예시를 넣는 데 집중하기 때문에 "올바른 답이 어떻게 생겼는지"는 보여주지만 "이 모델이 특히 어떤 실수를 하는지"는 직접 알려주지 않는다.

**inference-time scaling과 test-time scaling**

inference-time scaling은 학습을 다시 하지 않고 추론 시점에 계산량을 늘려 성능을 올리는 접근이다. 대표적으로 self-consistency는 같은 문제에 대해 여러 개의 답을 생성한 뒤 다수결로 최종 답을 고른다. self-reflection은 모델이 자기 답을 비판하고 수정하게 하고, LLM-as-a-judge는 외부의 강한 모델이 여러 후보 답을 평가하게 한다. 이 방법들은 효과가 있지만 생성 횟수가 늘어나므로 토큰 비용과 지연 시간이 커진다. 예를 들어 5번 생성하면 대략 출력 토큰도 5배 가까이 늘어난다.

**weak-to-strong generalization**

weak-to-strong generalization은 약한 모델이나 약한 감독 신호에서 얻은 정보를 강한 모델을 개선하는 데 쓰는 일반화를 뜻한다. 보통은 학습 단계에서 약한 teacher나 약한 라벨로 강한 student를 학습시키는 설정을 가리킨다. CritICL은 이와 달리 파라미터를 전혀 업데이트하지 않고 추론 시점에만 약한 모델의 정보를 쓴다. 여기서 "약한 모델의 정보"는 약한 모델이 낸 정답이 아니라 그 모델이 반복적으로 빠지는 실수 패턴이다. 실수 패턴은 직접 답을 가르치는 것보다 더 전이 가능한 신호일 수 있다.

**CritBank와 critique**

CritBank는 CritICL이 사용하는 오프라인 데이터 저장소다. 각 항목은 질문, 틀린 응답, failure mode 라벨, 그리고 자연어 critique를 포함한다. critique는 "어떤 단계에서 왜 틀렸고 어떻게 고쳐야 하는지"를 짧은 자연어로 설명한 것이다. 예를 들어 "두 분수를 비교할 때 통분을 하지 않고 분자만 비교해서 4/3을 11/8보다 크다고 잘못 판단했다" 같은 식이다. 정답만 보여주는 few-shot 예시와 달리 critique는 하지 말아야 할 사고 경로를 직접 짚어 준다.

## 문제의식

기존 추론 성능 개선 방법은 대부분 반복 생성이나 외부 검증에 의존한다. self-consistency는 같은 문제를 3번, 5번, 7번 생성해야 하고, self-reflection은 모델이 생성과 비판을 여러 차례 주고받아야 하며, LLM-as-a-judge는 후보 답 여러 개를 만들어 별도의 judge 모델까지 호출해야 한다. 이 때문에 정확도는 올라가도 실제 서비스에서는 API 호출 수, 지연 시간, 토큰 비용이 크게 늘어난다. 예를 들어 수학 문제 하나에 7개의 긴 풀이를 생성하면 출력 토큰이 수천 개에 이를 수 있다.

또한 약한 모델을 추론 시점에 활용하는 기존 weak-to-strong 방식은 새 입력마다 약한 모델을 다시 실행해 온라인 감독이나 중간 지도를 만들어야 한다. 이는 여전히 추가 추론 부담을 만들고, 약한 모델의 직접 출력 품질에 성능이 좌우될 수 있다. 더 중요한 문제는 약한 모델이 가진 더 풍부한 신호, 즉 "어떤 체계적인 방식으로 실패하는가"를 충분히 활용하지 못한다는 점이다.

논문의 관찰에 따르면 LLM의 오류는 무작위가 아니라 구조화되어 있고 예측 가능한 패턴이 있다. 같은 계열의 1.5B 모델과 72B 모델조차 자주 등장하는 failure mode의 상대적 분포가 상당히 비슷하다. 그렇다면 약한 모델의 실수 패턴을 미리 분석해 두면 강한 모델이 빠질 가능성이 높은 함정을 저렴하게 예측할 수 있다. 기존 방법은 이 구조화된 실패 신호를 버리고 있었다는 점이 CritICL의 문제의식이다.

## 핵심 아이디어

CritICL의 본질은 "약한 모델의 실패"를 제거해야 할 노이즈가 아니라 강한 모델을 위한 안내 신호로 재해석하는 것이다. 약한 모델과 강한 모델이 같은 모델 계열이면 학습에 쓰인 아키텍처, tokenizer, 사전학습 데이터, instruction tuning 방식이 상당 부분 겹치기 때문에 실수 패턴도 비슷하게 남는다. 따라서 약한 모델에서 발견한 반복적 실패는 강한 모델의 잠재적 실패를 미리 알려주는 일종의 지도가 된다.

이 아이디어를 실제 추론에 쓰려면 실패 신호를 모델이 이해할 수 있는 형태로 바꿔야 한다. 논문은 단순히 "이 문제에서는 이런 라벨의 실수가 있었다"고 알려주는 것을 넘어, 틀린 응답과 그에 대한 자연어 critique를 프롬프트 예시로 넣는다. 이렇게 하면 모델은 올바른 답만 보는 것이 아니라, 비슷한 실수가 어떤 사고 과정에서 생기고 어떻게 피해야 하는지를 문맥에서 직접 본다.

오프라인 사전 계산이 핵심 효율성 원천이다. 약한 모델을 여러 문제에 돌려 틀린 응답을 모으고, 실수 라벨과 critique를 붙이는 작업은 추론 시점이 아니라 CritBank를 만들 때 한 번만 수행한다. 실제 쿼리가 들어오면 CritBank에서 필요한 예시만 꺼내 프롬프트에 붙이면 되므로, 강한 target model은 기본적으로 1회만 생성하면 된다. 반복 생성을 오프라인 자원으로 대체한 셈이다.

CritICL에는 입력에 따라 실패 모드를 예측하는 CritICL-dynamic과, 모델 계열 전체의 평균적 실패 분포를 쓰는 CritICL-static 두 갈래가 있다. dynamic은 쿼리별로 "이 문제에서 내가 어떤 실수를 할 가능성이 높은가"를 먼저 물어 관련 critique를 가져온다. static은 입력을 보지 않고 약한 모델들에서 자주 나타난 지배적 failure mode들을 고정해 두고 그에 맞는 critique를 가져온다. 둘 다 공통적으로 "의미적으로 비슷한 문제"가 아니라 "실패 유형이 같은 문제"를 찾는다는 점이 다르다.

## 방법

CritBank를 만드는 첫 단계는 작은 모델로 틀린 응답을 대량 생성하는 것이다. 문제 집합을 $\mathcal{Q}$, 작은 모델 집합을 $M$이라 하자. 각 질문 $q$와 모델 $m$에 대해 chain-of-thought 프롬프트로 5개의 응답 $R(q,m)=\{r_{q,m}^{(i)}\}_{i=1}^{5}$을 만든다. 각 응답에는 중간 추론 단계와 최종 답이 들어 있다. 그다음 정답 여부를 판정하는 함수 $\phi(q,r)\in\{0,1\}$을 적용해 $\phi(q,r)=1$이면 맞는 응답, $\phi(q,r)=0$이면 틀린 응답으로 나눈다. CritBank는 틀린 응답들만 저장한다. 틀린 응답이 실패 모드를 노출하기 때문이다.

두 번째 단계는 각 틀린 응답에 failure mode 라벨과 critique를 붙이는 것이다. 논문에서는 gpt-4o-mini 같은 frontier LLM을 사용해 각 틀린 응답마다 최대 5개의 후보 failure mode 라벨을 생성한다. 이 라벨들은 노이즈가 있거나 의미가 겹칠 수 있으므로 군집화를 통해 비슷한 라벨을 묶고 대표 failure mode를 뽑는다. 또한 같은 $(q,r)$ 쌍에 대해 자연어 critique를 따로 생성한다. critique는 틀린 단계를 짚고 왜 틀렸는지, 어떻게 고칠지 설명하지만 정답 전체를 직접 제공하지는 않는다.

최종 CritBank는 $(q,r,l,\mathcal C(q,r))$ 형태의 튜플로 구성된다. 여기서 $l$은 그 틀린 응답에 할당된 failure mode이고, $\mathcal C(q,r)$은 해당 응답의 critique다. 한 응답에 여러 failure mode 라벨이 붙을 수 있으므로 라벨링 함수 $\mathcal L(q,r)$는 집합 값을 가진다. 특정 failure mode $l$이 달린 모든 사례를 찾기 위해 역매핑 $\mathcal L^{-1}(l)$을 정의한다. 이 역매핑이 이후 검색의 핵심이다. 어떤 라벨에 대해 CritBank 안의 모든 관련 질문-틀린응답 쌍을 바로 꺼낼 수 있다.

CritICL-dynamic은 새 질문 $q'$이 들어오면 먼저 target model에게 "이 문제에서 일어날 법한 failure mode 최대 5개를 예측하라"고 물어 $S_{\text{inst}}(q')$를 얻는다. 그다음 실패 모드 기반 선택 알고리즘을 써서 이 집합과 라벨이 겹치는 Critique 예시를 CritBank에서 최대 5개 뽑는다. 선택 점수는 후보 예시의 라벨 집합과 목표 라벨 집합의 교집합 크기로 계산한다. 수식으로는 $\operatorname{score}(q,r;S)=|\mathcal L(q,r)\cap S|$이고, 가중치를 주는 경우에는 겹친 라벨별 가중치 합을 쓴다. 점수가 높은 후보부터 고르되 이미 다룬 failure mode를 다시 다루는 예시는 후순위로 미뤄 중복을 줄인다. 마지막으로 선택한 예시들을 질문 앞에 붙여 target model이 최종 답을 만들게 한다.

CritICL-static은 입력별 예측을 하지 않는다. 약한 모델들이 만든 틀린 응답들에서 계열 전체의 failure mode 빈도 분포 $P_{\mathcal M}(l)$을 계산한다. 이 분포에서 가장 자주 나타나는 상위 $T$개의 failure mode를 $S_{\text{prof}}(\mathcal M)$으로 고른다. 그 뒤는 dynamic과 동일하게 이 라벨 집합과 겹치는 critique 예시를 CritBank에서 검색해 프롬프트에 넣는다. static은 target model 호출이 1번이면 끝나고, dynamic은 failure mode 예측 단계 때문에 target model 호출이 2번이다. 논문에서는 static이 더 안정적이고 효율적인 경우가 많다고 보고한다.

## 왜 성립하는가

CritICL이 성립하는 첫 근거는 failure mode 분포가 모델 크기가 달라도 같은 계열 안에서 상당히 일관된다는 관찰이다. 논문은 Qwen 계열에서 1.5B, 3B, 7B 약한 모델들의 failure mode 통계를 합친 뒤 72B 모델의 분포와 비교했다. 그림 2에서 상위 20개 failure mode의 상대 빈도 순서와 크기가 크게 변하지 않는 모습이 나타난다. 정량적으로는 Qwen 약한 모델 집계 프로파일과 72B 프로파일의 Spearman 상관이 0.91이고, 개별 약한 모델을 쓸 때보다 항상 높았다. Llama 계열에서도 집계 프로파일의 Spearman 상관이 0.88로 높았다.

여기서 집계가 개별 모델보다 더 나은 이유는 서로 다른 작은 모델이 상호 보완적인 실수 부분집합을 포착하기 때문이다. 1.5B 모델만 쓰면 그 모델이 잘 맞추는 영역의 실수가 덜 잡히고, 7B 모델만 쓰면 다른 실수가 빠질 수 있다. 여러 약한 모델을 합치면 error landscape를 더 넓게 덮어 강한 모델의 실패 분포를 더 잘 근사한다. 이 관찰이 CritICL-static이 입력별 예측 없이도 전역 프로파일만으로 효과를 내는 이유다.

둘째 근거는 failure mode 기반 선택이 단순 의미 검색보다 훨씬 강력하다는 ablation 결과다. 표 3에서 semantic similarity 기반 검색은 표면적으로 비슷한 문제를 가져오지만 정작 그 문제에서 모델이 저지를 특정 실수를 겨냥하지 못한다. 반면 failure mode 기반 검색은 "이 모델이 어떤 유형의 추론 단계에서 틀리는가"에 정확히 대응하는 critique를 가져온다. 예를 들어 분수 비교에서 틀릴 모델에게 분수 문제를 아무리 많이 보여줘도 비교 전략을 고치라는 critique가 없으면 같은 실수를 반복할 수 있다.

셋째로, source-of-gain ablation을 보면 단순히 추가 문맥을 넣거나 GPT의 지식을 넣는 것만으로는 성능 향상이 설명되지 않는다. 정답 예시를 조밀하게 검색하는 변형, 일반 GPT critique를 넣는 변형, 약한 모델의 틀린 응답만 넣는 변형, failure 라벨을 임의로 섞는 변형 모두 CritICL-static보다 낮았다. 따라서 핵심은 weak-model failure mode와 검색된 critique 사이의 정렬이다. 틀린 응답과 그 실패 유형을 함께 보여줄 때 모델이 자신의 비슷한 실수를 피하도록 행동이 바뀐다.

논문은 failure mode가 왜 규모를 넘어 전이되는지에 대해 같은 계열의 공유된 inductive bias를 유력한 설명으로 제시한다. 아키텍처, tokenizer, 사전학습 파이프라인, instruction tuning 방식이 같으면 모델 규모가 커져도 체계적 추론 경향이 완전히 사라지지 않을 수 있다. 다만 저자들은 이것을 확정적 기계론적 설명이 아니라 경험적 관찰에 대한 그럴듯한 해석이라고 명시한다. 인과적 연결을 밝히는 것은 후속 과제로 남겨 둔다.

## 구체적 예시

논문의 사례 연구는 failure mode 기반 검색과 의미 기반 검색의 차이를 분수 비교 문제로 보여준다. 문제는 집합 $\left\{\frac{3}{7},\frac{4}{3},\frac{11}{8},\frac{6}{16}\right\}$에서 가장 큰 원소와 가장 작은 원소의 양의 차이를 구하는 것이다. 실제 값을 보면 $\frac{3}{7}$은 약 0.4286, $\frac{4}{3}$은 약 1.3333, $\frac{11}{8}$은 1.375, $\frac{6}{16}$은 0.375다. 따라서 가장 큰 값은 $\frac{11}{8}$이고 가장 작은 값은 $\frac{6}{16}$이다. 올바른 차이는 $\frac{11}{8}-\frac{6}{16}=\frac{22}{16}-\frac{6}{16}=\frac{16}{16}=1$이다.

오답 모델은 $\frac{4}{3}$과 $\frac{11}{8}$을 비교하면서 잘못된 판단을 했다. 두 분수를 통분하면 $\frac{4}{3}=\frac{32}{24}$, $\frac{11}{8}=\frac{33}{24}$이므로 $\frac{11}{8}$이 더 크다. 하지만 모델은 분모를 제대로 비교하지 않아 $\frac{4}{3}$을 최댓값으로 착각했다. 최솟값은 $\frac{6}{16}=\frac{3}{8}$으로 제대로 잡고, $\frac{4}{3}-\frac{3}{8}$을 계산했다. 통분하면 $\frac{32}{24}-\frac{9}{24}=\frac{23}{24}$이 되어 틀린 답 $\frac{23}{24}$가 나왔다. 이 오답은 단순 산수 실수가 아니라 "값이 가까운 두 분수를 잘못 비교하는" failure mode에서 비롯한다.

의미 기반 검색을 쓰면 이 문제와 비슷한 분수 문제나 집합 문제를 가져오기 쉽다. 그런데 그 예시들이 반드시 "가까운 분수나 크기를 잘못 비교하는" 실수를 포함하지는 않는다. 겉으로는 비슷해 보여도 정작 모델이 교정해야 할 비교 전략을 보여주지 못할 수 있다. 그러면 모델은 같은 유형의 비교 실수를 다시 저지를 가능성이 크다.

실패 모드 기반 검색은 다르다. 이 문제에서 예측된 failure mode를 공유하는 다른 문제를 CritBank에서 찾는다. 논문 사례에서는 도형 넓이 문제에서 가장 큰 영역을 잘못 고른 사례가 검색되는데, 이 사례의 실패 원인도 상대적 크기를 잘못 해석한 것이다. 그 예시에 달린 critique는 "비교 전략이 잘못되었다"거나 "상대적 크기를 오해했다"는 점을 지적한다. 모델은 이 critique를 보고 분수 비교에서 통분을 다시 확인하거나 공통 분모로 바꾸는 절차를 적용하게 된다.

결과적으로 모델은 $\frac{11}{8}$이 $\frac{4}{3}$보다 크다는 것을 올바르게 파악하고, 최솟값 $\frac{6}{16}$과의 차이를 $\frac{11}{8}-\frac{6}{16}=1$로 계산한다. 이 예시는 surface-level similarity가 아니라 reasoning error type의 정렬이 중요하다는 것을 보여준다. 문제가 서로 달라도 실패 방식이 같으면 교정 전략이 전이될 수 있다.

## 실험과 결과

주요 벤치마크는 수학 추론 데이터셋인 GSM8K, MATH와 경쟁 수준의 AMC23, AIME24, AIME25다. CritBank는 GSM8K와 MATH의 훈련 분할에서 약 15,000개 질문을 모아 만든다. 평가는 GSM8K와 MATH의 전체 테스트 세트에서 Pass@1 정확도로 하고, AMC와 AIME는 out-of-distribution 일반화를 보기 위해 쓴다. Pass@1은 한 번 생성한 답이 정답이면 맞는 것으로 세는 지표다. 베이스라인은 0-shot, 1/3/5-shot random, 1/3/5-shot fixed, self-consistency 3/5/7, self-reflection, LLM-as-a-judge다.

Qwen2.5-32B-Instruct에서는 CritICL-static의 전체 평균이 49.8%로 가장 좋았고 CritICL-dynamic은 49.1%였다. 가장 강한 test-time baseline은 Consistency@7의 49.5%였는데, CritICL-static은 생성을 7번 반복하는 대신 1번만 하고도 0.3포인트 높았다. MATH 단독으로 보면 CritICL-static은 59.2%, Consistency@7은 58.6%였다. 또한 표준 ICL의 5-shot fixed 전체 평균 46.0%보다 3.8포인트 높았다. out-of-distribution의 AMC23, AIME24, AIME25에서도 static이 21.3% 평균으로 5-shot fixed 18.7%보다 높았다.

Qwen2.5-72B-Instruct에서는 격차가 더 뚜렷하다. CritICL-static의 전체 평균은 59.2%로, Consistency@5 59.0%, LLM-as-a-judge 58.5%, self-reflection 58.2%를 모두 넘었다. CritICL-dynamic도 58.7%로 Consistency@5와 거의 같았지만 생성 횟수는 2번이다. 표준 ICL 중 가장 좋은 5-shot fixed는 56.3%로, CritICL-static과 2.9포인트 차이가 났다. MATH에서 static은 84.0%, Consistency@5는 83.2%였다. 이 결과는 target model이 강해져도 약한 모델의 실패 정보가 여전히 유용하다는 것을 보여준다.

Llama 계열에서도 비슷하다. Llama-3.1-70B-Instruct를 target model로 쓰고 Llama-3.2-1B, 3B, Llama-3.1-8B에서 CritBank를 만들었다. CritICL-static의 전체 평균은 53.1%로 Consistency@5의 51.3%보다 1.8포인트 높았다. GSM8K에서 static은 95.9%, MATH에서 67.2%였다. out-of-distribution의 AIME24는 22.4%, AIME25는 20.7%로 test-time scaling보다 높았다. 이는 특정 모델 계열에만 작동하는 효과가 아님을 보여준다.

토큰 비용에서도 이점이 크다. Qwen2.5-32B-Instruct의 MATH 기준으로 CritICL-static은 총 3,768 토큰, CritICL-dynamic은 3,897 토큰을 썼다. 반면 Consistency@3는 4,192, Consistency@5는 4,814, consistency@7는 5,440, LLM-as-a-judge는 6,465, self-reflection은 7,533 토큰이었다. CritICL-static은 표준 5-shot fixed의 3,620 토큰보다 입력은 약간 많지만 출력은 296 토큰으로 오히려 적었다. 즉 critique가 모델을 더 직접적으로 정답에 도달하게 해 출력이 짧아지는 경향이 있다. 생성 횟수는 static이 1회, dynamic이 2회인데, test-time scaling은 3회에서 7회 이상이다.

Ablation에서 failure mode 기반 선택의 기여가 분명하게 드러난다. Qwen2.5-72B에서 MATH 정확도는 CritICL-static 59.2%, CritICL-dynamic 58.6%였다. 같은 설정에서 semantic similarity 기반 검색은 53.8%, random은 53.1%, fixed는 52.4%에 그쳤다. AMC23에서는 static 26.6%, dynamic 26.7%인 데 비해 semantic은 21.9%였다. 또 source-of-gain ablation에서 CritICL-static의 5개 벤치마크 평균은 59.9%였고, dense correct-exemplar retrieval은 57.4%, shuffled failure labels는 57.8%였다. 이는 추가 context나 GPT 지식 주입만으로는 설명되지 않는 고유한 효과가 failure mode 정렬에 있음을 보여준다.

다른 도메인 실험도 있다. GPQA의 Chemistry, Biology, Physics, Quantum Mechanics에서 Llama-3.1-70B에 대해 CritICL-static은 평균 74.4%를 기록했다. 5-shot fixed는 68.6%, Consistency@5는 71.8%, LLM-as-a-judge는 71.5%였다. 과학 지식이 많이 필요한 문제에서도 실패 패턴 기반 안내가 효과를 냈다. 부트스트랩 유의성 검정에서는 MATH 개선이 p-value 0.018로 유의했고, 매크로 평균도 p-value 0.041로 유의했다. 다만 AIME24와 AIME25는 평가 예시 수가 적어 신뢰구간이 넓다.

## 한계

가장 분명한 한계는 같은 모델 계열 안에서의 전이가 교차 계열 전이보다 훨씬 강하다는 점이다. Qwen 약한 모델의 CritBank를 Llama-3.1-70B에 쓰면 5-shot ICL보다는 좋지만, Llama 자체 CritBank를 쓸 때보다 성능이 낮았다. 정량 분석에서도 Qwen과 Llama 사이 교차 계열 Spearman 상관은 0.46과 0.43으로, 같은 계열의 0.88~0.91보다 크게 낮았다. 따라서 CritBank가 보편적 실수 사전처럼 모든 모델에 동일하게 작동하지는 않는다.

failure mode 주석은 자동 생성에 의존한다. GPT-4o-mini로 만든 라벨을 GPT-4.1, Claude-3.5-Sonnet, 인간 주석과 비교한 결과 F1이 0.81~0.84로 높았지만 완벽하지는 않았다. 인간-인간 F1이 0.86이므로 자동 주석과 인간 주석의 차이는 인간 간 차이에 가깝지만, 그래도 라벨 노이즈가 남을 수 있다. 특히 failure mode taxonomy의 세분도에 따라 성능이 달라진다. 논문에서는 8개 coarse 그룹, 20개 fine 그룹, 45개 very fine 그룹을 비교했는데 20개가 59.9%로 가장 좋았고 45개는 59.3%로 오히려 낮았다. 지나치게 잘게 나누면 검색 풀이 파편화되어 일치가 드물어진다.

비용 면에서는 CritBank를 만드는 오프라인 비용이 존재한다. 약한 모델 여러 개를 15,000문제에 대해 5회씩 돌려 오답을 모으고, 각 오답에 대해 GPT 기반 라벨링과 critique 생성을 해야 한다. 이 비용은 한 번만 들고 쿼리가 많아질수록 상각되지만, 쿼리가 아주 적은 일회성 사용에는 부담일 수 있다. 다만 논문은 이를 test-time scaling의 반복 비용을 재사용 가능한 오프라인 자원으로 옮긴 것이라고 설명한다.

통계적 유의성은 일부 벤치마크에서만 확인됐다. MATH와 매크로 평균에서는 유의한 개선이 있었지만 GSM8K, AMC23, AIME24, AIME25의 단독 비교에서는 p-value가 크고 신뢰구간이 넓다. 특히 AIME24와 AIME25는 표본 수가 작아 0.1~0.2포인트 차이를 해석하기 어렵다. 따라서 "모든 벤치마크에서 확실히 더 낫다"보다는 "전체적으로 경쟁력 있고 특정 과제에서는 유의하게 낫다"로 읽는 편이 정확하다.

저자들도 failure mode가 왜 규모를 넘어 전이되는지에 대해 기계론적 인과 증명을 제공하지 않는다고 인정한다. 공유된 inductive bias 때문이라는 설명은 그럴듯하지만 가설이다. 또한 CritICL-dynamic은 target model이 자기 failure mode를 잘 예측해야 효과가 좋을 텐데, 약한 target model이나 불확실한 문제에서 이 예측 단계가 얼마나 정확한지는 본문에서 충분히 다루지 않았다. dynamic이 예측을 잘못하면 관련 없는 critique를 뽑을 위험이 있다.

## 왜 중요한가

CritICL은 추론 성능을 높이기 위해 반드시 생성 횟수를 늘려야 한다는 암묵적 가정에 대안을 제시한다. 실패 패턴을 오프라인 지식으로 재사용하면 한 번의 생성으로도 여러 번 생성하는 test-time scaling과 비슷하거나 더 나은 정확도를 얻을 수 있다. 이는 API 지연 시간과 토큰 비용이 중요한 실무 환경에서 실용적 가치가 크다. 특히 같은 계열 모델을 여러 규모로 운영하는 조직이라면 작은 모델로 미리 실수 자원을 만들어 큰 모델 서비스에 적용하는 구조가 자연스럽다.

약한 모델을 "실패의 교사"로 쓰는 관점은 weak-to-strong generalization을 학습이 아닌 추론 시점으로 확장한다. CritICL은 파라미터 업데이트가 없으므로 기존 모델 서빙 파이프라인에 prompt 단계만으로 붙일 수 있다. 라벨과 critique가 사람이 읽을 수 있는 형태이기 때문에 모델이 왜 틀리는지에 대한 해석 가능한 진단도 함께 얻는다. 실무자에게는 단순한 정확도 향상보다 "이 모델 계열이 반복적으로 겪는 실수 목록" 자체가 가치가 있을 수 있다.

후속 연구 관점에서는 failure mode taxonomy를 더 잘 설계하는 문제, 교차 계열 전이를 높이는 문제, 실패 패턴 형성의 기계론적 원인을 밝히는 문제가 열려 있다. 또한 CritBank를 test-time scaling과 결합하면, 예를 들어 여러 샘플을 뽑되 각 샘플을 failure-aware 프롬프트로 생성하게 하여 self-consistency를 더 개선하는 방향도 가능하다. 논문은 수학 중심이지만 GPQA 과학 영역에서도 효과를 보였기 때문에, 도메인별 failure mode 사전을 구축하는 접근이 다양한 분야로 확장될 여지가 있다.

## 원문 초록

> Recent advances in inference-time scaling have significantly improved the reasoning performance of large language models (LLMs). However, these methods typically rely on repeated generation or external verification. To address this limitation, we introduce CritICL, a novel inference-time framework that improves reasoning while maintaining high efficiency. Our key insight is that LLM failure modes exhibit structured patterns across model scales within the same family. Instead of treating failures as undesirable outputs, CritICL leverages them as a source of guidance. Specifically, we utilize failure modes derived from weaker models and incorporate them into inference through critique-based in-context examples. We propose two variants: CritICL-dynamic, which adaptively predicts input-specific failure modes and retrieves critiques, and CritICL-static, which uses a global failure mode profile to provide stable guidance. Experimental results show that CritICL consistently outperforms standard in-context learning and achieves performance competitive with or superior to test-time scaling methods, while requiring significantly fewer generations and lower token cost. Code available at: https://github.com/umwyf/CRITICL
