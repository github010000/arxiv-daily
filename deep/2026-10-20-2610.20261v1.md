# Harness Policy Distillation: Agent Policy를 Runtime Semantics와 정렬하기

## 한 줄 요약
HPD(Harness Policy Distillation)는 에이전트 모델이 실행 환경(harness)의 제어 규칙을 명시적으로 학습하도록 하여, 실제 배포 시 환경 contract에 부합하는 동작을 수행하도록 하는 방법론입니다.

## 핵심 개념 풀이

### 1. Runtime Harness (실행 환경)
에이전트 모델이 실제 제품에서 작동하기 위해서는 특정 **runtime harness** 안에 구동되어야 합니다. 이 harness는 어떤 동작이 실행 가능 있는지 결정하고, 상태를 어떻게 advance 시키며, 언제 루프를 종료할지 정의합니다. 예를 들어, 도구를 호출할 때 permissions를 체크하고, observation을 삽입하며, 작업의 순서를 관리합니다. 이 harness는 에이전트의 actions이 실행되는 "ruleset" 역할을 합니다.

### 2. Control Document (제어 문서)
HPD의 핵심 아이디어는 각 결정 boundary에서 **control document**라는 privileged information을 생성하는 것입니다. 이 문서는 runtime observations과 reference annotations을 compile하여, 현재 상태의 lifecycle stage, remaining obligations, ready calls, termination conditions 등을 담고 있습니다. 이 document는 모델이 다음 동작을 선택할 때 필요한 "contextual rules"를 제공합니다.

### 3. Harness Verification (환경 검증)
teacher model이 제안하는 actions은 harness verification을 통과해야 합니다. 이는 actions이 runtime contract under에서 executable한지 확인하는 과정입니다. verification을 통과한 actions만이 training target으로 사용되므로, 모델은 환경에 부합하는 동작만 학습합니다.

### 4. Three-View Training (세 가지 뷰 훈련)
HPD는 하나의 shared model을 세 가지 view로 jointly training합니다:
- **Harness-Replay (T)**: native context에서 action prediction (deployment 시 사용)
- **Injected (I)**: control document가 injected된 context에서 action prediction
- **Runtime (R)**: native context에서 control document reconstruction

이 세 view는 model이 runtime semantics를 internalize하도록 연결합니다.

### 5. Policy Mismatch (정책 불일치)
에이전트 모델과 harness 사이에 두 가지 mismatch가 존재합니다:
- **Supervision mismatch**: supervision에 사용되는 history와 agent의 own rollout history가 다름
- **Runtime-state mismatch**: model policy가 harness의 current execution requirements를 반영하지 못함

HPD는 explicit control-state supervision을 통해 이 mismatch를 해결합니다.

## 문제의식

일반적인 trajectory supervision은 어떤 action이 취해졌는지는 보여줍니다. 하지만 그 action 뒤의 **runtime semantics**(실행 환경의 제어 규칙)는 implicit하게 남습니다. 예를 들어, 도구를 호출했다는 사실만으로는 그 도구가 이미 수행되었는지, 아직 pending인지, termination이 가능한지 등의 control state가 명시되지 않습니다.

기존 방법들(DPO, RLVR, OPD 등)은 action target, preference, reward, teacher supervision을 통해 runtime-sensitive behavior를 학습할 수 있지만, underlying control state는 action, preference, reward, teacher supervision을 통해 infer되도록 bırak습니다. 이는 model policy와 harness policy 사이에 mismatch를 일으킵니다.

실제 배포 상황에서는 model이 harness의 execution contract under에서 executable한 actions을 생성해야 합니다. 하지만 ordinary trajectory data는 이 control state를 implicit하게 만들므로, model이 harness의 rules를 제대로 학습하지 못합니다.

## 핵심 아이디어

HPD의 핵심 아이디어는 **runtime control semantics를 explicit training target으로 만들**는 것입니다. 즉, action label뿐만 아니라, 그 action이 수행되는 runtime state의 control information도 함께 supervision target으로 사용합니다.

구체적으로:
1. Reference trajectories를 harness를 통해 replay하여 implicit한 runtime semantics를 recover합니다.
2. 이 semantics를 control documents로 representation합니다.
3. 이 documents는 teacher model이 actions을 generate할 때 privileged information으로 사용됩니다.
4. Harness verification은 resulting targets가 runtime contract under에서 executable한지 보장합니다.
5. Shared model을 control semantics recovered from control-state privileged information와 native history에 jointly training하여, 이 semantics를 model policy internalize합니다.

이 접근법은 executable runtime semantics를 dense supervision으로 변환하여, 각 decision boundary에서 harness-compatible actions을 학습하도록 합니다.

## 방법

### 3.1 Closed-loop execution under a runtime harness
Task instance $q$와 target runtime harness $H$를 가정합니다. Harness는 initial state $s_0$를 생성하고, state space $\mathcal{S}_H$는 complete runtime configurations을 포함합니다. Valid stopping states는 $\mathcal{S}_H^{\mathrm{term}}$이고, failure state는 $\bot$입니다.

Serializer $\Omega_H: \mathcal{S}_H \to \mathcal{X}_H$는 state를 model-visible context로 serialize하고, transition kernel $T_H: \bar{\mathcal{S}}_H \times \mathcal{A} \rightarrow \Delta(\bar{\mathcal{S}}_H)$는 action execution에 따른 successor law를 정의합니다.

Model $\pi_\theta$는 harness action policy $\pi_\theta(a \mid x)$를 생성하고, closed loop를 형성합니다:
```math
x_b = \Omega_H(s_b), \quad a_b \sim \pi_\theta(\cdot \mid x_b), \quad s_{b+1} \sim T_H(\cdot \mid s_b, a_b)
```

### 3.2 Runtime semantic alignment gap
Policy distillation은 context distribution $\mu$와 teacher conditional $\pi^{\mathrm{T}}(\cdot \mid x)$를 지정합니다:
```math
\mathcal{L}_{\mathrm{PD}}(\theta;\mu,\pi^{\mathrm{T}})=\mathbb{E}_{x\sim\mu}\left[D_{\mathrm{KL}}\!\left(\pi^{\mathrm{T}}(\cdot\mid x)\,\|\,\pi_{\theta}(\cdot\mid x)\right)\right]
```

Runtime-state mismatch는 conditional target at a given boundary에서 발생합니다. Action label은 what was emitted를 specifies하지만, runtime control labels는 lifecycle stage, remaining obligations, ready calls, termination conditions를 additionally identify합니다.

### 3.3 Harness Policy Distillation

#### Harness-Replay (T view)
Recorded trajectory $\tau^\star$를 harness를 통해 replay합니다. 각 boundary에서:
- $x_b^\star = \Omega_H(s_b^\star)$ (native context)
- $o_b^H = \operatorname{Observe}_{H}(s_b^\star)$ (runtime observations)
- $d_b^H = \Phi_H(o_b^H; \tau^\star, a_b^\star)$ (control document)

#### Injected (I view)
Control document $d_b^H$가 injected된 context에서 action prediction:
```math
\pi_\theta^I(a \mid x, d) = \pi_\theta(a \mid \operatorname{Inject}_H(x, d))
```

#### Runtime (R view)
Native history에서 control document reconstruction:
```math
\pi_\theta^R(d \mid x) = \pi_\theta(d \mid \operatorname{Probe}_H(x))
```

#### Training Objective
Weighted combination of three views:
```math
\mathcal{L}_{\mathrm{HPD}}=\alpha_T\mathcal{L}_T+\alpha_I\mathcal{L}_I+\alpha_R\mathcal{L}_R, \quad \alpha_T+\alpha_I+\alpha_R=1
```

## 왜 성립하는가

HPD가 성립하는 이유는 **explicit control-state supervision**이 model이 harness의 execution requirements를 learn하도록 help하기 때문입니다.

1. **Control documents provide privileged information**: 각 boundary에서 compiled control document는 runtime observations과 reference annotations을 포함합니다. 이 information은 teacher model이 actions을 generate할 때 필요한 "contextual rules"를 제공합니다.

2. **Harness verification ensures executable targets**: Teacher model이 제안하는 actions은 harness verification을 통과해야 합니다. 이는 actions이 runtime contract under에서 executable한지 보장하므로, model은 환경에 부합하는 동작만 학습합니다.

3. **Three-view training internalizes semantics**: 
   - T view는 native context에서 action prediction을 training하여 deployment policy를 direct supervise합니다.
   - I view는 control document가 injected된 context에서 action prediction을 training하여 control semantics를 action selection에 connect합니다.
   - R view는 native history에서 control document reconstruction을 training하여 history와 control state를 connect합니다.

이 세 view는 shared parameters를 통해 연결되어, model이 runtime semantics를 internalize하도록 합니다.

4. **Joint supervision improves generalization**: Control-state supervision은 model이 specific task patterns에 overfit하는 것을 방지하고, harness policy를 generalize하도록 help합니다.

## 구체적 예시

TRAJECT-Bench with Pi harness에서 Qwen3-8B을 예시로 들겠습니다.

**Reference trajectory replay**:
- Recorded action $a_b^\star$를 harness에 submit합니다.
- Recorded observations을 per-tool queues에서 consumption합니다.
- Resulting $s_{b+1}^\star$를 next boundary에서 capture합니다.

**Control document compilation**:
- $\operatorname{Observe}_H(s_b^\star)$는 accessible runtime fields를 snapshot $o_b^H$로 reading합니다.
- $\Phi_H(o_b^H; \tau^\star, a_b^\star)$는 snapshot과 reference annotations을 textual control document $d_b^H$로 mapping합니다.

**Harness-verified privileged teacher**:
- Frozen base model $\pi_{\theta_0}$는 document $d_b^H$와 native context $x_b^\star$를 conditioning하여 $K$ candidate actions $\tilde{a}_b^{(k)}$를 sampling합니다.
- $\mathcal{A}_b^{\mathrm{ver}} = \{\tilde{a}_b^{(k)}: V_{H,b}(s_b^\star, \tilde{a}_b^{(k)})=1\}$는 verification을 통과한 candidates의 set입니다.
- Selected action $\tilde{a}_b$는 reference similarity over remaining fields로 selection됩니다.

**Training targets**:
- Triple $(x_b^\star, d_b^H, \tilde{a}_b)$는 training target으로 사용됩니다.
- T view는 native context $x_b^\star$에서 $\tilde{a}_b$ prediction을 training합니다.
- I view는 injected context $\operatorname{Inject}_H(x_b^\star, d_b^H)$에서 $\tilde{a}_b$ prediction을 training합니다.
- R view는 native context $x_b^\star$에서 $d_b^H$ reconstruction을 training합니다.

**Deployment**:
- Trained model은 original harness interface를 사용하여 $\pi_\theta^T(\cdot \mid x)$로 actions을 생성합니다.
- Control document나 additional supplement가 필요 없습니다.

## 실험과 결과

### Table 1: Qwen3-8B comparison on TRAJECT-Bench/Pi
- **Base model**: TS 3.09%, RC 19.90%
- **HPD-T**: TS 20.58%, RC 43.74%
- **Full HPD**: TS 22.98%, RC 49.23%

**Key observations**:
1. HPD-T( harness-verified teacher actions only)은 OPD(teacher model)보다 TS에서 4.97 points higher입니다.
2. Full HPD(I/R views added)는 HPD-T보다 TS에서 2.40 points higher, Step-SR에서 4.54 points higher입니다.
3. SFT는 RC를 55.92%로 improvements하지만 TS를 2.06%로 lowers합니다. 이는 gold actions fitting이 task completion을 preserve하지 못함을 보여줍니다.
4. DPO는 Action-Acc에서 best를 achieve하지만 Step-SR이 11.12%로 low합니다.

### Table 2: HPD component and schedule ablation
- **T+R joint**: Step-SR 63.13%, RC 48.03% (TS 20.58%)
- **T+I joint**: Step-SR 56.92%, RC 41.68% (TS 20.58%)
- **Full HPD (T+I+R)**: TS 22.98%, Step-SR 63.79%, RC 49.23%

**Key observations**:
1. T+R은 Step-SR과 RC를 improvements하지만 TS는 changes하지 않습니다.
2. T+I도 TS를 changes하지 않고 execution metrics를 lowers합니다.
3. Only joint T/I/R raises TS beyond HPD-T, suggesting I and R contribute to completion in combination.

## 한계

1. **Training complexity**: Three-view training과 harness verification은 training process를 complexity하게 만듭니다.
2. **Control document generation**: AutoProbe($\operatorname{Observe}_H$와 $\Phi_H$)는 harness-specific adapters가 필요하여, 새로운 harness에 적용할 때 adaptation effort가 필요합니다.
3. **Reference trajectory dependency**: HPD는 reference trajectories에 의존하여 control documents를 generate합니다. Reference data의 quality와 coverage가 performance에 영향을 미칩니다.
4. **Computational overhead**: Teacher model sampling과 harness verification은 training time overhead를 증가시킵니다.

## 왜 중요한가

HPD는 agent training에서 **runtime semantics를 explicit supervision target으로 통합**하는 새로운 접근법을 제시합니다. 이는 다음과 같은 의미를 가집니다:

1. **Improved runtime compliance**: Model은 harness의 execution contract under에서 executable한 actions을 생성하도록 learning합니다.
2. **Better generalization**: Control-state supervision은 model이 specific task patterns에 overfit하는 것을 방지하고, harness policy를 generalize하도록 help합니다.
3. **Portable methodology**: HPD는 다양한 model architectures와 harnesses에 적용할 수 있습니다.
4. **Bridging the gap between model policy and harness policy**: Explicit control-state supervision은 model policy와 harness policy 사이의 mismatch를 줄입니다.

이 방법론은 general-purpose models를 deployed agents로 adapt할 때, runtime constraints를 explicit learning target으로 integration하는 중요한 step입니다.

## 원문 초록

> Deploying a general-purpose model as an agent means running it inside a product-specific runtime harness that decides which actions are executable, how state advances, and when the loop may terminate. Ordinary trajectory supervision shows which action was taken but leaves the runtime semantics behind that action implicit. We introduce Harness Policy Distillation (HPD), which makes these runtime control semantics an explicit training target alongside actions to align the harness policy. HPD replays reference trajectories through the harness to recover the runtime semantics that are implicit in ordinary trajectory data, and represents them as control documents at each model-call boundary. These documents provide privileged information for a teacher to generate actions, while harness verification ensures that the resulting targets are executable under the runtime contract. We jointly train a shared model on the runtime semantics recovered from control-state privileged information and native history, thereby internalizing these semantics into the model policy. At deployment, the trained model uses the original harness interface without requiring the control document or any additional supplement. On TRAJECT-Bench with the Pi harness, Qwen3-8B trained with HPD reaches 22.98% autonomous task success and 49.23% runtime compliance, against 3.09% and 19.90% for the unadapted model. Harness-verified teacher actions substantially improve the native deployment policy, while joint control-state supervision provides further gains in task completion and runtime compliance. HPD turns executable runtime semantics into dense supervision for learning harness-compatible actions at each decision boundary.
