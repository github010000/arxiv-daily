# Harness Policy Distillation: Aligning Agent Policies with Runtime Semantics

## 한 줄 요약
**HPD(Harness Policy Distillation)**는 에이전트가 실행되는 런타임 후크(harness)의 제어 세맨틱스(실행 계약, 의무, 상태 전이 규칙 등)를 명시적인 학습 목표로 추가하여, 모델 정책이 런타임 환경에 적응하도록 돕는 교육 방법입니다.

## 핵심 개념 풀이

### 1. 런타임 후크 (Runtime Harness)
에이전트(일반 목적 모델)를 실제 제품에 배포할 때는, 해당 제품의 특정 **런타임 후크**라는 환경 içinde에서 실행됩니다. 이 후크는 모델이 사용할 수 있는 액션의 종류, 상태가 어떻게 업데이트되는지, 언제 루프를 종료할 수 있는지 등을 결정하는 "실행 계약"이나 "프레임워크"입니다. 예를 들어, 어떤 도구가 현재 사용 가능한지, 어떤 의무가 아직 완료되지 않았는지, 최종 답변을 내릴 수 있는지 여부 등을 제어합니다. 모델은 후크가 제공하는 제한된 인터페이스를 통해 액션을 선택해야 합니다.

### 2. 제어 문서 (Control Document)
HPD의 핵심 개념 중 하나입니다. 참조_trajectory(참표본 경로)를 후크를 통해 다시 실행(replay)하면서, 각 모델 호출 경계(boundary)에서 런타임의 상태 정보를 추출하고, 참조 데이터에 기반한 제어 정보(예: "lookup 의무는 완료됨", "최종 답변 준비 상태")를 결합하여 생성된 **텍스트 형태의 문서**입니다. 이 문서는 모델이 해당 시점에서 어떤 제어 상태를 고려해야 하는지를 알려주는 "특권 정보(privileged information)" 역할을 합니다.

### 3. 정책 불일치 (Policy Mismatch)
에이전트에서 발생하는 두 가지 주요 문제입니다.
*   ** Supervision mismatch (감시 불일치):** 모델이 훈련할 때 참조 데이터의 histories(히스토리)에 적응하지만, 실제 실행에서 모델 자신의 액션이 만들어내는 히스토리는 훈련 분포와 differ할 수 있습니다.
*   **Runtime-state mismatch (런타임 상태 불일치):** 모델이 참조 액션만 모방할 뿐, 그 액션이 결정되는 런타임의 제어 상태(의무, 상태 전이 규칙 등)를 이해하지 못합니다. 예를 들어, 도구가 사용 가능하다는 사실만으로는 그 도구가 실제로 필요한 의무인지 알 수 없습니다.

### 4. 세 가지 훈련 뷰 (Three Training Views)
HPD는 하나의 공유 모델을 세 가지 다른 관점(뷰)에서 jointly training합니다.
*   **Harness-Replay (T 뷰):** native context(원문 문맥, 제어 문서 없음)로부터 검증된 액션을 예측하도록 훈련합니다. 이는 배포 시의 실제 상황과 동일합니다.
*   **Injected (I 뷰):** injected context(제어 문서가 추가된 문맥)로부터 동일한 검증된 액션을 예측하도록 훈련합니다. 제어 문서를 통해 런타임 세맨틱스를 명시적으로 학습합니다.
*   **Runtime (R 뷰):** native context로부터 제어 문서 자체를 예측하도록 훈련합니다. 이는 런타임 상태를 히스토리로부터 추론하는 능력을 기릅니다.

### 5. Harness Verification (후크 검증)
모델이 생성한 candidate actions( candidate 액션)이 런타임 후크의 계약(실행 가능 여부, 참조 상태 일관성 등)에 부합하는지 확인하는 과정입니다. 이를 통해 훈련 target으로 사용되는 액션이 실제 환경에서 실행 가능하도록 보장합니다.

## 문제의식

일반적인 에이전트 훈련 방법은 참조 trajectory(참조 경로)에서 모델이 수행한 **액션**만.supervise합니다. 그러나 이 액션들이 결정되는 **런타임 제어 세맨틱스**(예: 어떤 의무가 남아있는지, 언제 종료해야 하는지, 도구가 실제로 필요한 시점 등)는 implicit(암시적)로 남아있습니다.

이로 인해 발생하는 문제는 다음과 같습니다.
1.  모델이 참조 액션은 잘 모방할 수 있지만, 실제 런타임 환경에서 어떤 액션이 valid한지(실행 가능한지) 이해하지 못합니다.
2.  모델이 런타임의 상태(의무, 진행도 등)를 고려하지 않아, 이미 완료된 작업을 반복하거나, 아직 필요한 작업을 수행하지 않고 prematurely terminate하는 등 runtime contract를 위반할 수 있습니다.

기존 방법들(DPO, RLVR, OPD 등)은 액션, 선호도, Reward, teacher의 분포를 직접 target으로 삼아 런타임 제어 상태를 infer(추론)하게 합니다. 하지만 이는 model이 간접적으로 학습해야 하므로, 특히 복잡한 런타임 계약 하에서는 효율적이지 않고 불일치(policy mismatch)가 발생할 수 있습니다.

## 핵심 아이디어

HPD는 런타임 제어 세맨틱스를 **explicit training target**(명시적 훈련 target)으로 추가합니다. 즉, 모델에게 "무엇을 해야 하는지"(액션) 뿐만 아니라, "어떤 상황에서 무엇을 해야 하는지"(제어 상태)도 함께 학습시킵니다.

구체적으로:
1.  참조 trajectory를 런타임 후크를 통해 replay하면서, 각 경계에서 런타임 상태와 참조 정보를 결합한 **control document**를 생성합니다.
2.  frozen base model이 이 control document를 condition으로 candidate actions를 생성하고, **harness verification**을 통해 실행 가능하고 참조와 일치하는 액션을 training target으로 선택합니다.
3.  하나의 공유 모델을 세 가지ビュー(T, I, R)에서 joint training하여, 제어 문서를 예측하는 능력(R), 제어 문서를 통해 액션을 선택하는 능력(I), 그리고 native context에서 액션을 선택하는 능력(T)을 모두 학습시킵니다.
4.  배포 시에는 control document 없이 native context만으로 액션을 생성합니다.

이 방식으로, 모델은 런타임 계약과 상태 전이 규칙을 internalize(내재화)하여, 실제 환경에서 실행 가능한 정책을 학습하게 됩니다.

## 방법

### 1. 런타임 후크 تحت의 closed-loop execution
*   **State space $\mathcal{S}_H$:** 런타임의 완전한 상태(히스토리, 도구 인터페이스, 권한, 스케줄링 상태, 의무 bookkeeping 등).
*   **Serializer $\Omega_H$:** 상태를 모델이 볼 수 있는 텍스트 context $x$로 변환.
*   **Transition kernel $T_H$:** 액션 $a$를 실행했을 때 다음 상태 $s_{b+1}$로 전이하는 규칙.
*   **Admissible action set $\mathcal{A}_H(s)$:** 상태 $s$에서 실행 가능한 액션들의 집합.

### 2. HPD의 훈련 파이프라인

#### a. Reference Replay & Control Document Construction
*   참조 trajectory $\tau^*$를 후크 $H$를 통해 replay합니다.
*   각 모델 호출 경계 $b$에서:
    *   상태 $s_b^*$를 관찰하여 snapshot $o_b^H$를 생성.
    *   $\Phi_H$ compiler를 사용하여 $o_b^H$와 참조 annotations를 결합해 **control document $d_b^H$**를 생성.
    *   이 document는 runtime facts, reference progress, witness-derived labels(다음 제어 결정, ready frontier, final permission 등)를 포함합니다.

#### b. Harness-Verified Privileged Teacher
*   frozen base model $\pi_{\theta_0}$에 control document $d_b^H$와 native context $x_b^*$를 injection하여 $K$개의 candidate actions $\tilde{a}_b^{(k)}$를 샘플링합니다.
*   **Harness verification $V_{H,b}$**를 통해 candidate들 중 실행 가능하고 참조와 일관된 ones을 필터링하여 $\mathcal{A}_b^{\mathrm{ver}}$를 생성합니다.
*   $\mathcal{A}_b^{\mathrm{ver}}$에서 참조 액션 $a_b^*$와 cosine similarity가 가장 높은 candidate를 selected action $\tilde{a}_b$로 선택합니다.
*   retained record: $(x_b^*, d_b^H, \tilde{a}_b)$.

#### c. Three-View Joint Training
*   **T (Harness-Replay):** $\pi_\theta^T(a | x)$ — native context $x$로부터 $\tilde{a}_b$를 예측.
*   **I (Injected):** $\pi_\theta^I(a | x, d)$ — injected context $(x, d)$로부터 $\tilde{a}_b$를 예측.
*   **R (Runtime):** $\pi_\theta^R(d | x)$ — native context $x$로부터 $d_b^H$를 예측.
*   Loss: $\mathcal{L}_{\mathrm{HPD}} = \alpha_T \mathcal{L}_T + \alpha_I \mathcal{L}_I + \alpha_R \mathcal{L}_R$.

#### d. Deployment
*   trained model은 native context $x$만으로 $\pi_\theta^T(\cdot | x)$를 통해 액션을 생성합니다. control document는 필요하지 않습니다.

## 왜 성립하는가

HPD가 작동하는 핵심 메커니즘은 **control state를 explicit supervision으로 제공**하여 model이 런타임 세맨틱스를 직접 학습하게 하고, 이를 **native action prediction과 연결**시키는 데 있습니다.

1.  **Control document는 privileged information**로, model이 참조 trajectory에서 학습한 런타임의 의무, 상태 전이 규칙, 실행 계약 등을 명시적으로 알고 있게 합니다.
2.  **Harness verification**은 training target이 실제 환경에서 실행 가능하도록 보장하여, model이 invalid한 액션을 학습하는 것을 방지합니다.
3.  **세 가지 뷰의 joint training**은 control state를 예측하는 능력(R), control state를 통해 액션을 선택하는 능력(I), 그리고 native context에서 제어 state를 추론하여 액션을 선택하는 능력(T)을 모두 학습시킵니다. 이를 통해 model은 control document 없이도 native context로부터 런타임 세맨틱스를 internalize할 수 있게 됩니다.
4.  **KL divergence chain rule**에 의해, R과 I losses는 joint teacher distribution $\pi^{\mathrm{rep}}(d,a|x)$를 matching하게 하고, T loss는 deployment policy $\pi_T^{\mathrm{rep}}(a|x)$를 matching하게 합니다.

## 구체적 예시

**예시: Lookup 의무가 있는 작업**

1.  **Runtime contract:** Final response 전에 `lookup(item_id=42)`를 호출해야 함.
2.  **Reference trajectory:** `lookup(item_id=42)` 액션이 기록됨.
3.  **Replay:**
    *   초기 상태: `lookup=pending`, `final=blocked`.
    *   `lookup(item_id=42)`를 실행 후: `lookup=complete`, `final=ready`.
4.  **Control Document:**
    *   초기 경계: `lookup=pending; final=blocked`.
    *   이후 경계: `lookup=complete; final=ready`.
5.  **Training:**
    *   R 뷰: native context로부터 `lookup=pending; final=blocked` document를 예측하도록 훈련.
    *   I 뷰: injected context(동일 document)로부터 `lookup(item_id=42)` 액션을 예측하도록 훈련.
    *   T 뷰: native context로부터 `lookup(item_id=42)` 액션을 예측하도록 훈련.
6.  **Deployment:** model은 native context(히스토리)로부터 `lookup` 의무가 남아있는지 추론하여, 필요한 경우 `lookup` 액션을 선택합니다.

## 실험과 결과

### 1. Main Comparison (TRAJECT-Bench/Pi)
*   **Base model:** TS 3.09%, RC 19.90%
*   **HPD-T (T 뷰 only):** TS 20.58%, RC 43.74%
*   **Full HPD (T+I+R):** TS 22.98%, RC 49.23%
*   **OPD (strongest baseline):** TS 15.61%, RC 66.21%

**해석:** HPD-T도 verified action supervision만으로도 TS를 크게 향상시킵니다. Full HPD는 I/R 뷰를 추가하여 TS와 RC를 더 향상시킵니다. OPD는 RC는 높지만 TS는 HPD보다 낮습니다.

### 2. Component Ablation (Table 2)
*   **T+R joint:** TS 20.58%, Step-SR 63.13%, RC 48.03%
*   **T+I joint:** TS 20.58%, Step-SR 56.92%, RC 41.68%
*   **Full HPD (T+I+R):** TS 22.98%, Step-SR 63.79%, RC 49.23%

**해석:** T+R은 execution metrics(Step-SR, RC)를 향상시키고, T+I는 action accuracy에 도움. Full HPD는 completion(TS)을 추가로 향상시킵니다.

### 3. Cross-benchmark Transfer (BFCL v4, Table 7)
*   **HPD-T:** TS 13.04%, Step-SR 46.16%
*   **Full HPD:** TS 21.74%, Step-SR 48.12%

**해석:** 새로운_TASK에서 Full HPD는 HPD-T보다 TS에서 8.70점 더 높은 성능을 보입니다. 이는 I/R 뷰가 runtime semantics를 generalize하는 데 도움됩니다.

### 4. Model-size Scaling (Table 8)
*   Qwen3-8B HPD: TS 16.12% (Base 3.09%)
*   Qwen3-32B HPD: TS 19.90% (Base 6.00%)

**해석:** HPD는 모델 크기에 관계없이 일관된 개선을 제공합니다.

## 한계

1.  **Harness-specific adaptation:** HPD는 특정 런타임 후크에 적응합니다. 다른 후크를 사용하면 replay, control document, verification을 다시 구성해야 합니다.
2.  **Reference replay coverage:** Training distribution은 successful reference prefixes에 의존합니다. deployment error 후의 states는 cover되지 않습니다.
3.  **Privileged information:** Control document는 training-time privileged information입니다. deployment에서는 필요하지 않지만, construction에 필요합니다.
4.  **Verifier dependency:** Teacher construction은 harness verification과 reference annotation에 의존합니다.

## 왜 중요한가

HPD는 에이전트 훈련에서 **runtime semantics**를 explicit target으로 추가하는 새로운 접근법을 제시합니다. 이는 모델이 런타임 계약과 상태 전이 규칙을 이해하고 적응할 수 있도록 도와, 실제 환경에서 더 실행 가능하고 준수하는 정책을 학습하게 합니다.

*   **Practical impact:** 에이전트를 특정 제품/환경에 배포할 때, 런타임 후크의 constraints를 준수하는 정책이 필요합니다. HPD는 이를 효율적으로 학습할 수 있는 방법을 제공합니다.
*   **Theoretical insight:** policy distillation에 control-state supervision을 추가하여 runtime-state mismatch를 해결할 수 있음을 보여줍니다.
*   **Generalizability:** HPD는 다른 모델 아키텍처와 다른 런타임 후크에도 적용할 수 있습니다.

이 방법은 에이전트 훈련에서 "무엇을 해야 하는지"뿐만 아니라 "어떤 상황에서 무엇을 해야 하는지"를 학습하는 중요한 단계를 제시합니다.

## 원문 초록

> Deploying a general-purpose model as an agent means running it inside a product-specific runtime harness that decides which actions are executable, how state advances, and when the loop may terminate. Ordinary trajectory supervision shows which action was taken but leaves the runtime semantics behind that action implicit. We introduce Harness Policy Distillation (HPD), which makes these runtime control semantics an explicit training target alongside actions to align the harness policy. HPD replays reference trajectories through the harness to recover the runtime semantics that are implicit in ordinary trajectory data, and represents them as control documents at each model-call boundary. These documents provide privileged information for a teacher to generate actions, while harness verification ensures that the resulting targets are executable under the runtime contract. We jointly train a shared model on the runtime semantics recovered from control-state privileged information and native history, thereby internalizing these semantics into the model policy. At deployment, the trained model uses the original harness interface without requiring the control document or any additional supplement. On TRAJECT-Bench with the Pi harness, Qwen3-8B trained with HPD reaches 22.98% autonomous task success and 49.23% runtime compliance, against 3.09% and 19.90% for the unadapted model. Harness-verified teacher actions substantially improve the native deployment policy, while joint control-state supervision provides further gains in task completion and runtime compliance. HPD turns executable runtime semantics into dense supervision for learning harness-compatible actions at each decision boundary.
