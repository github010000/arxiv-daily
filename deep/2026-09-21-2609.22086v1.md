## 한 줄 요약
이 논문은 전문 그래픽 디자인 에이전트에서 모델 weight는 전혀 바꾸지 않은 채, 사용자 트래픽에서 얻은 성공·실패 이력으로 자연어 절차 memory를 새로 추가하고 기존 절차를 수리하되, noisy한 자동 judge 아래에서도 기존에 잘 되던 사례를 깨뜨리지 않는 변화만 반영하는 matched replay gate를 제안한다.

## 핵심 개념 풀이

### 1. long-horizon agentic graphic design
일반적인 text-to-image 모델은 문장에서 바로 픽셀 이미지를 생성한다. 하지만 전문 그래픽 디자인은 그렇게 만들어진 납작한 이미지가 아니라, Photoshop 같은 도구에서 사용자가 나중에 레이어를 열어 수정할 수 있는 구조물을 요구한다. 이 논문의 에이전트는 230개가 넘는 도구를 호출하면서 자산을 검색하고, 벡터를 조작하고, 마스크를 만들고, 타이포그래피를 배치하는 식으로 하나의 편집 가능한 디자인 상태를 단계적으로 만들어 간다. 하나의 짧은 요청에도 수십 개의 상호의존적인 도구 호출이 필요한 경우가 많기 때문에, 이것을 하나의 긴 순차 결정 문제로 보아야 한다.

### 2. procedural memory와 skill bank
procedural memory는 에이전트가 과거에 배운 작업 절차를 바깥에 저장해 두었다가 다시 꺼내 쓰는 기억 장치다. episodic memory가 "무슨 일이 있었는지"를 기억하는 것이라면, procedural memory는 "어떤 부류의 일을 어떻게 하는지"를 기억한다. 이 논문에서 각 skill은 자연어로 쓰인 `SKILL.md` 파일이며, 예를 들어 double exposure이라는 skill은 "대상을 추출하고, 마스크를 만들고, 다른 이미지를 그 안에 블렌딩하고, 다듬어라" 같은 절차를 담는다. 고정된 매크로와 달리 모델이 이 절차를 문맥에 맞게 재배열하거나 일부만 적용할 수 있는, 원자적 도구 호출과 전체 trajectory 사이의 중간 표현이다.

### 3. frozen model과 외부 memory 학습
여기서는 Claude나 Qwen 같은 기반 모델의 weight를 업데이트하지 않는다. 상업용 모델은 호스팅되어 있어 학습이 어렵거나 불가능할 수 있고, 프로덕션에서 모델을 자주 교체해야 하는 상황도 있다. 대신 학습 대상은 모델 주변의 외부 context, 곧 skill bank가 된다. 이는 마치 숙련된 작업자의 뇌를 다시 훈련시키는 대신, 더 나은 체크리스트를 만들어 주는 것과 비슷하다. 모델은 그대로 두고 오직 기억 창고의 자연어 절차만 바뀌기 때문에, 검사와 롤백이 쉽고 여러 backbone에 같은 skill bank를 재사용할 수도 있다.

### 4. widening과 deepening
skill bank의 진화에는 두 축이 있다. widening은 지금까지 라이브러리가 다루지 못한 반복되는 하위 작업을 발견해 새 skill을 추가하는 것이다. deepening은 이미 있는 skill이 실패에 반복적으로 연루될 때, 그 skill의 성공 사례와 실패 사례를 대조해서 기존 절차를 더 단단하게 고치는 것이다. 레스토랑에 비유하면 widening은 메뉴에 없는 요리를 새로 추가하는 일이고, deepening은 기존 요리의 레시피를 손보는 일이다. 논문의 핵심 주장 중 하나는 이 둘이 따로는 효과가 작지만 함께일 때 크게 좋아진다는 것이다.

### 5. noisy하고 unverifiable한 feedback
디자인 결과에는 코드 실행 테스트 같은 정답 판정기가 없다. "빨간 로고를 왼쪽 위에 놓아라" 같은 구체적 요구와 "고급스럽고 균형 잡힌 구성을 해달라" 같은 주관적 기준이 한 brief에 섞여 있다. 따라서 사람이나 자동 judge의 평가는 참값이 아니라 noisy한 proxy reward다. 더구나 LLM 기반 judge는 제시 순서에 따라 점수가 달라지는 position bias, 같은 모델 계열 산출물을 더 좋게 주는 self-enhancement bias, 같은 이미지라도 실행할 때마다 절대 점수가 흔들리는 judge drift 문제가 있다. 이 때문에 "평균 점수가 올랐으니 받아들인다"는 단순 규칙은 회귀를 유발할 수 있다.

### 6. matched replay gate
새 skill 후보나 수정된 skill 후보는 곧바로 배포되지 않는다. 먼저 그 skill을 실제로 사용해야 하는 prompt들을 뽑고, 각 prompt마다 자산 검색 결과나 상류 상태를 다르게 한 여러 context를 고정해 둔다. 그런 다음 같은 context에서 후보 skill과 기존 skill, 또는 후보 skill과 no-skill 조건을 같은 배치 안에서 다시 실행해 pairwise 비교한다. 어떤 prompt가 이기려면 여러 context 중 과반수에서 이겨야 하고, 최종적으로는 패배한 prompt가 하나도 없으면서 적어도 하나의 prompt에서는 이겨야만 통과된다. 이는 절대 점수 대신 상대 비교를 쓰고, context를 고정해 다른 변수를 차단하며, 기존 성공 사례를 replay에 포함시켜 회귀를 막는 보수적 gate다.

## 문제의식
기존 생성 모델은 자연어 prompt에서 사실적인 이미지를 잘 만들지만, 전문 디자이너가 필요로 하는 것은 레이어와 벡터가 살아 있는 편집 가능한 산출물이다. 에이전트가 도구를 직접 조작해 이런 구조물을 만들도록 바꾸면, 디자인은 수십 단계의 상호의존적인 행동을 거치는 긴 순차 결정 문제가 된다. 그런데 trajectory가 길수록 마지막 결과 점수만으로는 어느 중간 결정이 성공이나 실패를 일으켰는지 거의 알 수 없다. 예를 들어 초반의 자산 선택은 좋았지만 후반의 텍스트 정렬에서 실패했다면, 전체 점수만 보고 초반 결정까지 나쁘다고 오인하기 쉽다.

더 근본적인 문제는 디자인에 programmatic oracle이 없다는 것이다. 코드는 실행 테스트로 정답을 확인할 수 있고, 많은 게임 환경은 reward를 계산해 주지만, 디자인 brief는 "로고를 넣어라" 같은 확인 가능한 요구와 "여백의 긴장감을 살려라" 같은 주관적 기준을 섞어 낸다. 사람이 직접 라벨을 만들면 비용이 크고, 결과 기반 강화학습은 long-horizon credit assignment와 불완전한 proxy reward를 동시에 처리해야 한다. 게다가 상업용 기반 모델은 외부에 호스팅되어 weight를 업데이트하기 어려운 경우가 많다.

자동 judge가 널리 쓰이지만, 그 자체가 또 다른 문제다. LLM judge는 position bias와 절대 점수 drift를 가지기 때문에, 평균 점수가 조금 올랐다는 이유만으로 업데이트를 승인하면 judge의 기분 변화나 우연한 solver noise를 진짜 개선으로 착각할 수 있다. 한 요청을 고치는 변경이 다른 요청을 망가뜨릴 수도 있는데, 이를 막을 보수적 배포 장치가 없으면 프로덕션에서는 회귀의 비용이 훨씬 크다. 이 논문은 바로 이 지점, 즉 noisy하고 검증 불가능한 피드백 아래에서 외부 memory를 안전하게 진화시키는 문제를 다룬다.

## 핵심 아이디어
이 논문의 본질은 "모델을 학습시키지 말고, 모델이 꺼내 보는 절차 memory를 학습시켜라"는 것이다. 모델 weight는 그대로 두고, 프로덕션 트래픽에서 반복되는 실패와 성공을 자연어 skill로 압축해 외부에 쌓는다. skill은 단일 도구 호출보다는 구체적이고 전체 trajectory보다는 일반적이어서, 한 번 배운 절차를 다른 디자인 요청으로 전이할 수 있다. 이렇게 하면 hosted model이라도 weight update 없이 지속 적응이 가능하다.

여기에 두 가지 상보적 동작을 결합한다. widening은 기존 skill로는 덮이지 않는 반복 하위 작업을 찾아 새 skill을 만든다. deepening은 기존 skill이 실패한 기록과 성공한 기록을 대조해 그 skill만 수리한다. 새 skill만 계속 추가하면 coverage는 넓어지지만 검증이 부족해 주변 요청에서 잘못 발동할 수 있고, 기존 skill만 고치면 새 작업을 못 배운다. 그래서 coverage와 reliability를 함께 올리는 것이 핵심이다.

그리고 모든 제안은 gate를 통과해야 한다. 제안을 만드는 Reflector는 permissive하게 두고, 배포 여부는 replay gate가 보수적으로 결정한다. 이 분리는 "일단 여러 후보를 만들되, 실제로 나가는 것은 엄격히 검증된 것만"이라는 원리다. gate는 절대 점수를 쓰지 않고, 같은 context를 두 팔에서 재실행해 pairwise로 비교하며, 후보가 기존 성공 사례를 깨지 않고 적어도 하나의 실패를 고쳐야만 통과시킨다. 이렇게 하면 judge drift와 asset retrieval 같은 confounding을 설계적으로 차단하면서도, 실패만 고치고 성공을 망가뜨리는 업데이트를 걸러낼 수 있다.

## 방법

### 시스템 역할
진화 loop는 네 역할로 나뉜다. Prompter는 실제 사용자 brief와 LLM으로 증강한 변형 brief를 만든다. Solver는 skill bank와 도구를 이용해 brief에서 렌더링된 이미지까지 실행하는 에이전트다. Grader는 Graphic-Eval이라는 멀티모달 judge로, 이미지와 brief를 보고 점수를 매기고 충족되지 않은 요구가 왜 나빴는지 `why-bad` 이유를 남긴다. Reflector는 이 실패 신호를 받아 `SKILL.md`를 고치거나 새 skill을 만든다. 오직 skill 파일만 변하며 모델 weight, 도구, 렌더러, judge는 고정된다.

### skill bank와 retrieval
각 skill은 YAML front matter와 본문을 가진 Markdown 파일이다. front matter에는 retrieval 신호로 쓰이는 `description`, 대상 앱을 나타내는 `app_mode`, 핵심 도구 경로를 담은 `tool_sequence`, 전제 조건인 `prerequisites` 등이 있다. retrieval은 두 단계로 동작한다. 먼저 frozen LLM이 긴 brief를 "double exposure", "background removal" 같은 핵심 작업 keyword로 증류한다. 그 다음 각 skill의 description과 query의 token overlap을 계산해 순위를 매긴다. overlap 점수는 `score(s) = |tokens(q) ∩ tokens(desc(s))| / |tokens(q)|` 이다. 연산 keyword가 몇 개의 skill description token과 겹치는지를 보는 것이다. 전체 skill 본문을 context에 넣지 않고, 에이전트가 필요하다고 판단할 때만 `load_skill(name)` 도구를 호출해 해당 skill의 steps와 tips를 읽는 progressive disclosure를 쓴다.

### rollout scoring과 outcome binning
모든 trajectory는 Graphic-Eval로 평가된다. completeness는 brief를 $3$–$10$개의 scorable requirement로 분해한 뒤 각각을 met, partial, not_met으로 판정해 그 비율을 계산한다. aesthetics는 1–10 점수로 매겨 0–1로 정규화한다. critique는 여덟 차원에서 major/minor 문제를 세는 진단 축이다. 최종 scalar는 $(w_c, w_a) = (0.7, 0.3)$을 써서 다음처럼 계산한다.

```math
s_j = w_c \cdot \text{completeness}_j + w_a \cdot \text{aesthetic}_j
```

완성도가 0.7로 우세한 이유는, 아무리 예뻐도 brief를 무시한 디자인이 높은 점수를 받지 못하게 하기 위해서다. 이 $s_j$가 threshold $\tau = 0.6$을 넘으면 성공, 못 넘으면 실패로 간주한다.

### widening
각 trajectory에서 frozen LLM이 brief와 도구 호출 sequence를 보고 실제 수행된 하위 작업을 추출하고 canonical label로 정규화한다. retrieval이 아무것도 반환하지 않았거나, 검색된 skill이 작업의 다른 부분만 다루면 그 하위 작업은 uncovered로 기록된다. 이 uncovered 하위 작업은 canonical label을 key로 하는 coverage pool에 쌓인다. 같은 label이 $k_{\min}=3$번 이상 나타나면, frozen LLM이 그 사례들을 증류해 후보 skill을 만든다. 후보는 replay gate에서 no-skill baseline을 상대로 검증을 통과해야만 bank에 들어간다. 거절되면 후보는 버려지지만 그 발생 기록은 pool에 남아 다음 라운드에서 더 많은 증거가 쌓이면 다시 시도할 수 있다.

### deepening
각 trajectory는 어떤 skill을 검색해 썼는지 기록한다. trajectory가 성공 threshold 미만이면 그 trajectory가 검색한 모든 skill에 실패 하나가 더해진다. failure-count가 기본값 $m=2$ 이상인 skill이 수리 대상으로 선택된다. Reflector는 brief, 요구별 결과와 `why-bad`, 현재 `SKILL.md`, 그리고 같은 skill이 유사 작업에서 성공했던 호출 사례들을 받는다. 성공 사례에는 도구 호출 sequence, 중간 결과, 실제로 효과가 있었던 thinking token이 포함된다. 이 성공 $\leftrightarrow$ 실패 대조를 통해 Reflector는 어떤 부분을 바꿀지 특정한 targeted edit을 만든다. 반복된 targeted rewrite가 gate를 통과하지 못하면 skill 전체를 다시 쓰는 major rewrite로 escalate한다. 거절된 rewrite는 선택적으로 exploration cycle을 돌려 실패 prompt를 skill 유무로 다시 탐색하고, 어느 쪽이 성공했는지에 따라 update, delete, keep을 결정한다. keep으로 가면 고칠 수 없는 기록을 widening의 coverage pool로 보낸다.

### replay gate
replay gate는 widening과 deepening이 만든 모든 변화에 공통으로 적용된다. rewrite의 경우 replay prompt는 그 skill을 검색한 trajectory에서 성공 2개, 실패 2개를 층화 추출한다. 실패 사례는 후보가 원래 문제를 고쳤는지 검사하고, 성공 사례는 기존에 잘되던 것을 유지하는지 검사한다. mint의 경우 trigger cluster의 trajectory에서 뽑아 candidate를 no-skill agent와 비교한다. 각 prompt마다 자산 검색 결과나 상류 상태가 다른 여러 context를 만들고, 그 context를 고정한 채 두 팔을 같은 batch에서 새로 실행한다. 이미지 쌍은 순서를 바꿔가며 pairwise judge에게 "어느 쪽이 brief를 더 잘 만족하는가"를 묻는다. judge jitter를 흡수하기 위해 win rate $r$에 tie band $\delta$를 두어, $r > 0.5 + \delta$면 improvement, $r < 0.5 - \delta$면 regression으로 본다. 최종 승인 조건은 다음과 같다.

```math
(\nexists \text{ prompt lost}) \wedge (\exists \text{ prompt won})
```

즉 후보가 replay prompt 중에서 하나라도 진 게 없어야 하고, 동시에 적어도 하나에서는 이겨야 통과한다. 모든 곳에서 비기기만 해도 version bump를 할 가치가 없으므로 거절된다. 이 규칙은 한 사례에서의 큰 이득으로 다른 사례의 손실을 덮는 것을 허용하지 않는다.

### cold start
완전히 빈 skill bank는 아무것도 검색하지 못한다. 그래서 프로덕션 도움말 문서에서 초기 76개 skill을 만든다. intent clustering, runtime tokenizer를 그대로 사용한 page assignment, skill generation, tool 이름 검증과 구조 검사라는 네 단계를 거친다. 이렇게 문서에서 뽑은 초기 skill은 common intent에 대한 recall 바닥을 제공하고, 이후 사용자 트래픽이 들어오면 위의 widening과 deepening이 그 skill들을 진화시킨다.

## 왜 성립하는가
이 논문은 수학적 증명보다는 설계된 비교 구조와 실험적 관찰로 주장을 뒷받침한다. gate가 왜 효과적인지부터 보면, 핵심은 세 가지 confounding을 동시에 제거한다는 점이다. 첫째, judge drift는 절대 점수를 아예 쓰지 않고 같은 batch에서 두 산출물을 pairwise로 비교함으로써 제거된다. 같은 batch라면 judge의 기분 변화가 두 팔에 비슷하게 작용해 차이에서 상쇄된다. 둘째, asset retrieval이나 상류 상태 차이는 prompt별 context를 고정하고 두 팔에서 동일하게 replay함으로써 차단된다. 셋째, position bias는 제시 순서를 바꾸어 판정하게 함으로써 완화한다. 따라서 남는 차이는 "skill 조건"뿐이다.

승인 조건도 보수적 회귀 방지에 맞게 설계되었다. replay에 성공 사례와 실패 사례를 함께 넣기 때문에, 후보가 실패만 고치고 기존 성공을 깨뜨리면 gate를 통과할 수 없다. prompt 단위로 패배가 하나라도 있으면 안 된다는 조건은 안전 정책 개선의 "기존 baseline 대비 회귀 금지" 원칙을 자연어 skill에 적용한 것이다. 과반수 context 요건은 여러 context 중 하나에서 우연히 크게 이겨서 평균이 올라가는 상황을 막는다. 이렇게 해서 제안 생성은 permissive하게 두고도 배포는 strict하게 유지할 수 있다.

empirical evidence도 이 설계를 뒷받침한다. ablation에서 documentation-derived cold start는 Base 대비 completeness가 69.08에서 68.62로 오히려 약간 낮고 win rate도 46.4%에 그쳤다. +rewrite만 한 경우는 69.02, +new skills만 한 경우는 69.79로 각각 win rate 48.6%, 49.4%에 머물렀다. 그러나 두 메커니즘을 함께 쓴 Evolve는 74.04 completeness와 58.5% win rate를 달성했고 $p=0.025$로 유의미했다. 이 superadditive 상승은 새로 만든 skill이 retrieval description을 정비해야 제대로 표면에 올라오고, 고칠 수 없는 실패가 다시 widening의 coverage pool로 흘러 들어가는 loop coupling 때문으로 해석된다.

진화 동역학에서도 이 상보성이 보인다. R3와 R4에서 minting이 많아져 bank가 77개에서 124개로 늘었지만, R4는 threshold $\tau \ge 0.3$에서 Base 94% 대비 90%로 하단이 오히려 나빠졌다. 반면 R4도 $\tau \ge 0.9$에서는 Base 43% 대비 50%로 상단은 좋았다. R4에는 아직 한 번도 rewrite되지 않은 v1 skill이 많았기 때문이다. R5에서 minting을 4개로 줄이고 rewrite를 21개 커밋하자 모든 threshold에서 가장 강한 라운드가 되었다. 이는 widening이 coverage를 넓히고, deepening이 그 coverage를 reliability로 바꾸는 순환을 보여 준다.

## 구체적 예시
내부 벤치마크의 evolution 궤적을 숫자로 따라가 보자. 이 벤치마크는 evolution brief와 겹치지 않는 200개의 고정된 human-authored brief로, 매 라운드 후 같은 200개를 다시 평가한다. completeness가 $\tau \ge 0.9$인 비율을 보면 Base는 43%다. 200개로 환산하면 약 86개가 아주 높은 completeness를 달성했다. R5에서는 56%로 올라 112개가 된다. 즉 Base 대비 13 percentage point 상승이며, 5(a)가 보여 주는 가장 큰 survival gap이다. $\tau \ge 0.5$에서는 Base 86%에서 R5 93%로 올라 172개에서 186개가 된다. 완벽한 $\tau = 1.0$ 비율은 Base 24%에서 R5 32%로 올라 48개에서 64개가 된다.

이 과정이 단조 증가는 아니었다. R4는 $\tau \ge 0.3$에서 Base의 94%보다 낮은 90%를 기록했다. 200개 기준으로 188개에서 180개로 줄어든 것이다. 그런데 같은 R4도 $\tau \ge 0.9$에서는 Base 43% 대비 50%로 여전히 +7 percentage point의 이득을 유지했다. 즉 품질이 아주 높은 꼬리는 좋아졌지만 낮은 구간이 무너진 것이다. 원인은 R3에서 26개, R4에서 13개의 skill을 minting해 R4가 한 번도 수리되지 않은 v1 skill을 가장 많이 보유했기 때문이다. 이런 v1 skill은 처음 만들어진 gap cluster에서만 검증되었으므로 그 주변 밖의 요청에서는 잘못 발동할 수 있다.

R5는 구성을 뒤집어 rewrite 21개와 mint 4개를 커밋했고, 모든 threshold에서 Base와 이전 라운드를 지배했다. gate의 전체 활동을 보면 다섯 라운드 동안 rewrite 제안 231개 중 100개를 거절해 131개를 커밋했고, mint 후보 136개 중 67개를 거절해 69개를 커밋했다. 순증가가 63개인 이유는 deepening이 중복되거나 대체된 skill 6개를 버렸기 때문이다. R1은 수리가 대부분이었는데 rewrite 59건 중 39건, mint 10건 중 4건이 통과했다. minting은 R2–R3에서 각각 46건 중 22건, 40건 중 26건이 통과하며 절정에 달했고, coverage가 포화되면서 다시 줄었다.

정성적 결과에서도 같은 절차가 전이되는 모습이 보인다. Figure 7의 Column 1은 Adobe 로고 안에 꽃을 double exposure하는 요청인데, Base는 블렌딩을 시도하지만 꽃이 흐릿하게 남고, Evolve는 대상을 추출하고 글리프를 마스크로 만든 뒤 꽃 이미지를 그 안에 또렷하게 블렌딩한다. Column 4는 축구 선수의 실루엣을 경기장과 합성하는 요청인데 Base는 인물 추출을 아예 시작하지 못하고, Evolve는 같은 double exposure 절차를 글자 형태에서 사람 형태로 전이해 적용한다. 둘 다 단순히 자산 선택만 잘한 것이 아니라, 절차가 없어서 실패하거나 절차를 잘못 실행해서 실패한 것을 절차 memory가 복구한 사례다.

### 일반 text-to-image 벤치마크
Table 1은 네 개의 일반 생성 벤치마크에서 Base와 Evolve를 비교한다. Claude-Opus-4.6은 평균 품질이 67.04에서 70.87로 +3.83 올랐고 평균 success rate는 92.7로 동일했다. 세부를 보면 GenEval2 quality가 61.24에서 57.92로 -3.32 하락했지만 success는 96.7%에서 98.0%로 +1.3 올랐다. DPG-Bench에서는 quality가 77.58에서 86.54로 +8.96 올랐지만 success는 89.3%에서 84.7%로 -4.6 내려갔다. 매우 강한 backbone에서는 이미 baseline success가 높아 품질 변화가 혼재한다.

Claude-Sonnet-4에서 효과가 가장 두드러진다. GenEval2 success는 72.7%에서 99.3%로 +26.6 percentage point 올랐고, quality는 34.26에서 46.25로 +11.99 올랐다. DPG-Bench success는 82.7%에서 100%로 +17.3 올랐고, quality는 68.28에서 83.79로 +15.51 올랐다. 평균 quality는 +7.70, 평균 success는 +10.5 상승했다. 특히 Sonnet은 skill bank가 없을 때 긴 디자인 실행에서 중간에 실패하거나 잘못된 도구를 쓰는 경우가 많았는데, 검증된 절차가 이를 크게 줄였다고 해석할 수 있다.

Qwen3.6-27B는 평균 quality가 68.67에서 78.34로 +9.67 올랐지만, 평균 success rate는 47.3%에서 49.5%로 +2.2에 그쳤다. quality가 높게 보이는 것은 quality가 성공한 산출물에 대해서만 평가되기 때문이다. 즉 쉬운 prompt만 성공해 그 쉬운 사례의 품질이 평균을 끌어올린 효과가 섞여 있다. DPG-Bench에서는 success가 44.0%에서 28.7%로 -15.3 하락했는데, 저자는 이를 로컬 GPU 서빙의 timeout과 connection drop 때문으로 본다.

### 전문 그래픽 디자인 벤치마크
Table 2는 GPT-5.4 judge가 blind, two-order 방식으로 매긴 Evolve vs. Base pairwise win rate다. 50%가 동률 baseline일 때 Claude-Opus-4.6은 OpenCOLE 64.0%, GraphicBench 63.5%, CreatiDesign 71.7%, BannerRequest400 71.3%를 기록해 전체 67.6%의 win rate를 얻었다. Claude-Sonnet-4는 전체 61.8%였고, BannerRequest400에서는 56.2%로 가장 낮았다. Qwen3.6-27B는 전체 62.8%였지만 GraphicBench에서 49.0%로 50%보다 낮았다. 이는 복잡한 다단계 디자인 제약에서 skill bank가 표준 zero-shot 실행보다 우위를 보인다는 증거지만, backbone에 따라 편차가 있다.

완료 신뢰성 측면에서는 Table 4가 더 분명하다. Claude-Opus-4.6 Base의 평균 성공률은 98.3%인데 Evolve는 99.2%다. Claude-Sonnet-4는 91.0%에서 99.8%로 +8.8 올랐고, 특히 BannerRequest400에서 Base 74.7%가 Evolve에서 100%가 되어 +25.3 percentage point 상승했다. 복잡한 레이아웃과 타이포그래피 제약이 있는 벤치마크에서 skill bank가 catastrophic tool-use failure를 막은 셈이다. Qwen3.6-27B는 local deployment 안정성의 영향을 받아 Base 평균 65.5%에서 Evolve 63.2%로 혼재했다.

### 비용과 ablation
latency는 대부분 backbone에서 평균 3.4%–6.2%만 늘었고, Sonnet의 DPG-Bench에서는 113초에서 82초로 오히려 줄었다. ablation에서 skill retrieval은 Base보다 prompt token을 약 28% 늘리지만, 최종 Evolve는 cold start보다 prompt/output token이 더 적었다. Cold start가 445.2k prompt token, 5298 output token을 쓴 반면 Evolve는 436.6k prompt token, 5167 output token을 썼다. skill이 실행을 더 직접적으로 만들어 교정 재시도가 줄었기 때문이다.

Ablation Table 3은 메커니즘 분리 실험을 보여 준다. Base는 skill 없이 completeness 69.08이다. 문서에서 뽑은 cold start 76개 skill은 completeness 68.62, win rate 46.4%로 Base를 이기지 못했다. rewrite만 적용한 경우 completeness 69.02, win rate 48.6%였다. 새 skill만 전부 추가한 경우 139개 bank에서 completeness 69.79, win rate 49.4%였다. 그러나 두 메커니즘을 결합한 Evolve는 같은 139개 bank로 completeness 74.04, win rate 58.5%를 기록했고, cold start 대비 +5.42, Base 대비 $p=0.025$의 유의미한 승리를 얻었다. aesthetics는 65.92에서 66.53으로 소폭 상승에 그쳤고, major critique는 3.93에서 3.57로 약간 줄었다.

## 한계
저자가 명시한 가장 큰 한계는 자연어 skill이 절차를 설명할 수는 있어도 모델이 강한 기본 전략을 가질 때 retrieval만으로는 그 전략을 강제하지 못한다는 점이다. 예를 들어 눈 내리는 효과를 만들 때 모델은 이미 알고 있는 particle generator 방식을 계속 쓰려 하고, 사용자가 원하는 noise 기반 레시피를 skill에 넣어도 그냥 무시할 수 있다. 이 문제를 해결하려면 사용자 선호를 반영한 retrieval과 도구 자체를 제한하는 강제 장치가 추가로 필요하다.

fine geometric operation도 한계다. 프레임 안에 재귀적으로 사진을 넣는 Droste 효과의 경우, 에이전트와 자동 verifier 모두 픽셀 수준의 경계 정렬을 정확히 인식하지 못한다. verifier를 VLM 판정에서 수치 측정으로 바꾸면 오정렬을 더 잘 잡아내지만, 에이전트가 여전히 pixel-exact 배치를 실행하지 못한다. 결국 정밀도가 중요한 디테일은 여전히 사람이 개입해야 한다.

긴 절차는 단계가 쌓일수록 fidelity가 새는 문제도 있다. 인간이 만든 복잡한 타일 패턴을 skill로 옮기면 annotation, distillation, use의 각 단계에서 정보가 조금씩 손실되고, 그 손실이 곱해져 결과가 목표보다 흐려진다. 논문은 skill distillation이 짧고 자기완결적인 절차에는 강하지만, 아주 긴 다단계 구성에는 자연어 절차만으로는 부족하다고 인정한다.

replay gate도 local guarantee만 제공한다. replay set에서 관찰된 회귀를 거절할 수는 있지만, 전체 사용자 트래픽 분포에서 단조 개선을 보장하지는 않는다. gate가 본 prompt 밖의 요청에서는 여전히 새 skill이 잘못 발동할 수 있다. 또한 Qwen3.6-27B의 로컬 서빙 불안정성이 success rate를 혼탁하게 만들어, 그 backbone에 대한 결론은 조심스럽게 읽어야 한다. 마지막으로 자동 judge는 proxy이므로, 그 judge가 부과하는 능력 천장이나 reward hacking 가능성 자체는 이 구조에서도 완전히 사라지지 않는다.

## 왜 중요한가
이 논문은 검증 가능한 reward가 없는 실제 프로덕션 환경에서도 에이전트를 지속적으로 적응시킬 수 있는 실용적 경로를 보여 준다. weight update와 human label 없이, 사용자 트래픽에서 얻은 경험만으로 세 가지 서로 다른 backbone의 성능을 끌어올렸다는 점이 중요하다. 특히 외부에 호스팅되어 학습시킬 수 없는 상업용 모델을 다루는 실무자에게, 모델 바깥의 자연어 memory를 학습 대상으로 삼는 방식은 큰 운영적 이점을 준다.

skill bank는 versioning과 inspection이 가능한 해석 가능한 산출물이다. 어떤 절차가 배포되었고, 어떤 제안이 거절되었는지 기록이 남기 때문에 문제가 생기면 롤백하거나 사람이 검토할 수 있다. 이는 불투명한 weight update보다 프로덕션 거버넌스에 훨씬 유리하다. 또한 같은 skill bank가 여러 backbone에서 재사용될 수 있어, 모델 교체 시에도 축적된 절차 지식이 사라지지 않는다는 장점도 실무적으로 크다.

보수적 replay gate는 노이즈 있는 judge 아래에서도 배포 안전성을 일부 확보한다는 점에서 의미가 크다. "평균 점수가 올랐다"로 승인하는 대신, replay에 성공 사례와 실패 사례를 함께 넣고 회귀가 없을 때만 내보내는 방식은 프로덕션에서 흔히 겪는 "한 고객의 요청을 고쳤더니 다른 고객이 망가진다"는 문제를 완화한다. 이 아이디어는 디자인뿐 아니라 judge가 불완전한 다른 open-ended 에이전트 시스템에도 폭넓게 적용될 수 있다.

이 논문은 또한 widening과 deepening이 따로가 아니라 함께일 때 superadditive하게 작용한다는 실험적 사실을 제시한다. 실무적으로는 단순히 skill을 많이 쌓는 것이 능사가 아니고, 새로 추가한 skill을 실패 이력으로 반복 수리하는 loop가 있어야 coverage가 reliability로 전환된다는 점을 시사한다. 마지막으로 개인화 축의 한계를 정직하게 드러냄으로써, 앞으로 preference-aware retrieval, deterministic primitive, plan-level orchestration, 모델 학습과의 결합 같은 후속 연구가 필요한 지점을 분명히 해 준다.

## 원문 초록

> Professional graphic design is a long-horizon agentic task in which structured, editable artifacts emerge from many interdependent actions, yet outcomes admit no reliable programmatic oracle. We introduce a continual adaptation framework in which a frozen frontier model operates professional design software through more than 230 tools, while an external procedural memory of natural-language skills accumulates and refines reusable design procedures from experience. The memory widens by acquiring procedures for recurring uncovered subtasks and deepens by revising existing procedures against their own successful and failed executions, while a matched replay gate admits only changes that repair failures without regressing observed successes. Five rounds over 1,406 real user briefs and 1,869 automatically graded trajectories, with no weight updates and no human labels, grow the bank from 76 documentation-derived skills to 139 and raise GenEval2 execution success on Claude-Sonnet-4 from 72.7% to 99.3% (+11.99 points in generation quality), with 61.8% and 67.6% win rates against the no-skill agent across four specialized design benchmarks on Claude-Sonnet-4 and Claude-Opus-4.6. We further show the two mechanisms are effective in combination: on 200 held-out briefs from user-traffic benchmark, widening or deepening alone reaches a 49.4% / 48.6% win rate over the no-skill agent, while their combination reaches 58.5% (p = 0.025). Procedural memory offers a practical route to continual adaptation of agents under noisy, unverifiable feedback.
