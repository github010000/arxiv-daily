## 한 줄 요약

Language model의 data attribution이 실패하는 원인을 통제된 합성 benchmark로 분리 진단한 결과, 증거가 문서 안 극소수 token에 몰려 있는데 표준 방법이 문서 전체를 평균 내며 그 증거를 희석시키고 있었다는 것을 밝히고, 새로운 estimator 없이 gradient를 계산하는 loss를 negative log-odds로 바꾸고 상위 몇 개 token만 집계하는 것만으로 ground-truth recall을 35~72 percentage point 끌어올린 논문.

## 핵심 개념 풀이

### 1) Data attribution과 counterfactual

Data attribution은 학습 데이터의 각 예시가 모델의 특정 출력에 얼마나 책임이 있는지를 점수로 매기는 작업이다. 이상적인 attribution은 counterfactual을 예측한다. 즉 "학습 corpus에서 문서 d를 빼고 다시 학습시키면 모델은 질문 q에 대한 답 y를 더 이상 말하지 못할 것"이라는 진술이다. 여기서 counterfactual이라는 말이 핵심인데, 이는 실제로 수행하지 않은 실험(재학습)에 대한 주장이기 때문이다. 검증의 표준은 문서를 하나씩 지우고 매번 모델을 다시 학습시키는 leave-one-out이지만, 40억 parameter 모델에 수천 개 문서라면 비용이 폭발한다. 그래서 실무에서는 gradient 같은 대리 신호로 근사를 하고, 검증은 "정답 문서를 상위에 올렸는가"라는 retrieval 지표로 대신한다. 이 논문이 진단하는 대상이 바로 그 대리 신호다.

### 2) Influence function: "이 문서를 조금 더 학습시키면 query loss가 얼마나 줄어드나"

Influence function은 문서 d를 조금 더 학습시켰을 때(upweighting) query q의 loss가 얼마나 변하는지를 1차 근사로 계산한다. 식은 τ_IF(d,q) = ∇θL(q)ᵀ H⁻¹ ∇θL(d)인데, ∇θL(q)는 query loss를 줄이는 방향, ∇θL(d)는 문서 loss를 줄이는 방향, H⁻¹은 두 방향 사이의 curvature 보정이다. 왜 Hessian이 필요한가 하면, 두 gradient의 단순 내적은 "두 방향이 비슷하냐"만 볼 뿐이라서, 학습이 이미 끝난 모델에서는 대부분의 문서가 비슷한 방향을 가리켜 변별력이 사라지기 때문이다. H⁻¹은 "그 방향으로 밀었을 때 parameter가 실제로 얼마나 움직이는가"를 환산하는 자 역할을 한다. 실제로는 H를 정확히 구할 수 없어서 EK-FAC, LoGra, TRAK 같은 방법이 layer별 Fisher나 Gauss-Newton 근사를 쓴다. 이 논문은 그 근사들을 새로 만들지 않고, 근사에 들어가는 입력 신호만 바꾼다.

### 3) Token 분해와 dilution: 문서 점수는 사실 token 점수의 합이다

Linear layer에서 위치 t의 weight gradient는 출력 쪽 gradient와 입력 activation의 outer product로 주어지고, 문서 전체의 layer gradient는 위치별 기여의 합이다. 즉 문서 점수는 태생적으로 token 점수의 합으로 쪼개진다. 그런데 표준 관행은 이 합을 문서 길이 T로 나눠 평균한다. 만약 문서 안에서 실제로 중요한 증거가 k개 token에만 있다면, 평균은 신호를 k/T로 줄인다. 240 token짜리 문서에서 10개라면 24분의 1이다. 비유하자면 240명이 한 마디씩 하는 회의록에서 결정적 발언 10개를 찾는데, 전체를 평균 내면 조용한 사람들의 잡음이 그 10개를 덮어버리는 것과 같다. 이 논문이 "dilution"이라 부르는 현상이 정확히 이것이고, 뒤에서 보겠지만 실제 측정값이 이 산술과 놀랍도록 잘 맞는다.

### 4) Cross-entropy와 negative log-odds: (1-p)라는 조용한 감쇠 인자

Cross-entropy loss는 -log p_y이고, negative log-odds loss는 -log[p_y/(1-p_y)]다. odds(승산)는 "정답일 확률 대 정답이 아닐 확률의 비율"이고, 여기에 로그를 취하면 정답 class의 logit과 정확히 같아진다. 이름 그대로 log-odds는 확률 자체가 아니라 확률의 비율, 즉 "정답 쪽으로 얼마나 여유가 있는가"를 본다. 두 loss의 gradient는 방향이 같고 크기만 다르다. ∇L_CE = (1-p_y)·∇L_nlo가 성립한다. 즉 cross-entropy는 정답을 99% 확률로 맞히는 token의 gradient를 100분의 1로 깎는다. 그런데 우리가 추적하려는 사실을 담은 token이 바로 그렇게 자신 있게 맞히는 token이다. 결과적으로 "이 문서는 영향이 없다"는 잘못된 판정이 나온다. NLO는 이 감쇠 인자를 없애서, 확신이 높든 낮든 token의 기여를 온전히 남긴다.

### 5) Recall@N과 AUC, 그리고 decoy AUC

Recall@N은 한 query의 정답 문서 N개 중 몇 개가 상위 N개 안에 들었는지의 비율이다. 상위 개수를 N으로 맞추는 이유는 실제 사용례가 "상위 몇 개를 지우고 재학습"이기 때문이다. 무작위 ranking의 기대값은 N/|D|이므로, 후보가 5,000개이고 N=50이면 chance는 0.01이다. AUC는 정답 문서 하나와 비정답 문서 하나를 무작위로 뽑았을 때 정답이 더 높은 순위일 확률로, 0.5가 chance, 1.0이 완전 분리다. 두 지표가 서로 다른 말을 할 수 있다는 점이 중요하다. Recall이 0.36인데 AUC가 0.80이면 순위는 대체로 잘 매기지만 최상위에 못 올린다는 뜻이다. decoy AUC는 정답 문서를 그 query를 흉내 낸 decoy와만 비교하는 지표로, 0.5보다 낮으면 decoy를 정답보다 선호한다는 뜻이다.

### 6) 합성 사실로 ground truth 만들기

진짜 pretraining corpus에서는 "Marie Curie가 Warsaw에서 태어났다"는 사실이 수십 개 문서에 다양한 표현으로 등장하고, 모델은 pretraining 단계에서 이미 그걸 알고 있을 수 있다. 그래서 모델이 답을 맞혀도 그것이 우리가 넣은 문서 때문인지 알 수 없다. 이 논문은 pretraining에 없는 가상의 사실만 fine-tuning해서, 그 사실의 유일한 인과적 출처가 우리 문서임을 보장한다. Function Bindings에서는 vocabulary에 새 token까지 추가해, 그 token에 대한 지식이 100% 우리 문서에서만 올 수 있게 만든다. Test query는 학습 문서에 없는 표현과 입력을 쓴다. 그래야 모델이 문자열을 암기한 것이 아니라 규칙을 적용했음이 보장되고, 단순한 lexical matching만으로는 답할 수 없다.

## 문제의식

기존 평가의 가장 큰 문제는 여러 dataset 속성을 동시에 바꾼다는 것이다. FTRACE-TREX, 그리고 여러 fact-tracing benchmark가 각자 다른 training corpus, 다른 query 구성 방식, 다른 task를 쓰기 때문에 결론이 서로 충돌한다. 어떤 benchmark에서는 BM25 같은 순수 lexical 검색이 influence function을 이기고, 다른 benchmark에서는 진다. 이 충돌은 방법론의 우열에 대한 것이 아니라 평가 설계의 차이에서 오는데, 고정된 dataset 하나만 보면 어느 쪽이 원인인지 분리할 방법이 없다.

구체적으로 어떤 곤란한 일이 생기는가. 한 실무자가 사내 문서 corpus에 TRAK을 돌렸는데 정답 문서를 거의 못 찾았다고 하자. 원인 후보는 최소 셋이다. 같은 사실이 여러 문서에 반복되어서일 수도 있고(중복), 질문과 표면적으로 닮았지만 답은 없는 문서가 많아서일 수도 있고(lexical distractor), 다뤄야 할 사실의 수가 많아서일 수도 있다. 기존 benchmark는 이 축들을 한꺼번에 바꿔놓았기 때문에 "당신의 corpus는 어떤 성질 때문에 어려운가"라는 질문에 답을 주지 못한다. 진단 신호가 없으니 알고리즘 연구도 정확도가 아니라 속도와 확장성 쪽으로만 흘러갔다. 그리고 counterfactual을 직접 검증하는 길은 막혀 있다. 4B 모델을 수천 문서에 대해 하나씩 지워가며 재학습시키는 것은 현실적으로 불가능하다.

## 핵심 아이디어

제안은 두 단계다. 첫째, 평가를 통제 실험으로 바꾼다. Dataset을 configuration c = (task T, fact set F, 문서 중복도 N, distractor 포함 여부)로 parameter화하고, 한 번에 한 축만 바꾼다. 합성 사실만 쓰기 때문에 ground truth가 모호하지 않고, 따라서 "어떤 조건에서 어떤 방법이 왜 무너지는가"를 분리해서 말할 수 있다.

둘째, 그 위에서 병리를 진단한다. Token 단위로 들여다보니 실제 증거가 극도로 국소적(localized)이었다. 표준 방법은 문서 전체를 평균 내며 그 증거를 잡음에 희석시키고 있었다. 그래서 estimator 자체는 그대로 두고 두 가지 설계 선택만 바꾼다. Gradient를 만드는 loss를 cross-entropy에서 negative log-odds로 바꾸고, 문서 점수를 전체 token 평균이 아니라 상위 k개 token의 평균으로 집계한다.

왜 이 아이디어가 문제를 푸는가. 문제의 원인이 "추정기가 나쁘다"가 아니라 "추정기에 들어가는 신호가 오염되어 있다"였기 때문이다. 신호 대 잡음비 관점에서 보면 두 수정은 서로 직교하며 곱해진다. 문서 평균은 신호를 k/T로 깎지만 top-k 집계는 k개를 그대로 남긴다. 그리고 cross-entropy는 신호가 있는 token의 크기를 (1-p)로 깎지만 NLO는 깎지 않는다. 실제로 Figure 4의 네 숫자가 이 곱셈 구조를 그대로 보여준다. 전체 평균 + cross-entropy가 0.01, top-k만 적용하면 0.30, loss만 바꾸면 0.35, 둘 다 적용하면 1.00이다. 각각의 효과가 따로 나타나고, 합치면 곱해진다. 게다가 이 수정은 Hessian 근사나 projection 같은 비싼 부분을 건드리지 않으므로 계산 비용이 거의 늘지 않는다.

## 방법

**1단계, 데이터 생성.** Configuration은 c = (T, F, N, 1_dist)다. T는 task, F는 사실 집합, N은 사실 하나당 문서 수, 1_dist는 distractor 포함 여부를 나타내는 0/1 지시자다. 사실 f를 지지하는 문서 부분집합을 D_f라 하고, 문서 하나하나가 f를 서로 다른 형식으로 서술한다. 각 configuration마다 seed s별로 모델을 하나씩 만든다: θ_{c,s} = Finetune(θ_0, D_c; s). Grid는 |F| ∈ {25, 50, 100}, N ∈ {1, 3, 5, 10, 20, 30, 40, 50}, seed 세 개(1001~1003)이고, 주 실험은 |F| = 50에 N ∈ {1, 5, 10, 30, 50}을 쓴다. Corpus는 중첩되게 만들어서 N을 늘리면 기존 문서는 그대로 두고 새 문서만 추가된다. 따라서 비교가 "데이터 양" 하나만 바뀌도록 통제된다.

**2단계, 두 개의 task.** Task I Function Bindings는 새 function token <f_i>가 항상 정답 token <v_i>를 반환하는 상수 함수를 가르친다. Vocabulary에 function token 300개와 answer token 101개를 추가하고, 새 embedding row는 기존 row의 중앙값 norm에 맞춰 초기화한다. 문서는 109~170 단어이고 7개 genre(기술 문서, 실무 가이드, unit test, tutorial, 수학 서술, REPL 세션, cheat sheet)를 돌아가며 쓴다. 학습 문서에는 query template인 "The output of ... is"라는 표현을 금지하고, 입력 범위 [1, 100]은 query용으로 예약한다. Lexical distractor는 정확히 한 줄이다: "The output of <g_i>(x) is <v_i>". Query template을 그대로 복사하고, 정답 token까지 같지만, 다른 함수 <g_i>를 가리킨다. 즉 표면만 보면 정답처럼 보이도록 설계된 함정이다.

Task II Rule Routings는 조합적 논리를 본다. 100개 category 각각에 4개의 boolean 속성이 있고, 그중 하나만이 deciding 속성이다. 16개 조합 중 8개만 학습 문서에 등장하고, 나머지 8개는 held-out이다. 규칙 문장은 LLM이 28개 paraphrase로 생성하고, 별도의 checker 호출이 각 paraphrase를 읽고 "deciding 속성을 가진 item이 어디로 가는가"를 맞히는지 검증해서 틀리면 버린다. Held-out noun과 유의어는 금지어 목록으로 차단한다.

**3단계, Fine-tuning.** Qwen3.5-4B에 LoRA(rank 64, α 128, 모든 linear layer)를 붙인다. Function Bindings는 새 token 때문에 embedding과 unembedding도 학습하는데, 원래 vocabulary 248,077개 row는 gradient를 0으로 막아 기존 지식을 건드리지 않는다. AdamW, learning rate 4×10⁻⁴(Function Bindings) 또는 3×10⁻⁴(Rule Routings), batch 10 문서, 약 1,000 optimizer step, bf16. Seed는 데이터 순서만 바꾸고 corpus와 LoRA 초기화는 고정한다.

**4단계, Attribution 점수 계산.** 기본 형태는 influence function이다. τ_IF(d,q) = ∇θL(q)ᵀ H⁻¹ ∇θL(d) ≈ Σ_ℓ ∇θ_ℓL(q)ᵀ H_ℓ⁻¹ ∇θ_ℓL(d). 여기서 ∇θL(q)는 정답 token y에 대한 query loss의 gradient, H는 training loss의 Hessian, H_ℓ은 layer ℓ별로 쪼갠 근사다. 이걸 token 단위로 분해하면, layer ℓ의 위치 t에서 weight gradient 기여는 g_{ℓ,t}(d) = vec(∇_{h_{ℓ,t}}L(d)·a_{ℓ,t}ᵀ)이고, 문서 gradient는 ∇θ_ℓL(d) = Σ_t g_{ℓ,t}(d)로 복원된다. 따라서 token별 점수는 τ_t(d,q) = Σ_ℓ ∇θ_ℓL(q)ᵀ H_ℓ⁻¹ g_{ℓ,t}(d)이고, 문서 점수는 τ_IF(d,q) ≈ Σ_t τ_t(d,q)다. 요컨대 "출력 쪽 gradient와 입력 activation의 곱"을 위치마다 계산한 뒤 query gradient와 대조하는 것이 전부다.

**5단계, Loss 교체.** 문서 쪽 loss를 L_nlo = -log[p/(1-p)]로 바꾼다. Query 쪽은 항상 NLO를 쓴다. 이때 curvature 추정치(Hessian/Fisher)는 cross-entropy 기준으로 고정해 둔다. 즉 비용이 큰 부분은 재계산하지 않고 gradient만 교체한다.

**6단계, Top-k 집계.** 문서 점수를 전체 token 평균 대신 상위 k개 τ_t의 평균으로 계산한다. 기본값은 k = 10이다. 실험에서는 k를 바꿔가며 성능 곡선을 그리는데, k를 늘리면 full-document 점수로 수렴하면서 성능이 떨어진다.

## 왜 성립하는가

먼저 (1-p) 관계의 유도다. Logit vector를 z라 하면 p_i = softmax(z)_i다. Cross-entropy의 logit 미분은 ∂L_CE/∂z_i = p_i - 1[i = y]이고, NLO의 미분은 정답 좌표에서 -1, 나머지 좌표에서 p_i/(1-p_y)다. 정답 좌표를 보면 p_y - 1 = -(1-p_y)이므로 정확히 (1-p_y)배이고, 경쟁 좌표를 보면 p_i = (1-p_y)·[p_i/(1-p_y)]이므로 역시 (1-p_y)배다. 좌표마다 같은 비율이 곱해지므로 ∇_z L_CE = (1-p_y)∇_z L_nlo이고, 같은 logit Jacobian J_θ = ∂z/∂θ를 양변에 곱하면 parameter gradient에 대해서도 같은 관계가 성립한다. 즉 두 loss의 gradient는 방향이 완전히 같고 크기만 (1-p_y)만큼 다르다.

다음으로 NLO의 gradient가 0으로 사라지지 않는다는 것이다. r_i = p_i/(1-p_y)라 두면 r_i ≥ 0이고 Σ_{i≠y} r_i = 1이므로, ||∇_z L_nlo||² = 1 + Σ r_i²다. Σ r_i²는 Cauchy-Schwarz에 의해 1/(|V|-1) 이상이고, 확률 질량이 한 곳에 몰리면 1 이하다. 따라서 √(1 + 1/(|V|-1)) ≤ ||∇_z L_nlo|| ≤ √2로 위아래가 모두 막힌다. 반면 cross-entropy는 같은 양에 (1-p_y)를 곱한 것이므로 p_y → 1이면 0으로 강제로 사라진다. 이것이 이 논문의 논리적 핵심이다. 추적하려는 사실을 표현하는 token은 학습이 끝나면 확률이 매우 높다. 그래서 정확히 그 token에서 cross-entropy gradient가 0이 되고, "이 문서를 지워도 예측은 안 변한다"는 잘못된 결론이 나온다.

Dilution 쪽은 산술이 더 단순하다. 문서 점수가 (1/T)Σ_t τ_t이고 신호가 k개 token에만 있으며 나머지는 평균 0인 잡음이라면, 문서 점수는 대략 (k/T)·signal + 잡음항이 된다. T ≈ 240, k = 10이면 신호가 24분의 1로 줄어든다. Top-k 집계는 나누는 분모를 T가 아니라 k로 바꾸는 것과 같으므로 이 감쇠가 사라진다. 실제로 distractor 실험에서 이 길이 효과가 정량적으로 드러난다. Distractor는 약 12 token, 사실 문서는 약 239 token이라서, 전체 평균을 쓰면 짧은 decoy가 길이 나눗셈에서 유리해진다. 논문의 부록에서는 같은 조건에서 평균 대신 합(sum)을 쓰면 회복된다는 것도 보여준다.

마지막으로 실증적 근거다. Token 종류별로 상위 10개 위치가 얼마나 농축되는지 세어보면, cross-entropy에서는 정답 token의 농축 비율이 0.2~1.3배로 사실상 chance 수준이다. NLO에서는 5.1~11배로 뛰고, 다른 token 종류는 1.4배를 넘지 않는다. Figure 5의 단일 문서 사례도 같은 이야기다. Cross-entropy는 순위를 1,500개 중 1,499위로 매겼지만, NLO는 12위로 올린다. 다만 저자들이 명시하듯 token gradient는 token 삭제의 정확한 counterfactual이 아니라 "국소화된 gradient 신호"다. Activation이 앞선 context를 담기 때문이다. 따라서 이 논문의 주장은 선형화된 점수 안에서의 신호 대 잡음에 대한 것이지, 정확한 인과 효과에 대한 것이 아니다.

## 구체적 예시

Figure 4의 숫자를 따라가 보자. 설정은 Grad-Dot, Function Bindings에 distractor 포함, |F| = 50, N = 50, seed 1001이다.

먼저 후보 문서 수를 세자. 사실 50개에 각각 50개 문서니까 사실 문서가 2,500개이고, distractor가 사실 문서와 1:1이므로 2,500개다. 그래서 attribution이 순위를 매겨야 하는 후보는 총 5,000개다. 각 사실 문서는 평균 239 token, distractor는 약 12 token이다. Query는 사실당 4개씩 총 200개다.

이제 지표의 기준선을 계산하자. Recall@N은 N = 50에서 측정하므로, 무작위로 50개를 뽑았을 때 정답 50개 중 기대 회수 개수는 50 × (50/5,000) = 0.5개, 즉 비율로 0.01이다. 이것이 chance 수준이다.

첫 번째 값, cross-entropy로 전체 token을 평균한 문서 점수의 recall은 0.01이다. Chance와 정확히 같다. 즉 표준 방법은 이 조건에서 무작위 ranking과 구별되지 않는다. Figure 4의 왼쪽 패널에서 정답 문서(빨강)와 나머지 문서(회색)의 점수 분포가 거의 완전히 겹쳐 있는 것이 이 값의 시각적 대응이다.

두 번째 값, cross-entropy는 그대로 두고 상위 10개 token만 평균하면 0.30이다. 문서당 239 token 중 229개를 버린 셈인데, 그만큼 잡음이 줄어 50개 중 약 15개를 회수한다. 다만 여전히 신호 token의 크기가 (1-p)로 깎여 있으므로 분포는 완전히 갈라지지 않는다.

세 번째 값, loss를 NLO로 바꾸고 전체 token을 평균하면 0.35다. 버리는 token은 없지만 신호 token의 크기가 회복되어 0.30보다 조금 더 나아진다. 이 두 값이 비슷하다는 사실 자체가 흥미롭다. 잡음을 줄이는 것과 신호를 키우는 것이 각각 독립적으로 기여한다는 뜻이기 때문이다.

네 번째 값, NLO에 top-10 집계를 결합하면 1.00이다. 정답 50개를 전부 상위 50위 안에 넣는다. 왜 갑자기 완벽해지는가. NLO에서 상위 점수를 차지하는 token은 거의 항상 정답 token <v_i>와 함수 token <f_i>다. 그런데 distractor는 <g_i>와 <v_i>를 담고 있을 뿐 <f_i>는 담고 있지 않다. Query는 "<f_i>의 출력은?"이라고 묻기 때문에 <f_i>를 포함한다. 따라서 query gradient와 강하게 맞는 위치는 <f_i>가 있는 문서이고, <v_i>만 공유하는 decoy와는 거기서 갈린다. 실제로 같은 조건에서 decoy AUC가 1.00으로 나온다. 즉 정답 문서와 decoy를 완전히 분리한다. (이 메커니즘 설명은 문서 구성과 점수 정의로부터의 해석이고, 논문이 문장으로 명시한 것은 아니다.)

참고로 같은 조건에서 dense TRAK은 이 1.00을 얻지 못한다. Dense projection은 위치별로 분해되지 않아 top-10 집계 자체가 불가능하기 때문이다. Layerwise TRAK은 0.67까지 간다. 즉 "어떤 표현을 쓰는가"가 "어떤 집계를 쓸 수 있는가"를 결정하고, 그것이 성능 차이로 이어진다.

## 실험과 결과

**기존 방법은 어디서 무너지는가.** Figure 3과 Table 10~12가 답한다. Function Bindings에서 사실당 문서 수 N을 1에서 50으로 늘리면 dense TRAK의 recall이 0.88에서 0.07로 붕괴한다. EK-FAC은 0.70에서 0.45로 덜 무너지지만 역시 하락한다. 나머지 gradient 방법은 평균 recall이 0.04~0.28로 낮다. Distractor를 넣으면 더 심각하다. 모든 gradient 방법의 평균 recall이 0.2 미만으로 떨어지고, TRAK 두 종류는 0.00이 된다. Rule Routings는 최악이다. 문서 단위 점수에서 gradient 방법 중 최고인 EK-FAC이 0.19이고 나머지는 0.10 이하다. 반면 BM25는 Function Bindings에서 전 구간 1.00, distractor 조건에서도 평균 0.96, Rule Routings에서 1.00이다. RepSim은 전 조건에서 0.10~0.14로 약하다. 이 대비가 중요한 이유는, 텍스트에 명시적 단서가 있는데도 gradient 방법이 그것을 추출하지 못한다는 것을 보여주기 때문이다.

**두 수정을 적용하면.** Top-10 + NLO 조합의 평균 recall 변화가 Table 10~12에 있다. Function Bindings에서 Grad-Dot은 0.07에서 1.00으로, EK-FAC은 0.59에서 1.00으로, layerwise TracIn은 0.14에서 1.00으로 간다. Distractor 조건에서는 EK-FAC이 0.06에서 1.00, Grad-Dot이 0.00에서 0.99, Layerwise TracIn이 0.04에서 0.99다. Rule Routings에서는 EK-FAC이 0.19에서 0.55로 오르지만 여전히 BM25의 1.00에 크게 못 미친다. 이 조건에서 gradient 방법 중 0.35를 넘는 것은 없다.

저자들이 보고하는 종합 개선폭은 35(TrackStar)에서 72(Grad-Dot) percentage point이고, 이는 세 task와 모든 N, |F|에 걸친 평균이다. TrackStar가 하한인 이유는 명확하다. TrackStar의 점수에는 whitened norm의 역수라는 자체 문서 가중치가 붙어 있는데, top-k 집계가 그 가중치를 제거하지 못한다. 그래서 distractor 조건에서 0.03에서 0.13으로만 오른다.

Figure 6은 k를 바꿔가며 그린 곡선인데, 중요한 관찰은 최적 k가 하나가 아니라는 점이다. 작은 k 구간 전반에서 성능이 유지되고, k를 키우면 full-document 기준선을 향해 서서히 내려간다. 그리고 Rule Routings는 최적 k가 더 크다. 이는 이 task에서 중요한 token의 집합 자체가 더 크다는 뜻이고, "top-k는 항상 작을수록 좋다"는 식의 처방이 아니라는 것을 보여준다.

**외부 benchmark로의 일반화.** FTRACE-TREX에서 mT5-small(300M)을 1,560,453개 예제로 fine-tuning하고, 8,437개의 novel fact 중 50개를 골라 각 방법이 상위에 올린 문서를 지운 뒤 8개 seed로 재학습해 정답률 하락을 잰다. 제거 예산은 2,000 / 5,000 / 11,522개다. 결과는 TRAK이 8%에서 40%로(4.9배), EK-FAC이 30%에서 46%로, Grad-Dot이 7%에서 23%로 오른다. 여기서 40%라는 하락은 "그 50개 사실에 대한 능력을 거의 잃었다"는 뜻이고, 8%는 "거의 아무 일도 안 일어났다"는 뜻이므로, 두 값의 차이는 실질적으로 방법의 유용성 차이다. 다만 이 benchmark에서는 top-k 집계가 중립적이다. NLO 아래에서 top-10은 최대 6 point 안쪽으로만 움직인다. 저자들의 해석은 top-k의 효용이 문서 안에서 점수가 얼마나 넓게 퍼져 있는가에 달려 있다는 것이다.

**흥미로운 반전.** FTRACE-TREX에서 주석된 정답 문서(proponents)를 전부 지워도 정확도는 9 point밖에 안 떨어진다. 반면 BM25가 고른 문서를 지우면(그 안에 proponents의 76%가 포함된다) 15 point가 떨어진다. 즉 "주석된 정답"과 "모델이 실제로 의존하는 문서"가 상당히 다르다. 또한 NLO ranking으로 문서를 지우면 같은 relation의 다른 사실에서도 8~15 point가 함께 떨어진다. 이는 상위 문서들이 특정 사실 하나의 증거가 아니라 relation의 답 패턴을 가르치는 문서들이기 때문이다.

**비용.** 전체 sweep은 843개 job에 2,426 GPU-hour가 들었고, 그중 EK-FAC 계열 job이 820시간으로 최대다. M = 5,000에서 EK-FAC job이 모델당 39시간, layerwise-project job이 6.6시간, dense TRAK이 2.7시간, BM25는 CPU에서 수 초~수 분이다. 중요한 것은 제안하는 수정의 추가 비용이 작다는 점이다. Layerwise TracIn은 per-token 항 때문에 약 15%만 더 들고, EK-FAC은 45% 정도다. 즉 4.9배 개선을 거의 공짜로 얻는다.

## 한계

저자가 인정한 것부터. 첫째, 평가가 single-token 예측에 한정된다. Query의 답이 token 하나이므로 긴 multi-token 생성이나 chain-of-thought에서의 의존 구조는 다루지 못한다. 둘째, single-task fine-tuning만 본다. Multi-task 학습에서 지식이 서로 얽힐 때의 attribution은 미탐구다. 셋째, top-k의 k가 새로운 hyperparameter인데, 실제 환경에는 ground truth 검증 신호가 없으므로 dynamic thresholding이 필요하다. 넷째, BM25가 benchmark에서 1.00을 찍는다는 사실 자체가 약점이다. 표면적 lexical overlap이 너무 강한 단서라서, 진짜로 어려운 attribution을 시험하지 못한다.

읽으면서 드러나는 약점도 있다. Distractor가 12 token짜리 한 줄로 매우 인위적이다. 문서 점수를 평균으로 내는 관행이 길이로 나누는 것이기 때문에, 짧은 decoy는 구조적으로 유리해진다. 논문의 부록에서 평균 대신 합을 쓰면 회복된다고 보고하는데, 이는 dilution 효과의 일부가 "token 희석"이 아니라 "길이 정규화"의 부작용일 수 있음을 시사한다. 또한 loss를 바꾸면서 curvature는 cross-entropy 기준으로 고정한다. 이론적으로는 objective가 바뀌면 Hessian도 바뀌어야 하므로 일관성 문제가 남고, 그럼에도 효과가 있다는 것은 결과적으로 근사가 둔감하다는 뜻 이상은 아니다. 모델도 Qwen3.5-4B 하나이고 LoRA(129.9M parameter)만 학습하므로, full fine-tuning이나 다른 규모에서 재현될지는 알 수 없다. 방법 간 비교도 표현 방식에 교란된다. Dense TRAK, exact TracIn, SOURCE는 token 항이 없어서 top-k 처방을 적용할 수 없고, 이들이 낮은 점수를 받는 것이 방법의 성질 때문인지 표현의 한계 때문인지 분리되지 않는다. Rule Routings에는 distractor 조건이 아예 없다(속성 단어가 겹치지 않아 만들기 어렵다고 저자가 밝힌다). 마지막으로 FTRACE-TREX에서 정답 문서를 다 지워도 9 point밖에 안 떨어진다는 관찰은, 이 논문이 최적화하는 "정답 recall"이라는 지표 자체의 타당성에 의문을 제기한다.

## 왜 중요한가

실무적 의미가 크다. Data attribution은 저작권 보호, 기여도 배분, emergent misalignment 추적처럼 고위험 영역에 쓰이려 하고 있고, 현재 관행은 문서 단위 점수를 그대로 신뢰한다. 이 논문은 인과적 증거가 국소화되어 있을 때 그 집계 점수가 근본적으로 불신뢰할 수 있음을 보여준다. 실무자에게 주는 처방은 구체적이다. Attribution을 돌릴 때 token 단위 점수를 반드시 들여다보고, 문서 전체 평균 대신 상위 token 집계를 기본으로 삼고, gradient loss가 cross-entropy인지 확인하라는 것이다. 세 가지 모두 추가 비용이 거의 없다.

방법론적으로는 더 큰 의미가 있다. 새로운 estimator를 만드는 대신 평가를 통제 실험으로 바꾸는 것만으로 "왜 실패하는가"라는 질문에 답할 수 있게 만들었다. 이 논문의 발견이 estimator 구조가 아니라 objective와 pooling에서 나왔다는 점이 특히 중요하다. 연구 공동체가 오랫동안 더 빠르고 더 확장 가능한 근사를 좇았는데, 실제 병목은 신호 처리에 있었다는 것이다.

후속 연구의 좌표도 제시한다. Multi-token 생성, multi-task 학습, multi-hop 추론(사실 근거가 한 문서가 아니라 여러 개념에 흩어진 경우), dynamic k 선택, 표면적 overlap이 단서가 되지 않는 더 어려운 corpus가 열린 문제로 남는다. 그리고 "언제 top-k가 도움이 안 되는가"라는 조건부 발견 자체가 하나의 연구 주제다. FTRACE-TREX처럼 점수가 문서 전체에 퍼져 있으면 top-k는 중립적이므로, 문서 내 점수 분포를 보고 집계 방식을 적응적으로 고르는 방향이 자연스러운 다음 단계다.

## 원문 초록

> Data attribution methods for Language Models (LMs) are typically evaluated using downstream tasks like fact retrieval. However, existing evaluations vary multiple dataset properties simultaneously, making it impossible to isolate exactly why an attribution algorithm fails. To diagnose these failures, we explore the design space of LLM data attribution, with a primary focus on evaluation. We introduce the Controlled Attribution Benchmark (CATT) for fact tracing, in which we fine-tune LLMs on entirely fictitious knowledge, providing unambiguous ground truth for attribution. This synthetic setup allows us to systematically alter one dataset configuration at a time, such as document redundancy and lexical distractors. With this configurable evaluation, we demonstrate that redundancy and distractors consistently degrade attribution performance. Rather than proposing a new estimator, we examine two design choices that are underexplored: the loss used to compute gradients and how per-token attribution scores are aggregated into a document score. We find that the true causal evidence within a training document is highly localized, but standard methods dilute this evidence into noise by averaging attribution scores across the entire document. We find that replacing standard cross-entropy loss gradients with the negative log-odds gradients surfaces the critical tokens from other uninformative ones. We can then aggregate only the top token scores to improve ground truth recall by 35 to 72 percentage points across multiple baselines on our diagnostic benchmark. The negative log-odds correction also generalizes to FTRACE-TREX, improving counterfactual retraining performance for every method we test, by up to 4.9x.
