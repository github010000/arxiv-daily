## 한 줄 요약
에이전트가 외부 객체를 통째로 읽는 대신 "지금 다음 결정에 필요한 증거"만 정해진 노출 예산 안에서 읽고, 국소 읽기가 손해인 상황에서는 전체 보기로 되돌아가게 만드는 모델 비수정 읽기 제어 계층 SparseRead 를 제안하고, 6개 모델·5개 시나리오 30개 설정에서 토큰을 중앙값 61.4% 줄이면서 과제 품질을 29개 설정에서 유지 또는 개선했다고 보고한 논문이다.

## 핵심 개념 풀이

**1) over-reading(과잉 읽기).** 이 논문의 문제 이름부터가 개념이다. 에이전트가 웹페이지나 파일을 열면, 읽기 인터페이스는 거의 항상 "객체(object) 단위"로 내용을 넘긴다. 페이지 전체, 파일 전체, tool 응답 전체다. 그런데 에이전트의 다음 결정에 실제로 필요한 것은 그중 몇 문장일 수 있다. 이 불일치를 논문은 over-reading 이라 부른다. 주의할 점은 이 말이 "모델이 게을러서 많이 읽는다"는 비난이 아니라는 것이다. 인터페이스가 부분 읽기라는 선택지를 아예 제공하지 않기 때문에 생기는 구조적 현상이다. 논문은 이 비용을 수치로 제시하는데, 기존 연구를 인용해 에이전트 궤적에서 처리되는 토큰의 60~80%가 외부 관찰(observation)이라고 하고, 짝지은 실행 비교에서 수정되지 않은 에이전트가 최대 17.3배 더 많은 토큰을 쓰고도 과제 품질은 더 높지 않았다고 보고한다.

**2) content admission 과 control plane / evidence plane.** "admission"은 입장 허가라는 뜻이다. 건물 앞 문지기가 모든 사람을 들여보내지 않고 용건이 확인된 사람만 로비로 들이는 것과 같다. SparseRead 는 모델과 외부 자원 사이에 서서, 어떤 내용이 모델의 context 에 "들어오도록 허락"될지를 결정한다. 중요한 설계 구분이 control plane 과 evidence plane 이다. control plane 은 의도를 해석하고, Reader 를 고르고, 증거 기록을 유지하고, 무엇이 context 에 들어갈지 통제한다. evidence plane 에 있는 Reader 들은 증거를 실제로 가져오지만, "언제 자기가 호출될지"는 스스로 결정하지 않는다. 이 분리가 논문이 말하는 "모델을 수정하지 않는다"의 실체다. 모델 가중치도 바꾸지 않고, 별도의 생성형 압축 모델도 두지 않는다.

**3) Read Intent, EvidencePack, coverage.** Read Intent 는 "다음 결정을 위해 무엇이 필요한가"를 구조화해서 적어 내는 요청서다. 논문은 두 층을 구분한다. session intent 는 사용자의 최초 요청에서 유도된 전체 목표이고, access intent 는 지금 이번 접근에서 필요한 것이다. access intent 가 우선하고, session intent 는 빠진 항목을 채우는 역할만 한다. 새 하위 목표를 덮어쓰지 않는다. 읽기의 반환값은 EvidencePack 인데, 여기에는 출처에 고정된(anchored) 증거 조각, 처리한 범위, 노출한 양, 그리고 요구 항목별 coverage 가 담긴다. coverage 는 이 논문에서 가장 오해되기 쉬운 개념이다. 그것은 "어느 요구에 증거가 붙었고 어느 요구가 아직 비어 있는가"를 기록할 뿐, "이 증거로 답이 충분한가"를 판정하지 않는다. 사서가 "이 주제 책은 이 서가에 있고, 저 주제는 아직 못 찾았습니다"라고 알려주되 "이걸로 충분합니다"라고 단정하지 않는 것과 같다. 충분성 판단과 중단 결정은 에이전트에게 남는다.

**4) processing scope, model exposure, evidence coverage 의 삼분(三分).** 논문이 반복해서 강조하는 구분이다. processing scope 는 Reader 가 훑거나 계산한 원본의 양, model exposure 는 실제로 모델 context 에 들어간 양, coverage 는 현재 의도의 항목 중 증거가 확보된 것이다. 이 셋은 함께 움직일 필요가 없다. 표 전체를 스캔해서 열의 합계를 구하고, 모델에게는 합계 값과 행 수와 출처만 보여줄 수 있다. 처리 범위는 전체인데 노출은 몇십 자다. 이 구분 덕분에 sparse reading 이 "국소 검색"에만 유리한 기법이 아니라, 전체 객체에 대한 정확 연산에도 유리한 기법이 된다. 노출을 줄이는 데 처리 범위를 줄일 필요가 없다는 것이 논문의 핵심 통찰 중 하나다.

**5) replay-weighted exposure.** 대화 이력은 매 호출마다 다시 모델에 들어간다. 그래서 i번째 단계에서 새로 노출된 내용 e_i 는 이후 R_i 번의 호출에 계속 남아 비용을 낸다. 논문은 이를 C_exposure = Σ_i |e_i| · R_i 로 적는다. "replay"라는 이름은 이 재생을 뜻한다. 논문이 스스로 단서를 붙이는 부분이 중요한데, 이 양은 논리적 context 재생을 재는 것이지 청구된 토큰이나 실제 prefill 연산량을 재는 것이 아니다. prefix caching 이 한계 비용을 낮출 수는 있어도, 남아 있는 내용 자체를 없애지는 않는다. 즉 일찍 크게 들여온 내용은 청구서에서 할인되더라도 여러 번 재생된다.

**6) ski rental 과 온라인 예산, 그리고 2L.** 스키를 살까 빌릴까를 모르고 결정해야 하는 고전 문제가 ski rental 이다. 빌린 총액이 살 값에 도달하면 그때 사는 전략이 최악의 경우에도 최적 대비 2배를 넘지 않는다는 것이 알려져 있다. 이 논문의 Budgeted Read Gate 는 정확히 이 구조다. "조금씩 sparse 로 읽기"가 대여, "full view 한 번 받기"가 구매다. 정답을 미리 알 수 없으므로 온라인으로 결정해야 하고, 논문은 누적 노출이 full view 길이 L 의 2배, 즉 2L 을 넘지 않음을 정리로 증명한다. 이 정리가 의미하는 바는 "sparse reading 이 손해일 수 있다"는 사실을 인정하면서도 손해의 상한을 보장한다는 점이다. 이익은 에이전트가 L 보다 훨씬 적은 증거로 끝낼 때 발생한다.

## 문제의식

기존 기법들은 이 문제의 조각들만 다룬다. long-context 아키텍처와 KV-cache 압축은 context 의 연산·메모리 오버헤드를 줄이지만, "모델이 어떤 원본 내용을 보아야 하는가"를 결정하지 않는다. ACON 이나 observation masking 은 tool 관찰이나 그 지속성을 줄이지만, 이미 내용이 들어온 뒤의 사후 처리다. 검색(retrieval)은 필요할 때 구절을 가져올 수 있지만, 그것만으로는 변화하는 읽기 의도, 명시적 출처 coverage, 노출 상한, 전체 보기 fallback 을 아우르는 공통 계약을 제공하지 못한다.

이게 실무에서 왜 곤란한가. 예를 들어 에이전트가 저장소에서 설정 파일 하나의 timeout 값을 확인하려 한다고 하자. 인터페이스는 3,000줄짜리 응답 전체를 넘긴다. 그 전체가 이후 호출마다 다시 재생되므로 비용은 한 번이 아니라 스무 번 난다. 더 나쁜 것은 품질이다. 논문은 과잉 내용이 관련 증거를 희석시켜 잘못된 tool 사용, 출처 혼동, 멈춰야 할 때 멈추지 못하는 실패를 유발할 수 있다고 지적한다. 실제로 Figure 3 의 짝지은 비교에서 전체 읽기 에이전트는 sparse 읽기보다 최대 17.3배 토큰을 쓰고도 점수를 올리지 못했다. 즉 "많이 보여주면 언젠가 도움이 된다"는 가정이 성립하지 않는다. 논문은 annotated 근거가 LooGLE 의 경우 질문당 중앙값 3.17%, 한 문서의 다섯 질문 전체로는 2.89%, Qasper 의 답변 가능 문항에서는 약 5.8%만 덮는다는 수치를 제시한다. 원본의 3%를 위해 100%를 들여오고 있었던 셈이다.

## 핵심 아이디어

본질은 읽기의 단위를 바꾸는 것이다. "객체를 전달한다"에서 "증거 요청에 응답한다"로 바꾼다. 그러면 세 가지가 명시적으로 관리되어야 한다. 첫째, 지금 무엇이 필요한가(Read Intent). 둘째, 지금까지 무엇을 처리했고 무엇이 노출되었고 무엇이 덮였는가(증거 기록과 coverage). 셋째, 얼마나 더 노출해도 되는가(노출 예산).

왜 이 아이디어가 문제를 푸는가를 논리로 이으면 이렇다. 과잉 읽기의 원인은 모델의 판단력 부족이 아니라 인터페이스에 부분 읽기 계약이 없다는 것이다. 그렇다면 모델을 바꾸는 대신 인터페이스에 계약을 넣으면 같은 모델로도 결과가 달라져야 한다. 그런데 계약만 넣으면 두 번째 문제가 생긴다. 정보 필요는 실행 중에 변하고, 각 부분 읽기는 목적과 검사한 범위를 남겨야 하며, 그렇지 않으면 같은 출처를 반복 방문한다. 그래서 의도와 coverage 를 상태로 유지하는 프로토콜이 필요하다. 동시에 sparse 접근이 항상 경제적인 것은 아니다. 작은 객체나 전역 통계처럼 전체를 봐야 하는 요청에서는 반복 부분 읽기가 직접 읽기보다 비싸다. 그런데 그 경계는 읽기 전에 알 수 없는 경우가 많다. 그래서 "미리 최적 모드를 예측"하는 대신, sparse 를 시도하되 누적 노출을 full view 비용과 비교하며 예산을 넘기 전에 전환하는 온라인 제어기가 필요하다. 이 세 가지가 각각 Read Intent Protocol, Adaptive Reader Backends, Budgeted Read Gate 로 대응하며, 하나의 읽기 루프를 이룬다.

## 방법

**(1) Read Intent Protocol.** 읽기를 "하나의 읽기 목표 아래 한 가지 버전의 객체에 대한 일련의 접근"인 episode 로 정의한다. episode 안의 refine 과 verify 는 접근 의도가 바뀌어도 같은 증거 기록과 같은 노출 예산을 공유한다. 목표가 다르면 새 episode 다. 에이전트가 쓰는 행동은 scout, focus, collect, refine, verify 다섯 개로 고정되어 있고, 새 Reader 를 추가해도 에이전트의 행동 집합은 늘지 않는다. Reader 가 각 행동을 자기 자원 유형의 연산으로 매핑한다. 또한 SHA-256 fingerprint 로 객체 버전을 식별해서, 버전이 바뀌면 그 객체에 대해 기록된 증거와 coverage 를 무효화한다. 버전이 같으면 이전 구간은 여전히 유효하지만 새 의도를 덮지는 못할 수 있다.

Algorithm 1 의 한 번의 접근을 말로 풀면 이렇다. 먼저 버전을 동기화하고, 접근 의도와 세션 의도를 합쳐 검증한다. 모호하거나 범위 요구가 모순되면 플래그를 단다. 다음으로 episode 상태를 확보하고 이 episode 에 고정될 full view f 를 정한다. 만약 의도가 전체 모델 열람을 요구하거나 객체가 작아 그냥 들어가면(native fit) 즉시 full view 로 간다. 의도가 미명세이거나 행동이 scout 이면 경계가 정해진 재사용 가능한 Object Preview 를 준다. 그다음 신뢰도와 비용을 기준으로 Reader 구성을 고르고, 후보가 없거나 준비된 배치의 추정 크기가 남은 예산을 넘으면 full view 로 간다. 직렬화 단계에서 실제 payload 를 같은 한도로 다시 확인하고, 잘라야만 들어가면 아예 버리고 full view 로 간다. 즉 의미나 출처 고정이 깨질 잘라내기는 하지 않는다. 통과하면 증거 기록과 예산을 갱신하고 EvidencePack 을 반환한다.

**(2) Adaptive Reader Backends.** Reader 는 "특정 검색 알고리즘"이 아니라 "다루는 자원 유형"으로 정의된다. 그 안에서 두 가지 선택이 분리된다. 어떻게 증거를 찾거나 처리할 것인가(어휘 매칭, BM25 창, hybrid 검색, 열 선택, key path 조회, 정확 연산)와, 무엇을 노출할 것인가(출처 고정 스니펫, 무손실 압축 전체 보기, 정확 연산의 결과와 provenance)다. 이 둘의 조합이 Reader configuration 이고, 모든 구성이 같은 EvidencePack 계약을 낸다. 선택 규칙은 r* = argmin Ĉ(r|g) subject to p̂_valid(r|g) ≥ τ 다. g 는 요청 그룹(자원 유형, full view 크기 구간, 의도 유형의 곱), Ĉ 는 노출 문자 수와 호출당 고정 오버헤드와 보정에서 관찰된 평균 후속 노출로 추정한 비용, p̂_valid 는 보정 요청에서 얻은 증거 성공률의 95% Wilson 구간 하한, τ 는 0.6 이다. 임계를 만족하는 구성이 없으면 임계를 몰래 낮추지 않고 full view 로 간다.

**(3) Budgeted Read Gate.** f(o) 를 현재 요청에 쓸 수 있는 가장 싼 충실한 전체 보기, L 을 그 노출 길이라 하자. 원본 native 읽기일 수도 있고 무손실 압축 표현일 수도 있다. 즉 압축된 전체 보기를 쓰면 예산 L 자체가 작아진다. 규칙은 셋이다. 전체 열람이 필요하거나 적합한 Reader 가 없으면 full view, 작은 객체면 sparse 우회, 그 외에는 sparse 로 시작하되 누적 payload E 가 L 을 넘지 않게 한다. 배치를 내보내기 전에 추정 크기를 남은 예산과 비교하고, 직렬화 후 실제 크기를 같은 한도로 재확인한다. 다음 배치가 온전히 들어가지 않으면 그 배치는 보류하고 full view 를 준다. fallback 시 이전의 sparse 관찰은 이후 프롬프트에서 퇴역시켜 재생을 막는다. 이미 지불한 비용은 환불되지 않는다.

## 왜 성립하는가

핵심은 Proposition 4.1, 즉 "native 대비 노출 상한"이다. 고정된 버전과 고정된 full view f(o), 길이 L 인 episode 에서, Gate 가 누적 sparse payload 를 최대 L 만 허용하고 fallback 에서 full view 를 최대 한 번만 준다면, episode 의 총 비노출 가중 노출은 최대 2L 이다. preview 와 프로토콜 메타데이터는 별도로 상한이 있다고 보고 제외한다.

증명의 뼈대는 불변식 하나다. E ≤ L 이 항상 유지된다. 처음에 E = 0 이다. E 를 바꾸는 곳은 알고리즘의 한 줄뿐인데, 그 줄은 "직렬화가 L − E 라는 한도 아래에서 끝난 직후"에 실행된다. 따라서 새 E 는 E + PayloadSize(x) ≤ E + (L − E) = L 이다. fallback 을 포함한 다른 모든 분기는 E 를 건드리지 않는다. 이제 노출을 세면, 허용된 sparse 증거가 정확히 E ≤ L 이고, fallback 은 f(o) 를 최대 한 번 주고 episode 를 닫는다. f(o) 가 이미 증거로 노출된 적이 있으면 fallback 은 아무것도 더하지 않아 총합이 E ≤ L 이다. 아니라면 L 이 더해져 총합이 E + L ≤ 2L 이다. fallback 없이 끝난 episode 는 E ≤ L 이다. 모든 경우에 2L 이하다. ∎

왜 이 불변식이 실제로 지켜지는가. 논문이 강조하는 부분은 이것이 "직렬화된 실제 payload 검사"에만 의존한다는 점이다. 배치 준비 단계의 추정은 fallback 을 더 일찍 트리거할 수만 있고, 예산을 넘겨 통과시키지는 못한다. 그리고 "배달한 뒤에 검사"하면 어떻게 깨지는지도 명시적이다. 그 경우 총합이 2L + δ 가 되는데 δ 는 가장 큰 배치 크기다. 실측이 이를 뒷받침한다. 배달 후 검사한 코호트에서는 세 번의 업그레이드가 full view 의 2.10~2.33배에 도달했고, 배달 전 검사로 바꾼 코호트에서는 여섯 번의 비율이 모두 1.62~1.93 안에 머물렀다.

상수 2 가 느슨한 장식이 아니라는 점도 증명에 붙어 있다. L 에 살짝 못 미치는 배치들을 채운 뒤 다음 배치를 거절하고 fallback 하면 총합이 2L 에 살짝 못 미친다. 즉 이 규칙에 대해 2는 tight 하다. 다만 이 정리가 보장하는 것은 어디까지나 episode 단위의 비가중 원시 노출이다. replay-weighted context, 청구 토큰, 지연 시간, 여러 episode 로 이루어진 세션에는 보장이 없다.

정리가 아닌 부분의 근거는 실험이다. 프로토콜이 실제로 재방문을 줄이는지는 절제 실험으로 제시된다. intent 를 쓰지 않을 때와 둘 다 쓸 때를 비교하면, 과제당 반복 읽기가 4.8회에서 1.5회로 68.8% 줄고, 추적 불가능한 증거가 28%에서 8%로 줄며, 증거 공백을 실제로 메우는 검증의 비율이 37%에서 89%로 오르고, 증거 누락 때문에 실패한 답이 25%에서 5%로 떨어진다. access intent 만 쓰는 것이 session intent 만 쓰는 것보다 네 진단 모두에서 낫고, session intent 를 더하면 반복 읽기가 1.9회에서 1.5회로, 유효 검증이 82%에서 89%로 개선된다.

## 구체적 예시

**예시 A: 2L 상한을 숫자로 따라가기.** full view 길이 L = 10,000 character 인 문서를 읽는 episode 를 상상하자. 첫 배치가 2,800 character, 둘째가 3,400 character 로 온전히 들어왔다면 E = 6,200 이고, 비율 (E + L)/L = 16,200/10,000 = 1.62 다. 이 값은 논문이 배달 전 검사 코호트에서 관찰한 하한 1.62 와 정확히 같은 형태다. 여기서 셋째 배치의 추정 크기가 4,500 character 라면 남은 예산은 L − E = 3,800 이므로 들어가지 않는다. Gate 는 그 배치를 보류하고 full view 를 준다. 총 노출은 6,200 + 10,000 = 16,200, 즉 1.62L 로 상한 2L 안이다. 반대로 예산을 거의 다 쓴 뒤 fallback 하면 비율이 1.93까지 올라간다. E/L = 0.93 인 상태에서 full view 를 더한 값이다. 배달 후 검사 방식이 2.10~2.33까지 overshoot 한 것은 비율을 E/L 로 환산하면 1.10~1.33, 즉 이미 L 을 넘긴 배치를 받아들인 뒤였다는 뜻이다. 상한을 넘긴 정도가 곧 "사후 검사가 놓친 배치 크기"다.

**예시 B: sparse 가 손해인 지점(부록 C).** T67 은 SPARQL 질의 생성 과제다. 강제로 sparse 읽기를 적용하면 토큰이 Naive 대비 309.0% 증가한다. 3배가 넘는다. T59 는 할인 계산 과제로 210.5% 증가한다. 이유는 이 과제들이 국소 증거 조각을 반복해서 가져오는 방식과 맞지 않기 때문이다. 반면 Gate 를 쓰면 T67 에서 22.5%, T59 에서 54.0% 토큰을 절약하고, 점수도 T67 이 0.50 대 0.43, T59 가 0.69 대 0.65 로 오히려 높다. 같은 실험에서 T58(DiD 회귀)은 강제 sparse 가 49.0% 증가, Gate 는 45.0% 절약이다. 그리고 sparse 가 잘 맞는 과제에서는 이득이 유지된다. L5Q 79.8%, T21 88.3%, T12 82.5% 절약이다. 이 표가 보여주는 것은 "적응적 문턱"의 가치 그 자체다. 같은 기법이 한 과제에서는 3배 손해, 다른 과제에서는 5배 이익이다.

## 실험과 결과

규모는 6개 모델(중형 2개, 대형 오픈 모델 3개, 상용 폐쇄 모델 Claude Opus 5), 5개 시나리오(장문 읽기, 다중 파일 감사·진단, 구조화 분석, 웹 심층 검색, AI for Science)의 30개 설정이다. 논문에 적힌 모델명과 버전은 논문 표기를 그대로 옮긴 것이다.

전체 결과는 토큰 15.7~92.9% 절감, wall time 23.0~89.0% 절감, 중앙값 각각 61.4%와 53.7%다. 점수는 30개 중 29개에서 유지 또는 개선이고, 회귀는 GLM-5.1 의 AI for Science 한 곳이다. 여기서 해석이 필요하다. 중앙값 61.4%는 "평균적으로 절반 이상 줄었다"는 뜻이고, 92.9%라는 최대치는 원본의 대부분이 불필요했던 설정이 있었다는 뜻이다. 실제로 장문 읽기 시나리오가 76.5~92.9% 절감으로 가장 크다. 근거 비율이 3% 수준인 과제이니 예상된 결과다. 반대로 웹 심층 검색은 31.0~43.0% 절감에 그치는데, 반복 검색 질의 자체가 과제 수행에 필수라 줄일 여지가 작기 때문이다. 그런데도 이 시나리오에서 여섯 모델 모두 점수가 5~14 percentage point 올랐다. 절감 폭은 작지만 노이즈 감소 효과가 품질로 나타난 것으로 읽을 수 있다. Opus 5 는 다섯 시나리오 전부에서 토큰 41.0~89.0%, 시간 35.0~78.1%를 절약했다. 추론 능력이 강한 모델도 읽기를 통제하면 이득을 본다는 뜻이다.

베이스라인 비교는 15개 설정이다. RAG Static 은 웹 설정 다섯 개에서 모두 더 빠르지만 15개 중 9개에서 Naive 보다 점수가 낮다. 정적 검색은 빠르지만 필요한 증거를 다 덮지 못한다는 뜻이다. RAG Agent 는 같은 반복·시간 제한 아래에서 8개 설정에서 점수를 잃고 8개에서 Naive 보다 느리다. ACON 은 5개에서 점수를 잃고 6개에서 두 비용이 모두 증가하며, observation masking 은 5개에서 점수를 잃는다. SparseRead 는 15개 전부에서 점수를 유지 또는 개선하고 토큰 27.0~92.9%, 시간 23.0~88.9%를 절약한다. 다중 파일 진단에서는 다섯 모델 모두 토큰과 시간 양쪽 최소를 달성하면서 점수를 17.8~34.5 percentage point 올렸다. 이 정도 점수 상승은 비용 절감의 부산물로 보기 어렵고, 증거 희석이 줄어든 효과로 해석하는 것이 자연스럽다.

프레임워크 이식성은 NanoBot, OpenCode, OpenClaw 세 곳, 18개 설정이다. 18개 전부에서 토큰과 시간이 줄고, 점수는 15개에서 유지 또는 개선, 3개에서 0.013~0.031 감소다. 중앙값 토큰 절감은 각각 65.0%, 65.2%, 30.6%다. OpenClaw 의 이득이 가장 작은데, 논문은 원인을 명시하지 않는다. 다만 얇은 plugin·bridge 어댑터로 붙였다는 기술이 있고, 접근 경로가 하나 더 끼는 구조라는 점은 감안해서 읽어야 한다.

절제 실험의 숫자도 해석할 만하다. Reader 위치 방법 비교(47개 LooGLE 문서, 741개 질문)에서 어휘 매칭은 780 character 로 39.5% hit, BM25 는 1,497 character 로 60.1%, Hybrid 는 1,490 character 로 65.3%다. Hybrid 가 거의 같은 노출로 BM25 보다 5.2 percentage point 높다. 반면 BM25 의 창을 넓히면 노출이 2,106 character 로 41% 늘어나는데 hit 는 56.7%로 떨어진다. 많이 보여주면 좋아진다는 직관의 직접적 반례다.

## 한계

저자가 인정한 것부터. 첫째, 2L 보장은 episode 단위의 비가중 원시 노출에만 적용된다. replay-weighted context, 청구 토큰, 지연, 여러 episode 세션에는 보장이 없고, fallback 시 이전 관찰을 퇴역시켜 미래 재생은 줄여도 이미 지불한 노출은 환불되지 않는다. 둘째, 상수 2 는 이 규칙에 대해 tight 하므로 더 조인 개선의 여지가 규칙 자체를 바꾸지 않고는 없다. 셋째, 신뢰도 보정은 평가 과제가 아닌 수동 설계 요청에 의존하고, 그룹당 보정 요청이 20개 미만이면 adaptive 하지 않고 기본 구성으로 떨어진다. 넷째, Figure 8(b) 의 위치 방법 비교는 고정 구성 대비 선택기의 증분 이득을 분리하지 못한다고 저자가 직접 밝힌다. 다섯째, fallback 은 이전 sparse 관찰을 퇴역시키므로 수정 지점 이후의 prefix-cache 재사용을 잃을 수 있다.

읽으며 드러나는 약점도 있다. 점수 회귀가 완전히 사라지지 않았다(GLM-5.1 의 AI for Science, OpenCode 의 Kimi-K2.5 −0.031 등). NanoBot 의 Kimi-K2.5 는 토큰 92.9% 절감에 점수 +0.598 이라는 매우 큰 폭을 보고하는데, 이 정도 상승은 개선 효과라기보다 그 설정의 Naive 기준선이 낮았다는 신호로 보는 편이 안전하다. 논문은 이 폭에 대한 설명을 주지 않는다. 또한 상한 계산에서 preview 와 프로토콜 메타데이터를 제외하고 있는데, 실제 배포에서는 이 고정 비용과 Gateway 왕복이 총비용에 들어간다. 웹 검색처럼 절감률이 30%대인 영역에서는 이 고정 비용이 상대적으로 커질 수 있다. 마지막으로 "충실한 full view"를 무엇으로 볼지, 즉 L 을 어떤 표현으로 잡을지는 도메인 판단이며, 이 선택이 예산 전체를 좌우한다.

## 왜 중요한가

이 논문의 기여는 압축 기법 하나가 아니라 계약(contract) 하나다. Read Intent 에서 EvidencePack 으로 이어지는 인터페이스는 검색이나 압축 기법을 대체하지 않고 그 위에서 조정한다. 논문이 밝히듯 SWE-Pruner 나 Squeez 같은 도구 출력 압축기도 Reader backend 로 끼울 수 있다. 즉 증거 획득 기술이 발전할수록 상위 제어 계층의 효과도 같이 커지는 구조다.

실무적으로는 tool 인터페이스 설계 지침으로 바로 쓸 수 있다. 첫째, 읽기 API 에 preview 와 read 를 분리하고, read 는 의도를 받게 한다. 둘째, 반환값에 출처 고정, 처리 범위, 노출량, 항목별 coverage 를 필드로 넣는다. 셋째, 에이전트 세션에 노출 예산과 full view fallback 을 두고, 배치를 내보내기 전에 검사한다. 이 세 가지는 모델 교체 없이 적용 가능하고, 프레임워크 세 곳에서 이식성이 확인됐다.

후속 연구의 방향도 선명하다. episode 를 넘는 세션 수준 예산, replay-weighted 비용에 대한 상한, 보정 요청 수를 줄이는 선택기 학습, coverage 를 자동 검증하는 방법이 모두 열려 있다. 그리고 이 논문이 던지는 더 큰 질문은 이것이다. 에이전트 성능의 병목이 "모델이 얼마나 똑똑한가"에서 "모델에게 무엇을 언제 보여줄 것인가"로 옮겨가고 있다면, 읽기 제어는 프롬프트 엔지니어링의 하위 기법이 아니라 인프라 계층의 일급 문제다.

## 원문 초록

> Web-facing AI agents repeatedly access webpages, documents, repositories, and tool responses, yet reading interfaces often expose entire objects when only sparse evidence is needed. This over-reading increases token and latency costs and can dilute relevant evidence. We present SparseRead, a reusable reading control layer that governs content admission without modifying the agent model. Its Read Intent Protocol tracks evolving needs and source coverage; Adaptive Reader Backends select how evidence is located and exposed; and the Budgeted Read Gate bounds cumulative raw exposure per episode with faithful full-view fallback. A unified Reader interface supports interchangeable evidence acquisition across heterogeneous resources. Across six models, including Claude Opus 5, and five scenarios, SparseRead reduces total tokens by up to 92.9% and wall time by up to 89.0%, preserving or improving task quality in 97% settings. On Web deep-search tasks, it reduces tokens by 31.0--43.0% and task completion time by 23.0--37.0%. Ablations validate the three designs, while integration with three agent frameworks demonstrates portability.
