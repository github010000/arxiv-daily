## 한 줄 요약

LIBERO-PeRM은 로봇이 작업을 성공하는 것(task success)과 사용자가 원하는 방식으로 수행하는 것(preference satisfaction)을 분리해 측정하는 시뮬레이션 benchmark이며, 312개의 preference-conditioned task와 다섯 개의 task suite를 제공하고, 기존 Vision-Language-Action 모델은 zero-shot personalization에 약하며 supervised fine-tuning으로 일부 학습되지만 일반화·조합·충돌이 어렵다는 것을 실험으로 보여준다.

## 핵심 개념 풀이

**Preference는 task goal이 아니라 수행 방식을 제약한다.**  
로봇에게 “머그잔을 테이블에 올려라”라고 하면 이것이 task goal이다. 그런데 사용자는 같은 잔을 옮길 때도 “손잡이를 바깥쪽으로 두세요”, “테이블의 지정된 구역은 피하세요”, “테이블을 보호해야 하니 컵받침을 사용하세요” 같은 조건을 붙인다. preference는 이처럼 목표를 바꾸지 않으면서, 같은 목표를 달성하는 여러 trajectory 중 어떤 것을 선택할지 정하는 기준이다. LIBERO-PeRM은 언어로 표현할 수 있고, 시뮬레이션에서 관찰 가능하며, 자동으로 만족 여부를 측정할 수 있는 preference만 다룬다. 이런 제한이 있어야 재현 가능한 benchmark가 된다.

**Vision-Language-Action (VLA) model과 zero-shot personalization.**  
VLA는 vision 입력과 language 입력을 함께 받아 robot action을 출력하는 정책이다. 최근에는 대규모 vision-language model backbone에 로봇 데이터를 학습시켜 generalist robot policy를 만드는 방식이 많이 쓰인다. zero-shot은 이 모델을 LIBERO-PeRM의 preference 예시에 추가로 학습시키지 않고, 프롬프트에 “Preference: ...” 같은 문구를 넣어주는 것만으로 preference를 따르는 능력을 평가하는 상황이다. 이 논문은 OpenVLA-OFT, pi0-fast, pi0.5, GR00T-N1.6, SmolVLA, UniVLA 여섯 개 VLA를 zero-shot 평가에 사용한다.

**Demonstration, SFT, LoRA.**  
demonstration은 어떤 observation에서 어떤 action을 취해야 하는지 보여주는 trajectory 데이터다. 정책을 언어 명령만으로 처음부터 학습시키는 것은 어렵기 때문에, 이 demonstration의 action을 모방하도록 supervised learning을 시킨다. 이를 supervised fine-tuning (SFT)이라고 부른다. LoRA는 모델 전체를 fine-tuning하지 않고, 원래 weight에 작은 low-rank 행렬을 더하는 parameter-efficient fine-tuning 기법이다. 이 논문은 non-zero-shot 실험에서 zero-shot 성능이 가장 좋았던 pi0.5를 base checkpoint로 두고 LoRA 기반 SFT를 적용한다.

**Task success rate와 preference satisfaction.**  
task success rate(SR)는 에피소드가 목표 상태에 도달했는지만 측정한다. preference satisfaction(SA)은 preference가 얼마나 지켜졌는지를 평가하되, task에 실패한 에피소드는 preference 만족 점수를 0으로 처리한다. 이렇게 하는 이유는 “작업은 실패했지만 우연히 어떤 preference 조건은 만족했다”는 관찰을 보상하지 않기 위해서다. 논문의 공식 $\mathrm{SA}=\frac{1}{N}\sum_{n=1}^{N}\mathbb{I}[G(\tau_n)]d_n$에서 $\mathbb{I}[G(\tau_n)]$는 task 성공 여부, $d_n$은 0, 1/4, 3/4, 1의 4단계 discrete satisfaction label이다. 예를 들어 SR만 높고 SA가 낮으면 로봇은 일은 잘 끝내지만 사용자의 방식을 무시한다는 뜻이고, SR 자체가 낮으면 preference가 task 수행을 어렵게 만든다는 뜻이다.

**LIBERO의 mission, layout, paired demonstration.**  
LIBERO는 로봇 팔이 물체를 집고 놓는 3D 시뮬레이션 manipulation benchmark이다. 여기서 mission은 task instruction, scene layout, goal condition을 묶은 단위다. layout은 어떤 물체들이 어디 놓여 있는지, 목표 받침대가 어디인지 같은 시각적 구성을 말한다. LIBERO-PeRM은 같은 mission에 대해 no-preference demonstration과 preference-conditioned demonstration을 함께 생성한다. 이렇게 paired demonstration을 만들면 scene 차이 때문에 행동이 달라지는 혼동을 막고, 오직 preference 문구 차이가 행동 차이의 원인인지 분리할 수 있다.

## 문제의식

최근 VLA 모델들은 “사과를 바구니에 넣어라” 같은 일반적인 task는 잘 수행한다. 그러나 집에 들어가는 로봇은 사용자마다 다른 습관과 제약을 따라야 한다. 사용자가 “우유를 식탁에 올려라”라고 했을 때, 로봇이 그냥 식탁 표면에 우유를 내려놓으면 task는 성공이지만, 사용자가 “테이블 흠집을 피하려면 컵받침 위에 놓아야 한다”고 원했다면 실제로는 실패다. 기존 manipulation benchmark는 대부분 task success rate만 보고하기 때문에 이런 종류의 실패를 진단하지 못한다.

개인화 연구는 용어와 평가가 제각각이다. 어떤 연구는 human feedback을 통한 암시적 선호 정렬로 보고, 다른 연구는 사용자별 스타일 적응이나 특정 사용자의 receptacle 선택으로 정의한다. preference를 표현하는 방식도 자연어, 적은 예시, explicit reward function, numerical preference vector 등으로 나뉜다. 평가 역시 task success, 사용자 설문, preference scoring 등이 섞여 있어 방법 간 비교가 어렵다.

기존 preference 관련 benchmark는 대체로 high-level navigation이나 semantic selection에 집중하고, 로봇 팔이 물체를 잡는 세밀한 manipulation preference와 다중 preference 충돌을 다루지 않는다. memory-based manipulation benchmark도 특정 task-instance를 기억하는 것과 진짜 사용자 preference를 따르는 것을 구분하지 않는다. 그 결과 어떤 policy가 preference를 학습했는지, 아니면 그냥 특정 scene을 외웠는지 알기 어렵다. LIBERO-PeRM은 이 간극을 메우기 위해 task 성공과 preference 만족을 분리한 통제된 benchmark를 제공한다.

## 핵심 아이디어

LIBERO-PeRM의 핵심은 preference를 task나 layout과 같은 1차 구성 요소(first-class building block)로 승격시키는 것이다. 기존에는 preference가 task instruction 뒤에 붙는 부가 설명 정도로 여겨졌다면, 여기서는 각 task가 mission 하나와 preference condition 하나의 조합으로 정의된다. 따라서 데이터셋을 만들 때 애초에 preference 조건의 유무를 통제할 수 있다.

이를 위해 preference를 motion, skill, user profile의 세 층위로 나눈 taxonomy를 제시한다. 이는 사람의 선호도 연구에서 빌려온 분류를 시뮬레이션에서 관찰 가능한 형태로 변형한 것이다. trajectory 수준의 제약인지, 특정 skill 수준의 제약인지, subtask 선택 수준의 제약인지에 따라 실패 양상이 다르기 때문에 taxonomy가 진단 도구가 된다.

가장 중요한 설계는 “같은 layout, 같은 task 언어, preference 유무만 다른 paired demonstration”을 생성한다는 점이다. User Profile처럼 물체를 추가해야 하는 경우에도 task 언어를 추상화하여 양쪽 조건을 모두 덮게 만든다. 이렇게 해야 policy가 preference 문구 때문에 행동을 바꿨는지, scene이 달라져서 행동을 바꿨는지가 분리된다. 만약 no-preference scene과 preference scene이 다르다면 공정한 zero-shot 비교가 불가능하다.

두 가지 평가 지표 SR와 SA를 나눈 것도 아이디어다. SR은 원래 LIBERO의 task 성공, SA는 preference 만족을 task 성공과 곱해 계산한다. 이 분리는 정책의 실패 모드를 “task는 되는데 방식이 틀림”, “task 자체가 안 됨”, “둘 다 실패”로 나누어 보여준다. 실제 실험에서 이 세 가지 모드가 모두 나타난다.

마지막으로 다섯 개 task suite는 personalization의 핵심 능력을 하나씩 격리한다. single preference 학습, data scaling, 일반화, 충돌, 조합, 함축적 언어 이해까지 나누어 같은 모델이라도 어떤 능력이 부족한지 알 수 있게 한다.

## 방법

**Preference 정의와 입력 형식.**  
정책 입력은 $\ell_{\text{task}}\|\ell_{\text{pref}}$ 형태의 프롬프트다. $\ell_{\text{task}}$는 task 언어, $\ell_{\text{pref}}$는 preference 언어이고, 실제 프롬프트는 “Task: ... Preference: ...”처럼 붙인다. timestep $t$에서 정책은 agent view 이미지 $I_t^{agent}$, eye-in-hand 이미지 $I_t^{hand}$, 그리고 이 텍스트를 조건으로 action $a_t$를 출력한다. preference 타입은 세 가지다. Motion Preference는 trajectory의 물리적 성질을 제한한다. 예를 들어 “특정 구역을 피하라”는 end-effector와 물체가 그 구역에서 떨어져 있도록 거리 제약을 만든다. Skill Preference는 특정 skill의 실행 방법을 바꾸는데, “손잡이를 바깥으로 두라”는 placement skill에서 mug를 회전시키는 pose constraint를 추가한다. User Profile은 사용자 배경 지식으로 subtask 의미 선택을 바꾸는데, “테이블 표면을 보호하려는 사용자”라면 컵받침을 지지대로 고른다. 논문 표기는 각각 $P_{\mathrm{motion}}$, $P_{\mathrm{skill}}$, $P_{\mathrm{profile}}$이다. 총 37개 single-preference instance와 18개 two-preference combination을 제공한다.

**데이터 생성 pipeline.**  
pipeline은 세 단계다. 첫째, 사용자가 preference instance와 초기 LIBERO layout을 고르면 VLM이 layout을 최소한으로 수정한다. Motion/Skill Preference에서는 layout과 task 언어를 바꾸지 않고, “피해야 할 물체” 같은 target만 고른다. User Profile에서는 예컨대 빨간 물체 preference라면 같은 category의 빨간 물체를 추가하는 최소 편집을 한다. 이때 task 언어는 두 조건을 모두 덮도록 추상화한다. 둘째, VLM이 preference 없이 수행할 subtask plan과 preference 조건을 넣은 subtask plan을 만든다. 이후 미리 녹화된 heuristic skill library가 trajectory를 생성한다. 각 skill은 사람 시연 하나를 수집한 뒤 핵심 waypoint를 추출하고 OMPL planner로 초기 자세를 무작위로 바꿔가며 많은 성공 경로를 만든다. OMPL은 충돌 없는 로봇 팔 경로를 sampling으로 찾아주는 motion planner이다. 생성 경로는 smoothing되고 필요한 경우 offset이 조정되는데, 실험에서 72% 이상 skill은 어떤 task에서도 offset 조정이 필요 없었다. 셋째, preference satisfaction metric을 만든다. Motion Preference는 trajectory quantity에서 직접 계산한다. Skill Preference는 key waypoint와 VLM image check로 skill 실행을 검증한다. User Profile은 조작된 물체를 포함한 subtask plan을 감시한다. 연속 satisfaction score는 trajectory statistics와 human review를 거쳐 0, 1/4, 3/4, 1의 4단계 label로 mapping된다.

**Task suite.**  
LIBERO-SinglePref는 100개 task로 단일 preference 학습과 실행을 평가한다. LIBERO-PrefScale는 100개 task로 demonstration, task, layout 수가 늘어날 때 scaling을 평가한다. LIBERO-PrefConflict는 48개 task로 preference끼리 충돌하거나 preference와 task goal이 충돌하는 상황을 다룬다. LIBERO-PrefCompose는 64개 task로 no preference, $P_A$, $P_B$, $P_A+P_B$ 네 조건을 비교한다. LIBERO-ComprePref는 기존 task의 프롬프트를 다시 써서 “Preference: speed up” 같은 명시적 필드를 없애고 “손님이 곧 쓸 거예요” 같은 contextual cue로 바꾼다. 예를 들어 “Pick the mug by its handle”은 “전자레인지에서 막 나와서 본체가 너무 뜨거워요”라는 문장으로 preference를 함축한다.

**평가 지표와 실험 설정.**  
SR은 에피소드가 task goal에 성공한 비율이다. SA는 각 에피소드의 task 성공 지시자 $\mathbb{I}[G(\tau_n)]$와 discrete satisfaction label $d_n$을 곱한 평균이다. 따라서 $d_n$이 1이라도 task에 실패하면 SA에 기여하지 못한다. preference-preference conflict에서는 두 preference 중 더 높은 satisfaction score를 사용하고, task-preference conflict에서는 원래 task 완수를 우선한다. 이 규칙은 충돌이 있을 때 정책이 충돌을 감지하거나 사용자에게 질문하는 능력을 평가하지는 않는다는 점을 명시한다. zero-shot 실험에는 OpenVLA-OFT, pi0-fast, pi0.5, GR00T-N1.6, SmolVLA, UniVLA를 쓴다. fine-tuning 실험은 zero-shot 최강인 pi0.5를 base로 LoRA SFT를 적용한다. 학습 전략으로 preference 데이터만 쓰는 pi0.5-LoRA, LIBERO 원본 데이터와 mixture로 학습하는 pi0.5-Mix-LoRA, 먼저 LIBERO를 학습한 뒤 LIBERO-SinglePref를 학습하는 pi0.5-Seq-LoRA를 비교한다. 평가는 고정 checkpoint에서 10회 반복해 평균과 표준편차를 보고한다.

## 왜 성립하는가

이 논문은 theorem을 증명하는 논문이 아니라, 통제된 benchmark를 만들고 실험적 근거로 주장을 뒷받침하는 논문이다. 첫째, paired demonstration과 높은 no-preference SR이 벤치마크 설계의 타당성을 뒷받침한다. 예를 들어 pi0.5는 no-preference SR이 97.6%인데 Motion Preference SR도 97.50%로 거의 같다. 이는 pipeline의 layout 편집이 기존 LIBERO task 분포를 크게 망가뜨리지 않았다는 의미다. 따라서 낮은 SA는 layout 편집 artifact가 아니라 실제 preference-following 실패로 해석할 수 있다.

둘째, SA가 task 성공을 전제로 계산되기 때문에 SR와 SA를 함께 보면 서로 다른 실패 모드가 드러난다. pi0.5는 Motion과 Skill에서 SR이 각각 97.50%, 100.00%로 매우 높지만 SA는 24.38%, 25.00%에 불과하다. 이는 로봇이 일을 끝냈지만 사용자의 방식을 대부분 무시했다는 강한 증거다. 반대로 User Profile에서는 SR과 SA가 모두 19.12%로 낮다. 이는 preference가 subtask 선택 자체를 바꿔 task 수행까지 어려워졌다는 다른 실패 유형이다. 두 지표가 아니라 SR만 있었다면 User Profile 문제는 보여도 Motion/Skill 문제는 보이지 않았을 것이다.

셋째, mixed training과 sequential training의 비교는 no-preference 데이터가 catastrophic forgetting을 막는다는 관찰을 뒷받침한다. pi0.5-Seq-LoRA의 no-preference SR은 52.33%로 크게 떨어지는 반면, pi0.5-Mix-LoRA는 91.00%를 유지한다. sequential adaptation은 원래 task 행동을 잃어버리고, mixture training은 두 행동을 함께 유지할 수 있다는 뜻이다. 다만 Mix-LoRA는 Motion Preference SR이 66.88%로 preference-only LoRA의 90.00%보다 낮다. 이는 motion-level preference가 일반 LIBERO 데이터와 충돌하기 쉬움을 보여준다.

넷째, data scaling 실험에서 L1-L3 비교는 같은 demonstration 예산에서 layout 다양성을 늘리는 쪽이 이득이라는 것을 보여준다. L4가 L2보다 좋다는 관찰은 같은 layout 수에서 no-preference mission을 추가하면 preference-conditioned 행동을 task/layout cue에서 분리하는 데 도움이 된다는 해석을 뒷받침한다. 마지막으로 15명을 대상으로 한 초기 human validation에서 demonstration의 human-likeness가 10점 만점에 평균 9.11, preference의 real-world plausibility가 8.35로 나와 생성 데이터의 질이 어느 정도 사람 평가에서도 지지된다.

## 구체적 예시

LIBERO-SinglePref zero-shot 표에서 pi0.5의 수치를 따라가 보자. pi0.5의 no-preference SR은 97.6%다. 즉 preference 없이 원래 LIBERO task를 수행하면 거의 다 성공한다. 이제 Motion Preference 조건을 넣은 평가에서 SR은 97.50%, SA는 24.38%다. SA 공식은 task에 성공한 에피소드에만 discrete satisfaction label을 곱해 평균을 낸다. 100개 에피소드로 환산하면 97.5개 에피소드가 task에 성공했다. 전체 SA 총합이 24.38이므로 성공한 에피소드들의 평균 $d_n$ 값은 24.38 / 97.5 ≈ 0.25다. 즉 pi0.5는 거의 항상 task를 끝내지만, preference 척도에서는 평균적으로 4분의 1만 지킨 셈이다.

Skill Preference는 더 극단적이다. pi0.5의 SR은 100.00%, SA는 25.00%다. 100번 모두 task에 성공했는데, 성공한 에피소드의 preference label 평균이 정확히 0.25라는 뜻이다. 이것은 “손잡이를 바깥으로 향하게 두라” 같은 skill-level 제약을 완전히 무시하고, 그냥 물체를 성공적으로 집고 놓기만 한다는 해석을 뒷받침한다. 비슷한 양상이 OpenVLA-OFT에서도 나타나는데, Motion SR은 70.00%인데 SA는 7.30%에 그친다. 모델의 기본 조작 능력은 있지만 preference-following 능력은 거의 없다.

User Profile 조건은 실패 구조가 다르다. pi0.5의 SR은 19.12%, SA도 19.12%다. 이는 성공한 에피소드에서는 평균 $d$가 약 1.0, 즉 profile 조건을 제대로 만족하지만, 애초에 task 성공 확률이 5분의 1 수준이라는 뜻이다. “테이블을 보호하는 사용자”라서 컵받침을 골라야 하는 경우, 로봇이 의미적 선택을 바꾸지 못하고 task 자체를 실패하는 것이다. 이 한 표에서도 SR과 SA를 함께 봐야 “행동을 무시함”과 “의미 선택을 못 해서 실패함”이라는 서로 다른 원인을 구분할 수 있다.

## 실험과 결과

**Q1: zero-shot personalization.**  
Table 2의 SinglePref 결과에서 OpenVLA-OFT는 no-preference SR이 91.2%인데 All-Pref SR은 40.00%, SA는 4.53%로 떨어진다. pi0.5는 no-preference SR 97.6%, All-Pref SR 66.67%, SA 37.92%다. All-Pref SA가 가장 높은 모델도 37.92%에 불과하므로, 기존 VLA는 preference-specific training 없이 preference를 따르지 못한다. 특히 pi0.5는 Motion SR 97.50%, SA 24.38%, Skill SR 100.00%, SA 25.00%로 높은 task 성공 뒤에 낮은 preference 만족이 숨어 있다. User Profile에서는 pi0.5 SR과 SA가 모두 19.12%로 급락한다. SmolVLA와 UniVLA는 User Profile에서 거의 0%에 가깝다. 이는 User Profile이 물체 선택이나 subtask plan을 바꾸기 때문에 zero-shot으로 가장 어렵다는 뜻이다.

**Q2: SFT 학습 능력.**  
pi0.5-LoRA는 All-Pref SR 84.96±1.06%, SA 82.48±1.02%를 기록한다. zero-shot의 All-Pref SA 37.92%와 비교하면 preference 학습이 상당히 가능해졌다. 학습 전략을 비교하면 pi0.5-Seq-LoRA는 no-preference SR이 52.33±0.37%로 급락하고 All-Pref SR도 74.75±1.97%로 낮아진다. 반면 pi0.5-Mix-LoRA는 no-preference SR 91.00±0.70%, All-Pref SR 84.55±1.94%, SA 84.45±2.04%를 유지한다. contextual prompt를 평가하는 LIBERO-ComprePref에서도 Mix-LoRA는 SR 72.83±0.95%, SA 70.07±0.91%로 preference-only LoRA의 44.00%, 42.64%보다 훨씬 높다. 그러나 Mix-LoRA의 Motion Preference SR은 66.88±3.56%로 preference-only LoRA의 90.00±2.85%보다 크게 낮다. 즉 mixed training은 no-preference 유지와 contextual robustness에는 유리하지만 motion-level preference 학습을 약화시키는 trade-off가 있다.

**Q3: 데이터 크기와 효율.**  
Figure 4의 in-domain 곡선에서 SR과 SA가 전 scale 구간에서 높게 정렬된다. 성공한 실행은 대체로 preference도 만족한다는 뜻이다. 2.25K 규모의 통제 비교에서는 L1, L2, L3가 같은 demonstration 예산을 쓰지만 layout 수를 각각 2, 3, 5개로 늘린다. L1에서 L3로 갈수록 성능이 좋아지는데, 이는 몇 개 layout에서 demonstration을 많이 모으는 것보다 더 다양한 layout에서 적게 모으는 것이 효과적임을 보여준다. L4는 L2와 같은 layout 수를 쓰면서 matched no-preference mission을 추가하는데, L2보다 성능이 더 좋다. 이는 no-preference 데이터가 task/layout-specific cue에서 preference-conditioned 행동을 분리하는 데 도움을 준다는 관찰이다.

**Q4: 일반화.**  
pi0.5-LoRA*의 unseen-layout 평가에서 All-Pref SR은 37.49±3.27%, SA는 28.36±2.55%로 in-domain의 84.96%, 82.48%에서 크게 떨어진다. Motion은 unseen layout에서 SR 55.00%로 그나마 높지만 SA는 43.43%다. Skill과 User Profile은 각각 SR 28.57%, 34.00%로 더 낮다. 그림에서 unseen-layout 곡선은 data scale이 커질수록 완만히 개선되지만, unseen-layout에 다른 task까지 바꾼 green 곡선은 여전히 제한적이다. preference-conditioned 행동을 배우는 것과 새로운 task-layout 조합에서 그 행동을 성공적으로 수행하는 것은 별개의 어려운 문제라는 뜻이다.

**Q5: 조합과 충돌.**  
조합 실험에서 $P_A$와 $P_B$를 따로 학습한 뒤 $P_A+P_B$를 평가하면 in-domain SR/SA는 58.3%인데 eval SR/SA는 25.0%다. 두 preference의 단순 합성을 어느 정도 배울 수는 있지만 일반화는 약하다. decomposition 실험에서는 $P_A+P_B$와 $P_A$를 보고 $P_B$를 추론하라는 조건에서 eval SR은 37.5%, eval SA는 0.0%다. task는 성공해도 원하는 preference 실행은 전혀 되지 않는다. 충돌 실험에서 preference-preference conflict는 conflict SR 66.00%, SA 47.75%로 in-domain의 73.00%, 63.40%보다 떨어지고, Pref Dom.은 11.25%에 불과해 한 preference가 다른 preference를 일관되게 지배하지 않는다. task-preference conflict에서는 Follow Task 33.3%, Follow Preference 29.2%, Incomplete 37.5%로, 충돌 상황에서 명확한 해결보다는 실행 실패로 빠지는 경우가 많다.

## 한계

LIBERO-PeRM은 미리 정의된, 언어로 표현 가능하고, 자동 측정 가능한 preference만 다룬다. 따라서 implicit preference inference, interaction history, 비언어적 신호, open-ended 또는 시간에 따라 변하는 preference는 포함하지 않는다. 시뮬레이션과 생성 pipeline에서 나온 demonstration은 randomized initial state, mission 다양화, human review에도 불구하고 pipeline과 skill library에 특화된 편향이 남아 있을 수 있다.

현재 composition suite는 두 preference 조합만 다루고, 세 개 이상의 preference 조합은 없다. conflict suite도 충돌 감지, preference weighting, 사용자에게 언제 되물어야 하는지 같은 의사결정을 평가하지 않는다. 실험 표의 오차 막대는 고정된 checkpoint에서 평가를 10회 반복한 randomness만 반영하므로 training-seed variation은 측정하지 않는다. human validation도 15명의 초기 설문일 뿐이고 real-robot 실험이나 장기간 사용자 연구는 포함되지 않았다. 따라서 실제 가정 환경에서의 타당성은 후속 연구로 남아 있다.

## 왜 중요한가

LIBERO-PeRM은 개인화 로봇 조작을 “task 성공”과 “preference 만족”으로 분리해 측정할 수 있게 만든 첫 controlled benchmark라는 점에서 의미가 크다. 기존 연구는 개인화를 제각각 정의하고 성공률만 보고해, 좋은 모델이 실제로는 사용자의 행동 방식을 무시하는 경우를 놓치기 쉬웠다. 이 benchmark는 같은 task에서도 motion, skill, user profile 층위의 서로 다른 실패 모드를 드러내므로, 연구자와 실무자가 모델의 어느 부분이 부족한지 구체적으로 진단할 수 있다.

또한 40.8K trajectory와 preference satisfaction score, subtask metadata, subgoal image annotation을 함께 공개해 preference-conditioned imitation learning, reward modeling, hierarchical VLA 학습에 바로 쓸 수 있는 기반을 제공한다. 후속 연구는 이 데이터를 활용해 preference를 단순 암기가 아니라 정말 일반화해 배우는 방법, 여러 preference를 합성하는 방법, 충돌 시 사용자에게 질문하는 정책을 개발할 수 있다. 실무적으로는 가정용 로봇을 평가할 때 SR만 보면 안 되고 SA를 함께 봐야 한다는 평가 관행을 제시한다. 마지막으로, contextual prompt suite는 “Preference: ...” 같은 인위적 필드에 의존하지 않고 자연스러운 사용자 발화에서 preference를 추론하는 방향을 실험할 수 있게 해 준다.

## 원문 초록

> Personalization is essential for general-purpose robots to transition into household environments and achieve true practicality. While general robotic manipulation has been extensively studied, personalized robotic manipulation (PeRM) lacks a controlled benchmark for separating task completion from preference satisfaction. We introduce LIBERO-PeRM, a benchmark for preference learning in embodied agents. LIBERO-PeRM studies five questions: 1) how policies follow preferences in zero-shot settings; 2) how they learn single preferences from demonstrations; 3) how efficiently they acquire preferences as demonstrations increase; 4) how learned preferences generalize across layouts and tasks; and 5) how policies compose preferences and behave under conflicts. We propose a controlled formulation and taxonomy of observable preferences in simulation, covering motion, skill, and user-profile choices. This formulation is restricted to language-expressible preferences that can be instantiated in LIBERO without changing the task goal, evaluated automatically, and reused across tasks. Building on LIBERO, our procedural pipeline generates paired demonstrations with and without preferences. We create five task suites (312 tasks) with high-quality demonstrations, rich metadata, and preference-satisfaction metrics. Experiments show that current VLA policies struggle with zero-shot personalization, while SFT makes preferences learnable. Mixed training achieves better no-preference retention than sequential adaptation and improves performance with contextual prompts compared with preference-only training, but can weaken motion-preference learning; preference generalization, decomposition, and conflict handling remain difficult. The code, datasets, and demos can be found on the project website: https://libero-perm.github.io/.
