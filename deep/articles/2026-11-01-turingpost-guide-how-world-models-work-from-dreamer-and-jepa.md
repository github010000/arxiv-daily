## 한 줄 요약

world model 은 "다음에 무엇이 보일지"를 생성하는 모델, 압축된 latent 상태로 미래를 예측하는 모델, 물체와 공간의 구조를 명시적으로 담는 모델로 갈리며, 이 세 갈래가 각각 visual simulation, 빠른 planning, 물리적 정합성이라는 서로 다른 쓸모를 결정한다.

## 배경과 핵심 개념

**world model 은 "행동하면 세계가 어떻게 변하는가"를 배우는 모델이다**

world model 은 agent 가 붙어 있는 환경의 변화 규칙을 내부에 학습해 두는 모델이다. 원문은 이것을 "세계가 어떻게 변하는지, 그리고 agent 가 어떤 행동을 했을 때 무엇이 일어날 수 있는지"를 포착하는 것으로 설명한다. 예를 들어 로봇이 컵을 밀기 전에, 밀면 컵이 미끄러질지 아니면 넘어질지를 미리 예측할 수 있다면 실제로 시도하지 않고도 행동을 고를 수 있다. (배경) 강화학습에서 model-based 방법이 model-free 방법보다 sample 을 적게 쓰는 이유가 여기에 있다. 실제 환경에서 부딪히는 대신 학습된 모델 안에서 여러 번 상상해 보고 좋은 행동을 고르는 것이다. 그래서 world model 은 이미지 한 장을 그럴듯하게 만드는 모델과 다르다. 상태와 상태 사이의 전이, 즉 dynamics 를 다루는 모델이다.

**state, observation, action 의 되먹임 루프**

원문이 제시하는 기본 구조는 다섯 단계다. 세계에는 특정 순간의 모든 것을 뜻하는 state 가 있고, agent 는 그 state 의 일부만 보여 주는 observation(카메라 이미지, 센서 값)을 받는다. world model 은 이 부분 관측으로 현재 state 를 추정하고 다음에 어떻게 변할지 예측하며, 그 예측을 근거로 agent 가 action 을 고르고, action 이 물리 법칙에 따라 세계를 바꿔 새로운 state 와 새로운 observation 을 만든다. 비유하면 안개 속에서 운전할 때다. 눈에 보이는 것은 앞차의 흐릿한 뒷모습뿐이지만, 머릿속 모델이 "저 차가 곧 차선을 바꿀 것 같다"를 추정해 속도를 줄인다. 여기서 핵심은 world model 이 완전한 state 를 보지 못한다는 점이다. 부분 관측에서 전체를 추정하는 능력이 모델의 일부다.

**latent 상태: 픽셀을 버리고 의미만 남기는 압축**

world model 은 보통 이미지를 픽셀 그대로 다루지 않는다. 중요한 정보를 숫자 벡터, 즉 latent 표현으로 압축한다. 원문은 이 압축의 목표를 "물체, 움직임, 인과관계, 물리적 제약은 유지하면서 조명, 질감, 배경 노이즈는 버리는 것"으로 설명한다. 압축이 잘 되면 한 번의 상상 rollout 비용이 싸지고, 압축이 지나쳐 중요한 물체를 잃으면 모델은 그 물체를 영원히 예측하지 못한다. (배경) 이 표현은 사람이 읽기 쉬운 형태가 아니라서, 모델이 왜 그런 예측을 했는지 눈으로 확인하기 어렵다는 검증상의 부담이 따라온다.

**render, simulate, plan 이라는 세 가지 기능**

원문은 Fei-Fei Li 의 분류를 빌려 world model 의 기능을 셋으로 나눈다. render 는 세계가 어떻게 보이는지를 생성하는 것으로 비디오 모델이 여기 속하며, 결과물이 사실적으로 보여도 구조나 물리적으로는 틀릴 수 있다. simulate 는 세계가 실제로 어떻게 구성되고 움직이는지를 표현하는 것으로 기하, 물리, 운동을 포함하고, 로봇 학습이나 자율주행 테스트, 건물 설계에 쓰인다. plan 은 모델이 본 상황과 주어진 목표를 바탕으로 어떤 행동을 할지 결정하는 것이다. 원문의 주장에 따르면 simulation 이 나머지 둘을 잇는다. 물체의 모양과 물성, 힘에 대한 반응을 이해하는 모델이라면 그 물체를 다른 각도에서 보여 주고, 밀었을 때를 예측하고, 로봇의 상호작용을 계획할 수 있어야 한다는 논리다.

**재구성과 표현 예측: 무엇을 맞히도록 학습하는가**

latent 모델 안에서도 두 갈래가 갈린다. 재구성 계열은 압축 상태에서 원래 observation 을 복원할 수 있어야 한다고 본다. decoder 가 "이 상태에 정보가 충분한가"를 확인해 주는 감시 장치 역할을 한다. 반대로 JEPA 같은 표현 예측 계열은 픽셀을 복원하지 않고, 숨겨진 부분의 추상적 표현만 맞히도록 학습한다. 비유하면 사진의 일부를 가리고 "가려진 곳에 고양이가 있다"를 맞히는 것과 "가려진 픽셀 값을 전부 그려 내는 것"의 차이다. 전자는 질감이나 그림자 같은 예측 불가능하고 중요하지 않은 디테일에 시간을 쓰지 않는다. 대신 결과를 사람이 눈으로 검사할 디코딩된 미래 프레임이 없다는 것이 대가다.

**분류축: 시간을 넘길 때 무엇을 들고 가는가**

원문은 통용되는 분류가 없다고 인정하면서, 자체적인 축을 하나 제안한다. 다음 observation 을 생성해 넘기는가, 압축된 latent 상태를 넘기는가, 아니면 물체와 공간의 명시적 구조를 넘기는가. 이 축이 유용한 이유는 쓸모가 거의 이 선택으로 결정되기 때문이다. 보이는 미래가 필요하면 생성 모델, 계산을 아끼며 planning 해야 하면 latent 모델, 기하학적 정합성이 중요하면 structured 모델이다. 다만 원문도 이 경계가 깔끔하지 않다고 말한다. 실제 모델들은 여러 갈래를 섞는다.

## 글의 내용

글은 왜 지금 world model 인가에서 출발한다. 텍스트, 코드, 이미지, 오디오, 비디오로 AI가 실무에 들어오고 있지만 공장이나 자율주행차 같은 물리 세계에서는 고성능 추론 모델이나 개인 agent 로 충분하지 않다. 약점은 물리 세계에서 다음에 무엇이 일어날지 안정적으로 예측하는 능력이다. 그리고 저자는 이 분야에 보편적으로 합의된 정의가 없다는 점을 먼저 밝힌다. simulator, 비디오 생성기, JEPA 같은 표현 모델이 모두 world model 이라는 이름 아래 들어오고, 최근 열린 workshop 에서는 참가자마다 정의가 달랐다고 한다.

이어서 모든 world model 에 공통인 패턴을 정리한다. 세계는 한 상태에 오래 머물지 않고 시간에 따라 변하는 상태의 연쇄이며, world model 은 그 전이 뒤의 규칙을 배운다. 그 규칙의 출처는 물리, 화학, 생물, 인간 행동, 코드일 수도 있고 여러 개가 동시에일 수도 있다. 앞서 정리한 다섯 단계 루프가 이 절의 뼈대이고, 여기에 세 가지 속성이 더해진다. 서로 다른 종류의 정보를 결합하는 omnimodal, 서로 다른 속도와 시점에 도착하는 신호를 처리하는 asynchronous, agent 의 제한된 시야에서 동작하는 local 이다. 현재는 render, simulate, plan 을 각각 다른 모델이 맡고 있으며 render 는 이미 널리 쓰이지만 simulate 와 plan 은 훨씬 덜 성숙하다. 장기 목표는 셋을 한 모델로 합치는 것이다.

그다음이 분류표다. 원문은 일곱 개의 architecture 를 제시한다. visual token, diffusion/flow, reconstructive state-space, predictive representation, task-oriented, spatial/geometry-aware, object-centric 이고, 이것을 다시 observation-generating, latent dynamics, structured worlds 세 family 로 묶는다. 표의 각 행은 "핵심 메커니즘"과 "예시 모델"을 함께 적는데, 예를 들어 visual token 은 미래의 시각 token 을 autoregressive 하게 예측하고 IRIS 와 Dreamer 4 가 예시이며, reconstructive state-space 는 압축 상태를 예측하고 observation 을 복원하며 PlaNet 과 Dreamer V1 부터 V3 까지가 해당한다.

observation-generating 계열의 기본 동작은 "과거 observation 더하기 조건 → 미래 observation"이다. 조건에는 행동, 카메라 경로, 언어 지시 등이 들어간다. visual token 방식은 tokenizer 가 이미지를 시각 코드 묶음으로 압축하고, sequence 모델이 상호작용 이력에서 미래 코드를 예측하고, decoder 가 다시 이미지로 되돌린다. IRIS 는 Atari 에서, Dreamer 4 는 Minecraft 에서 게임 규칙을 자기 world model 안에서 배우는 강화학습 agent 다. Dreamer 4 는 causal video tokenizer 와 상호작용 가능한 dynamics Transformer 를 결합했고, 마우스를 움직이거나 키를 누르면 Transformer 가 다음에 무엇이 바뀔지 예측한다. 이 계열의 결정적 약점은 tokenizer 다. 압축 과정에서 작지만 중요한 물체와 그 dynamics 가 사라지면 모델은 그것을 예측할 정보를 끝내 받지 못한다.

diffusion 과 flow 계열은 관측을 여러 번의 정련으로 생성한다. diffusion 은 노이즈를 더하는 과정을 거꾸로 학습하고, flow 기반 방법은 노이즈 분포에서 데이터 분포로 가는 변환을 학습한다. 예측 시점에 모델은 맥락을 받아 가능한 미래를 생성으로 유도하며, 같은 출발점이라도 노이즈 샘플이 다르면 다른 결과가 나온다. Genie 3 는 이전에 생성한 프레임들과 사용자의 최신 행동으로 다음 프레임을 예측해 상호작용 가능한 세계를 만든다. 각 예측이 다음 예측의 이력에 들어가는 action-conditioned autoregressive generation 이고, 이 이력 덕분에 물체가 시야를 벗어났다 돌아와도 위치와 정체성이 유지되며 미리 정의된 3D 장면이 필요 없다. Waymo World Model 은 이 Genie 3 를 자율주행 시뮬레이션에 맞춰 적용한 것으로, 행동과 장면 배치, 언어 지시를 조건으로 카메라와 lidar 관측을 생성한다. 엔지니어는 날씨를 바꾸고, 이상한 장애물을 넣고, 대안 경로를 시험해 실제 도로에서 거의 마주치지 않는 상황에 Waymo Driver 가 어떻게 반응하는지 평가할 수 있다. NVIDIA 의 Cosmos-Predict2.5 는 causal VAE 로 비디오를 압축 token 으로 만들고, Diffusion Transformer 가 flow matching 으로 노이즈 섞인 token 을 깨끗한 미래 시퀀스로 바꾼다. Cosmos-Reason1 이 지시를 인코딩해 cross-attention 으로 생성을 유도하고, 제공된 이미지나 비디오 프레임이 시퀀스의 시작을 고정한다. 이 계열의 한계는 생성된 미래가 사실적으로 보이면서도 물리적으로는 틀릴 수 있다는 것, 특히 시퀀스가 길어질수록 오차가 누적되고 물체 배치가 어긋난다는 것이다.

latent dynamics 계열은 렌더링을 건너뛴다. encoder 가 관측을 수치 특징으로 바꾸고, transition 모델이 현재 표현과 제안된 행동을 받아 다음 표현을 예측하며, 그 예측을 다시 넣어 상상 상태의 시퀀스를 만든다. 이 계열 안에서 세 가지 학습 신호가 갈린다. reconstructive 방식은 RSSM 을 쓰는데, 상태가 순환 메모리와 확률 분포로 표현되는 확률적 latent 두 부분으로 나뉜다. 새 이미지가 들어오면 메모리와 결합해 상태 추정을 갱신하고, 미래를 상상할 때는 새 이미지 없이 기존 상태와 행동으로 다음 상태를 예측한다. 학습은 두 경로를 KL divergence 로 묶어, 관측을 반영한 상태가 예측 경로에 "무엇을 예상했어야 하는지"를 가르치게 한다. 여기에 reward 와 episode 지속 여부 예측을 붙이고, 상상 rollout 안에서 actor 가 행동을 제안하고 critic 이 미래 수익을 추정하면, 모든 예측 상태를 이미지로 디코딩하지 않고도 어떤 행동이 통하는지 배울 수 있다. JEPA 는 프레임 일부를 가린 뒤 context encoder, target encoder, predictor 로 표현 공간에서 예측을 맞춘다. task-oriented 계열은 내부 상태를 행동 평가에 맞춰 형성한다. MuZero 는 표현 함수, dynamics 함수, 예측 함수를 연결하고 tree search 로 대안 행동 시퀀스를 탐색하며, 상상 속 상태는 환경과 닮을 필요 없이 reward, value, policy 예측을 지탱하기만 하면 된다. Newt 는 여기에 언어 조건, 시연 기반 사전학습, 다중 과제 강화학습을 더한 변형이다.

마지막으로 structured 계열은 공간이나 개별 물체를 표현의 명시적 구성 요소로 만든다. 공간 쪽의 표현 수단은 depth map, occupancy grid, point cloud, mesh, Gaussian splat 등이다. World Labs 의 Atlas 는 이미지에 카메라 정보를 붙여 그 이미지가 공간 어디에서 어느 방향으로 찍혔는지를 모델에 알려 주고, 이렇게 모인 관측이 공유 공간 맥락을 이룬다. 방의 마주 보는 두 모서리에서 찍은 사진을 주면 카메라 pose 로 두 시점을 연결해 그 사이에 놓인 카메라가 무엇을 볼지 생성한다. transformer 가 텍스트, 이미지, 카메라 pose, depth map 을 처리하고, autoregression 이 출력의 순서를 정하며, rectified flow 가 압축 latent 공간에서 노이즈를 시각 표현으로 바꾼 뒤 디코딩한다. 두 과정이 동시에 작동하는데, autoregression 은 시퀀스가 어떻게 전개될지를, flow 는 각 출력의 내용을 결정한다. 생성된 뷰와 depth 추정으로 point cloud 를 복원하고 이를 Gaussian splat 으로 바꿔 탐색 가능한 장면을 렌더링한다. 입력이 희박하면 보이지 않는 영역을 추론하고, 관측이 추가되면 그 추측이 제약된다. object-centric 계열은 장면을 개별 entity 표현으로 쪼개고, 학습된 벡터인 slot 에 물체를 담아 dynamics 모델이 slot 을 시간에 따라 갱신하며 상호작용을 모델링한다. SlotFormer 는 비디오에서 뽑은 물체 표현으로 미래 전개를 Transformer 로 예측하고, attention 이 물체 간 상호작용과 각 물체 내부의 변화를 함께 표현한다. OC-STORM 은 segmentation network 의 물체 표현과 학습된 world model 을 결합하고 소량의 라벨 프레임으로 의사결정에 중요한 물체를 식별한다.

결론에서 글은 세 family 의 쓸모를 다시 정리하고 선택 지침을 준다. 보이는 미래가 필요하면 observation-generating, 효율적 예측과 planning 이면 latent dynamics, 기하와 3D 일관성이 핵심이면 spatial, 개별 entity 간 상호작용이 중요하면 object-centric, 오직 어떤 행동이 최선의 결과로 이어지는지만 중요하면 task-oriented latent 모델이다. 그러면서 오늘날 어느 모델도 한 상자에 깔끔히 들어가지 않는다고 덧붙인다. Atlas 처럼 생성과 명시적 공간 구조를 결합한 사례가 그렇고, 앞으로의 방향은 상상할 만큼의 render, 효율적으로 계획할 만큼의 latent dynamics, 물리 세계에 붙어 있게 해 줄 만큼의 구조를 섞는 것이다.

## 근거와 수치

원문에 나오는 수치는 많지 않고, 대부분 구조를 세는 숫자이거나 특정 모델의 학습 효율을 주장하는 숫자다.

- "three main functions"라는 표현으로 render, simulate, plan 을 제시한다. 기능 분류가 셋이라는 것 자체는 수치라기보다 분석 틀이다.
- 분류표는 일곱 개 architecture 행을 담고, 세 family 로 묶인다. 이는 문헌 전체를 포괄하는 계수가 아니라 저자가 제안한 정리다.
- Dreamer 4 는 "shortcut forcing objective" 덕분에 다음 상태를 만드는 데 "just four refinement steps"만 쓴다.扩散 샘플링이 보통 수십 단계를 반복한다는 점을 감안하면 (배경) 이는 매우 작은 값이고, 실시간 상호작용 게임 환경에서 모델을 돌리기 위한 핵심 주장으로 읽힌다.
- Dreamer 4 는 Minecraft 에서 다이아몬드를 얻는 데 필요한 "20,000-plus-action sequence"를 학습 중 실제 게임으로 돌아가지 않고 완수한다고 한다. 2만 번이 넘는 행동을 상상만으로 이어 붙인다는 것은 오차 누적에 대한 자신감을 뜻하며, 이 논문의 가장 강한 주장이다.
- Waymo World Model 은 "February 2026"에 소개되었다고 명시된다. 자율주행 시뮬레이션에 생성 모델을 붙인 시점이 최근이라는 뜻이다.
- Atlas 는 "September 2026"에 World Labs 가 소개했고, 회사는 Fei-Fei Li 가 공동 창업했다고 밝힌다. 글의 게시일과 거의 같은 시점이라, 이 모델에 대한 독립적 검증은 아직 없다고 봐야 한다.
- Newt 는 "ICLR 2026"에서 발표되었고, OC-STORM 은 "February 2026"에 개정 논문이 나왔다고 한다.
- 사이트 하단에는 "115,000+" 구독자라는 문구가 있으나, 이것은 뉴스레터 자체의 홍보 수치이고 world model 성능과는 무관하다.

반대로 이 글에는 모델 간 정량 비교가 전혀 없다. 정확도, 생성 품질 지표, 학습 비용, 추론 지연, 폐루프 주행 성능 같은 숫자가 없고, "4 steps"나 "20,000 actions"도 각 논문의 주장을 인용한 것이지 독립 재현 결과가 아니다. 어떤 아키텍처가 얼마나 더 효율적인지에 대한 수치도 제시되지 않는다. 원문에 명시 없음.

## 따져볼 점

가장 먼저 봐야 할 것은 이 글이 스스로 인정한 한계다. world model 에 보편적으로 합의된 정의가 없고, workshop 참가자마다 정의가 달랐으며, 기존 분류들은 범주가 크게 겹친다. 저자가 제시한 세 갈래 축도 "we propose"라는 표현에서 드러나듯 정설이 아니라 제안이다. 따라서 이 표를 업계 표준으로 인용하면 안 되고, 특정 글쓴이의 정리로 다뤄야 한다.

두 번째는 발표 주체의 위치다. 이 글은 Fei-Fei Li 의 기능 분류를 뼈대로 삼고, 그가 공동 창업한 World Labs 의 Atlas 를 상당한 분량으로 상세히 다루며 이미지까지 싣는다. 물론 Li 의 분류는 업계에서 널리 인용되지만, 한 회사의 제품이 결론부의 "가장 흥미로운 모델" 사례로 반복 등장하는 구성은 소개 글의 균형에 영향을 줄 수 있다. Atlas 에 대한 평가는 원문에 인용된 회사 설명 이상의 근거가 제시되지 않는다.

세 번째는 검증 공백이다. Waymo World Model 이 Genie 3 를 "adapts" 했다고만 쓰고, 어떻게 적응시켰는지, 시뮬레이션 충실도가 어느 정도인지, 그 결과가 실제 주행 안전에 어떤 기여를 했는지는 원문에 없다. Dreamer 4 의 2만 행동 주장도 단일 논문에 근거한다. ICLR 2026 발표나 2026년 2월 개정 논문 같은 시점 정보 역시 이 글之外의 확인이 필요하다.

네 번째는 개념적 긴장이다. 원문은 video model 과 world model 을 구분하려 하지만, "행동 조건이 붙고 시간에 따른 환경 변화를 모델링하면 world model 에 가까워진다"는 기준은 정도의 문제이지 경계가 아니다. 같은 이유로 render 계열의 한계로 지적된 "사실적으로 보이지만 물리적으로 틀림"은 structured 계열에도 정도 차이로 존재할 수 있는데, 이 비교는 글에서 정량화되지 않는다.

다섯 번째는 빠진 정보 목록이다. omnimodal, asynchronous, local 이라는 세 속성이 왜 중요한지 설명은 있지만, 어떤 모델이 실제로 이 속성을 만족하는지, 만족하지 못하면 어떤 실패가 생기는지는 서술되지 않는다. 또한 실제 로봇 배포에서의 지연 시간, 학습 데이터 요구량, 실패 사례 연구가 없어서 실무 판단에 쓰기에는 해상도가 낮다. 마지막으로 "task-oriented 모델은 상상 속 상태가 환경과 닮을 필요가 없다"는 서술은 MuZero 계열의 장점인 동시에, 그 상태를 사람이 해석하거나 디버깅할 수 없다는 위험이기도 한데 이 위험은 논의되지 않는다.

## 왜 중요한가

이 글이 실무자에게 주는 가장 쓸모 있는 것은 모델 목록이 아니라 질문 하나다. "내 시스템이 시간을 넘길 때 무엇을 들고 갈 것인가." 자율주행 시뮬레이터를 만든다면 렌더링된 미래가 필요하므로 관측 생성 계열이 맞고, 로봇 팔이 다음 0.1초에 어느 관절을 움직일지 빠르게 결정해야 한다면 latent dynamics 가 맞으며, 디지털 트윈이나 AR 처럼 3D 일관성이 제품 요구사항이면 공간 구조 계열이 맞다. 이 선택을 먼저 하지 않으면 벤치마크 점수는 높은데 제품 요구를 못 맞추는 모델을 고르게 된다.

두 번째로 중요한 것은 평가 방식에 대한 경고다. 관측 생성 모델의 출력은 사람 눈에는 훌륭해 보이면서 물리적으로 틀릴 수 있고, 시퀀스가 길어질수록 오차가 누적된다. 따라서 "비디오가 예뻐 보인다"를 배포 판단 근거로 쓰면 안 되고, 물체 위치나 접촉, 충돌 같은 물리 지표와 폐루프 과제 성공률로 평가해야 한다. 반대로 latent 모델은 디코딩된 미래가 없어 사람이 검사하기 어려우므로, 해석 가능성과 검증 비용을 설계 단계에서 함께 고려해야 한다.

세 번째는 데이터 전략이다. Waymo 사례가 보여 주는 것은 희귀한 상황을 실제 도로에서 모으는 대신 조건을 바꿔 생성해 시험한다는 발상이다. 이것이 안전 인증으로 이어지려면 생성된 시나리오가 물리적으로 타당하다는 보증이 필요하고, 그 보증은 structured 표현이나 물리 제약을 결합할 때 더 강해진다. 즉 render 와 structure 의 결합은 연구 트렌드가 아니라 배포 요건이다.

지켜볼 지점은 세 가지다. 하나는 render, simulate, plan 을 한 모델에 통합하려는 시도가 실제로 어디까지 왔는지, 다른 하나는 action-conditioned world model 을 공정하게 비교할 벤치마크가 등장하는지, 마지막은 tokenizer 병목과 물리 정합성 문제를 structured 표현으로 얼마나 메우는지다. 실무자라면 작은 실험부터 권한다. 자기 도메인 데이터로 latent 모델을 학습해 빠른 rollout 을 만들고, 의사결정이 필요한 순간에만 observation 을 디코딩하는 2단 구성을 시도해 보는 것이다. 비용은 latent 쪽으로 아끼고, 검증과 보고는 디코딩된 장면으로 하는 방식이다. 글 마지막이 예고한 world action model 비교 글도 이 연장선에서 함께 보면 좋다.
